### 一、 题意抽象
我们需要在长度为 $N$ 的字符串中选两个分割点 $(i, j)$（满足 $1 \le i < j < N$），把字符串分成三段：
- **第一段**：$S[1 \dots i]$
- **第二段**：$S[i+1 \dots j]$
- **第三段**：$S[j+1 \dots N]$

要求：**三段各自都必须包含 `'A'`、`'B'`、`'C'`。**
直接枚举 $(i, j)$ 是 $O(N^2)$，而 $N \le 3 \times 10^5$，必须优化到 $O(N)$ 或 $O(N \log N)$。

---

### 二、 核心突破口：单调性 + 固定一维

这道题的关键性质是：**“包含 A、B、C”具有单调性**——如果一个子串已经集齐了 A、B、C，那么把它拉长（往左或往右扩展），它依然集齐 A、B、C。

利用这个单调性，我们可以把“三段”拆开处理：

#### 1. 处理第一段：算出 $i$ 的下界 $i_{\min}$
第一段只跟 $i$ 有关。要让 $S[1 \dots i]$ 包含 A、B、C，分割点 $i$ 至少要越过三种字符**第一次出现**的最晚位置：
$$i_{\min} = \max(\text{first}_A,\ \text{first}_B,\ \text{first}_C)$$
只要满足 $i \ge i_{\min}$，第一段就一定合法。

#### 2. 处理第三段：算出 $j$ 的上界 $j_{\max}$
第三段只跟 $j$ 有关。要让 $S[j+1 \dots N]$ 包含 A、B、C，起点 $j+1$ 必须不能晚于三种字符**最后一次出现**的最早位置（即 $j+1 \le \min(\text{last}_A, \text{last}_B, \text{last}_C)$）：
$$j_{\max} = \min(\text{last}_A,\ \text{last}_B,\ \text{last}_C) - 1$$
只要满足 $j \le j_{\max}$，第三段就一定合法。

#### 3. 固定 $i$，处理第二段（固定一维，维护另一维）
现在只剩下第二段 $S[i+1 \dots j]$。
当我们**固定左分割点 $i$**（满足 $i \ge i_{\min}$）时，第二段从 $i+1$ 开始向右延伸。什么时候它刚好集齐 A、B、C 呢？
取决于 $i$ **右侧**最近的 `'A'`、`'B'`、`'C'` 的位置（记作 $\text{pos}_A, \text{pos}_B, \text{pos}_C$）中最靠右的那一个：
$$r(i) = \max(\text{pos}_A,\ \text{pos}_B,\ \text{pos}_C)$$
只要 $j \ge r(i)$，第二段就一定合法。

#### 4. 合并所有条件，直接计数
对于固定的 $i \ge i_{\min}$，合法的 $j$ 只需同时满足：
- 第二段合法：$j \ge r(i)$
- 第三段合法：$j \le j_{\max}$

（由于 $r(i) \ge i+3$ 且 $j_{\max} \le N-1$，边界 $i < j < N$ 会自动满足。）

因此，每个 $i$ 贡献的合法方案数就是区间 $[r(i), j_{\max}]$ 内的整数个数：
$$\max(0,\ j_{\max} - r(i) + 1)$$

---

### 三、 算法流程与复杂度

1. **特判**：如果 `'A'`、`'B'`、`'C'` 没有在 $S$ 中全部出现过，直接输出 `0`。
2. **求上下界**：正序找第一次出现位置算出 $i_{\min}$，倒序找最后一次出现位置算出 $j_{\max}$。
3. **倒序遍历求答案**：
   从 $i = N$ 倒序遍历到 $i_{\min}$，用三个变量 $\text{pos}_A, \text{pos}_B, \text{pos}_C$ 实时记录“在 $i$ 右侧最近一次出现 A/B/C 的下标”（初始设为 $N+1$）：
   - 先用当前的 $\text{pos}_A, \text{pos}_B, \text{pos}_C$ 算出 $r(i)$，把 $\max(0, j_{\max} - r(i) + 1)$ 累加到答案中；
   - 再用 $S[i]$ 更新对应的 $\text{pos}$，留给左边的 $i-1$ 使用。

- **时间复杂度**：$O(N)$（只需常数次线性扫描）。
- **空间复杂度**：$O(N)$（仅用于存储输入字符串）。

---

### 四、 同思路的另外两种常见写法（拓展）

在上面“算出 $i_{\min}, j_{\max}$ 并固定 $i$”的同一框架下，求 $r(i)$ 还有两种常见替代方式，比赛时想到哪个写哪个即可：

1. **前缀和 + 二分查找**（$O(N \log N)$）
   预处理 A、B、C 的数量前缀和。固定 $i$ 后，因为区间长度越大、包含的字符种类越多，可以直接二分出最小的 $j$ 使得 $S[i+1 \dots j]$ 中三种字符数量都 $\ge 1$，这个 $j$ 就是 $r(i)$。
2. **正序双指针 / 尺取法**（$O(N)$）
   随着 $i$ 从左往右移动，$r(i)$ 只会往右移（不会往左退）。用两个指针维护窗口 $[i+1, r]$ 内的字符计数：右指针 $r$ 不断向右扩直到集齐三种字符，统计 $j_{\max} - r + 1$ 后，左指针 $i$ 右移一格并把 $S[i+1]$ 移出窗口。
