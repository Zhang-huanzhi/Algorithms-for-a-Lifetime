在算法竞赛和编程中，**向上取整（Ceil）** 是一个非常高频且实用的小技巧。

最推荐的纯整数写法是：
> 当 $A \ge 0, B > 0$ 时：
> $$\lceil \frac{A}{B} \rceil = \lfloor \frac{A + B - 1}{B} \rfloor$$
> **Python 代码写作**：`(A + B - 1) // B`  
> **C++ / Java 代码写作**：`(A + B - 1) / B`

---

### 1. 为什么这个公式能实现“向上取整”？

我们可以用**除法的余数**来理解：

任何整数 $A$ 除以 $B$，余数只有两种情况：
1. **能整除**（余数为 $0$，即 $A$ 是 $B$ 的倍数）：
   - 加了 $B - 1$ 后，不足以让商再多进一位。
   - 比如 $B = 4$：
     - $A = 8 \rightarrow (8 + 3) // 4 = 11 // 4 = 2$（答案依然是 2，没有多进位）。
2. **不能整除**（余数在 $1 \sim B-1$ 之间）：
   - 只要有哪怕 $1$ 点点余数，再加上 $B - 1$，其和就会 $\ge B$，**恰好能让商多进一位（$+1$）**！
   - 比如 $B = 4$：
     - $A = 5 \rightarrow (5 + 3) // 4 = 8 // 4 = 2$（成功从 1 进位成了 2）。
     - $A = 7 \rightarrow (7 + 3) // 4 = 10 // 4 = 2$。

---

### 2. 为什么不用自带的 `math.ceil(A / B)`？

很多初学者喜欢用 `math.ceil(A / B)`，但在算法竞赛中这是个**大坑**，主要有两个原因：

1. **浮点数精度丢失（致命 WA）**：
   - 浮点数（float）在计算机里只有约 15~17 位的有效数字精度。
   - 如果 $A$ 或 $B$ 很大（比如本题中 $10^9$，或者题目要求 $10^{18}$），`A / B` 会强制转成浮点运算。
   - 极端情况下，原本整除的数可能会算出 `2.0000000000000004`，一取整变成了 `3`；或者原本是 `1.9999999999999998`，导致结果错误。
2. **运行效率慢**：
   - 转成浮点数调用函数，比底层的纯整数位移/除法运算慢得多。

### 3. 生活中的常见应用场景

只要题目涉及**“分批”、“打包”、“容量填补”**，基本都在考这个向上取整：

- **载客/装箱问题**：有 $N$ 个人，每辆大巴能坐 $C$ 人，需要几辆大巴？
  $\rightarrow$ `(N + C - 1) // C`
- **分页问题**：总共有 $Total$ 条数据，每页显示 $PageSize$ 条，共有几页？
  $\rightarrow$ `(Total + PageSize - 1) // PageSize`
- **本题的铺水问题**：空白长为 $d$，按一次管 $K$ 秒，需要按几次？
  $\rightarrow$ `(d + K - 1) // K`
