我们从零开始，用最直觉的方式梳理一遍 **C 题（Move One Card）** 的完整解题思路。

---

### 第一步：看清“抽一张牌再插回去”的本质

题目说：从 $A$ 中挑一个数抽出来，插到另一个位置。假设我们挑的位置和插入的位置分别是 $l$ 和 $r$（$l \le r$），其实只有 **3 种情况**：

1. **插回原位**：序列完全不变（$A = B$）。
2. **往左抽着插**（把右边的 $A_r$ 插到左边的 $l$ 位置）：
   例如 `[1, 2, 3, 4, 5]`，把 `4` 插到 `2` 的位置 $\rightarrow$ `[1, 4, 2, 3, 5]`。
   你看中间那段 `[2, 3, 4]` 变成了 `[4, 2, 3]`，**本质就是区间 $[l, r]$ 整体向右循环移位 1 格！**
3. **往右抽着插**（把左边的 $A_l$ 插到右边的 $r$ 位置）：
   例如 `[1, 2, 3, 4, 5]`，把 `2` 插到 `4` 的位置 $\rightarrow$ `[1, 3, 4, 2, 5]`。
   中间那段 `[2, 3, 4]` 变成了 `[3, 4, 2]`，**本质就是区间 $[l, r]$ 整体向左循环移位 1 格！**

**核心发现**：
无论你怎么移动这张牌，**永远只会影响某个连续区间 $[l, r]$（让它整体左移或右移 1 格），区间外面的数字纹丝不动！**

---

### 第二步：怎么快速锁定区间 $[l, r]$？（剥洋葱）

由于 $N \le 2 \times 10^5$，我们不可能暴力枚举所有的 $[l, r]$ 去试。怎么一下子锁定唯一需要检查的区间呢？

方法很简单：**把 $A$ 和 $B$ 上下对齐，从两头往中间“剥掉”一模一样的部分！**

1. **特判**：如果 $A$ 和 $B$ 从头到尾全都相等，直接“抽一张插回原位”，输出 `Yes`。
2. 如果不相等，设：
   * 从左往右数，**第一个不相等**的位置是 $m$（$1 \sim m-1$ 全相等）；
   * 从右往左数，**第一个不相等**的位置是 $M$（$M+1 \sim N$ 全相等）。

既然 $m$ 和 $M$ 这两个位置的数字必须被改变，那我们操作的区间 $[l, r]$ **必须把 $[m, M]$ 全包住**。

---

### 第三步：消除最大的疑惑——“剥掉相同的头和尾，不会漏解吗？”

很多人做到这里会犯嘀咕：**“万一本来需要把前面相同的‘头’一起卷进来移动，才能变成 $B$ 呢？直接把头砍掉只看 $[m, M]$，会不会把正确答案漏掉？”**

我们来用两个极端的例子实验一下，你就明白了：

* **实验 1（往左插把“头”卷进来了）**：
  假设 `A = [1, 2, 3, 1]`，`B = [1, 1, 2, 3]`。
  这里把第 4 位的 `1` 插到第 1 位（相同的 `1` **前面**），确实能得到 `B`。
  如果我们**强行砍掉公共前缀** `1`，剩下 `A' = [2, 3, 1]`，`B' = [1, 2, 3]`。
  把 `A'` 整体向右循环移 1 位 $\rightarrow$ `[1, 2, 3]`，**照样等于 `B'`！**
  *原因*：把 `1` 放到另一个 `1` 的前面，和放到它的后面，结果根本没区别！

* **实验 2（往右插把“头”卷进来了）**：
  假设 `A = [1, 1, 2, 3]`，`B = [1, 2, 3, 1]`。
  这里把第 1 位的 `1` 抽出来扔到最后，确实能得到 `B`。
  如果我们**强行砍掉公共前缀** `1`，剩下 `A' = [1, 2, 3]`，`B' = [2, 3, 1]`。
  把 `A'` 整体向左循环移 1 位 $\rightarrow$ `[2, 3, 1]`，**照样等于 `B'`！**
  *原因*：把第一个 `1` 扔到末尾，和把第二个 `1` 扔到末尾，结果一模一样！

**背后的铁律（对应官方题解那几行连锁等式）**：
之所以“头”被卷进去移动后还能保持和原来一模一样，唯一可能是**这个“头”加上移动过来的那个数，全都等于同一个值**。既然它们全是一样的数，那“从头开始移”和“跳过它们、从 $m$ 开始移”的效果是**100% 等价的**！后缀（“尾”）也完全同理。

---

### 第四步：结论落地，3 步直接出答案

既然把相同的头和尾都剥掉后**绝对不会漏解**，那么剩下的子区间 $[m, M]$ 就只剩最后一步验证了：

因为第 $m$ 位和第 $M$ 位都必须改变（$A_m \ne B_m$ 且 $A_M \ne B_M$），所以这一步操作必须同时动到 $m$ 和 $M$——也就是说，**只能把整个 $[m, M]$ 区间整体向右循环移 1 格，或者整体向左循环移 1 格**！

于是整个算法浓缩为极其清爽的 3 步：
1. **双指针去掉公共后缀**（找到最右不同位置 $M$），如果全删空了，直接 `Yes`；
2. **双指针去掉公共前缀**（找到最左不同位置 $m$）；
3. 取出子区间 `A[m..M]` 和 `B[m..M]`：
   * 如果 `A[m..M]` **向右循环移 1 位**等于 `B[m..M]` $\rightarrow$ `Yes`；
   * 如果 `A[m..M]` **向左循环移 1 位**等于 `B[m..M]` $\rightarrow$ `Yes`；
   * 否则 $\rightarrow$ `No`。

---

### 第五步：拿样例验证一下

* **样例 1**：
  `A = [1, 4, 1, 4, 2, 1]`
  `B = [1, 4, 1, 1, 4, 2]`
  1. 剥掉公共前缀 `1, 4, 1`（尾部没有相同的）。
  2. 剩下 `A' = [4, 2, 1]`，`B' = [1, 4, 2]`。
  3. 把 `A'` 向右循环移 1 格（把末尾 `1` 放到最前）$\rightarrow$ `[1, 4, 2]`，正好等于 `B'`！输出 **`Yes`**。

* **样例 2**：
  `A = [1, 1]`，`B = [1, 2]`
  1. 剥掉公共前缀 `1`。
  2. 剩下 `A' = [1]`，`B' = [2]`。
  3. `[1]` 不管左移还是右移都还是 `[1]`，不等于 `[2]`！输出 **`No`**。

* **复杂度**：整个过程双指针从头尾各扫一次，再比对一次切片，总时间复杂度 **$O(N)$**，轻松通过 $N \le 2 \times 10^5$ 的数据范围。
