### 标准固定套路（四步走）：

要算 $\frac{A}{B} \pmod{MOD}$：

1. **求分子：** `numer = A % MOD`
2. **求分母：** `deno = B % MOD`
3. **求分母逆元：** `inv_deno = pow(deno, MOD - 2, MOD)`  *(Python 3.8+ 也可以写 `pow(deno, -1, MOD)`)*
4. **乘起来再模：** `ans = (numer * inv_deno) % MOD`

---


### 一、 四步走的逐步深度拆解

```python
# 1. 求分子
numer = A % MOD

# 2. 求分母
deno = B % MOD

# 3. 求分母逆元
inv_deno = pow(deno, MOD - 2, MOD)  # 或 pow(deno, -1, MOD)

# 4. 乘起来再模
ans = (numer * inv_deno) % MOD
```

* **第 1 步与第 2 步（独立隔离）：**  
  在进入逆元之前，必须把分子 $A$ 和分母 $B$ **当成两个完全独立的整数**去算。不管它们是由连乘、连加还是递推得到的，算完后都要立刻 `% MOD`，把数值压制在 $[0, MOD - 1]$ 之间。
* **第 3 步（数学变身）：**  
  通过费马小定理，把“除以 $B$”在数学逻辑上彻底等价替换成了“乘以 $inv\_deno$”。
* **第 4 步（收尾归一）：**  
  两个在 $[0, MOD - 1]$ 之间的数相乘，最大可能达到约 $10^{18}$，因此最后必须**再模一次**，把答案重新收拢回 $[0, MOD - 1]$。

---

### 二、 必须牢记的 5 大致命注意事项

在实际做题中，哪怕逻辑完全正确，只要忽视了以下几点，就会遭遇令人抓狂的 **WA（答案错误）** 或 **RE（运行报错）**。

#### ⚠️ 注意事项 1：分母 `deno == 0` 会直接暴毙（ZeroDivisionError）
* **现象：** 如果分母取模后是 $0$，执行 `pow(0, -1, MOD)` 或 `pow(0, MOD - 2, MOD)`，Python 会直接抛出：
  `ZeroDivisionError: base is not invertible for the given modulus`
* **根源：** $0$ 在数学上是没有逆元的。在模意义下，如果分母 $B$ 是 $MOD$ 的倍数，$B \bmod MOD = 0$。
* **应对：**
  * 在题目保证答案存在的前提下，分母通常不会是 $MOD$（$10^9+7$）的倍数。
  * 但要注意**非法状态**！比如组合数 $C_n^r$ 中，如果写漏了 `r < 0 or r > n` 的判断，传进来的分母可能算错变 $0$。**算组合数前务必加特判：**
    ```python
    if r < 0 or r > n:
        return 0
    ```

#### ⚠️ 注意事项 2：最后一步绝对不能漏掉 `% MOD`
新手最常犯的笔误就是：
```python
# 错误写法！
ans = numer * inv_deno  # 忘了取模！
```
* **后果：** 
  虽然 Python 支持超大数不会崩溃，但 $numer \approx 10^9$，$inv\_deno \approx 10^9$，乘积是一个 $10^{18}$ 级别的巨大数！而题目的输出要求答案严格小于 $MOD$（即在 $0 \sim 10^9+6$ 之间）。漏了 `% MOD` 就会直接 **WA（Wrong Answer）**。

#### ⚠️ 注意事项 3：分子中如果有减法，警惕负数
在一些容斥原理或计数题目中，分子是由减法算出来的，例如 $A = X - Y$：
```python
# 危险写法：如果 X % MOD < Y % MOD，可能会带来潜在逻辑混乱
numer = (X - Y) % MOD
```
* **在 Python 中：** Python 的 `%` 机制是向负无穷取整（数学定义上的模），`-3 % 7` 会自动算出 `4`，这在 Python 内部是安全的。
* **但竞赛最佳实践（好习惯）：** 为了防止思维混淆，或者以后用 C++ / Java 写代码，涉及到加减法的分子，**习惯性加上一个 MOD**：
  ```python
  numer = ((X - Y) % MOD + MOD) % MOD
  ```

#### ⚠️ 注意事项 4：模数 $MOD$ 必须是质数
* 无论是使用 `pow(deno, MOD - 2, MOD)` 还是 `pow(deno, -1, MOD)`，底层的数学支撑都是**费马小定理**。
* **前提条件：$MOD$ 必须是一个质数！**
* 在 AtCoder、Codeforces 中，模数几乎 99.9% 都是质数：
  * $1000000007$（$10^9 + 7$，质数）
  * $998244353$（质数）
* 如果哪天遇到极其罕见的不按常理出牌的题，模数是个合数（比如模 $10^9$ 或模 $100000$），**这个四步法则会立刻失效**（必须改用扩展欧几里得）。不过在 1200 分的路上你几乎碰不到这种情况。

#### ⚠️ 注意事项 5：中间过程“连乘”一定要“边乘边模”
如果你在计算分子 $A$ 或分母 $B$ 时需要连乘（例如算阶乘）：
```python
# 不推荐：先乘到天文数字，再一口气取模
# 这样会大量消耗大数乘法的计算时间和内存
deno = 1
for i in range(1, r + 1):
    deno *= i
deno %= MOD

# 正确推荐：边乘边模，数字永远跑在寄存器里，极速！
deno = 1
for i in range(1, r + 1):
    deno = (deno * i) % MOD
```
