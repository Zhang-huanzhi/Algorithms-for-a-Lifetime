Python 内置的 `pow(a, b, [mod])` 是整个 Python 标准库中最强大的数论与代数“神器”之一。它绝不仅仅是一个简单的 `(a ** b) % mod` 语法糖，其底层实现包含了大量针对大整数、性能和密码学场景的极致优化。

以下从**底层原理、高阶特性、性能优势和避坑点**全面介绍它：

---

### 一、基本调用规范

`pow()` 支持两种调用方式：
1. **双参数模式**：`pow(a, b)` $\to$ 等价于 `a ** b`。
2. **三参数模式**：`pow(a, b, mod)` $\to$ 计算 $(a^b) \pmod{mod}$。

在算法竞赛和数论中，**永远使用三参数模式**。

---

### 二、底层原理：为什么它既快又不会爆内存？

如果你写：
```python
ans = (a ** b) % MOD  # 错误做法！
```
Python 会**先**在内存中计算出极其庞大的数字 $a^b$（如果有几亿位，会直接把几十 GB 的内存撑爆），**然后再**做一次昂贵的高精度除法取模。

而内置的 `pow(a, b, mod)` 采用了**蒙哥马利算法（Montgomery Multiplier）或经典的快速幂（Repeated Squaring）**在 CPython 的 C 语言底层（`Objects/longobject.c`）直接实现：
1. 它的时间复杂度是严格的 $O(\log b)$。
2. **边乘边模**：在计算的每一步自乘或累乘时，立即对 `mod` 取模。计算过程中出现的数值**永远不会超过 `mod * mod`**，内存开销恒定为 $O(1)$，即使 $b = 10^{100000}$ 也只需要极微小的内存。

---

### 三、高阶黑科技：指数 $b$ 可以是负数（Python 3.8+）

这是很多 1200 分选手都不知道的 Python 隐藏神技！
在 Python 3.8 之后，**`pow(a, b, mod)` 允许 $b = -1$**。

#### 它的含义：直接求模逆元（Modular Inverse）
在数学中，$a^{-1} \pmod m$ 表示 $a$ 关于模 $m$ 的逆元（即找一个整数 $x$，使得 $a \cdot x \equiv 1 \pmod m$）。

以往在 C++ 或低版本 Python 中，求逆元要写扩展欧几里得算法（`exgcd`），或者用费马小定理写 `pow(a, mod - 2, mod)`。
现在，如果 $a$ 与 $mod$ 互质，你只需要写：

```python
# 求解 3 关于模 10^9+7 的逆元（相当于在模世界里的 1/3）
inv = pow(3, -1, 10**9 + 7)

# 验证一下：3 * inv 应该同余 1
print((3 * inv) % (10**9 + 7))  # 输出 1
```

* **底层实现**：当你传入负指数时，Python 底层会自动调用**扩展欧几里得算法（Extended Euclidean Algorithm）**。
* **极大优势**：即便模数 $mod$ **不是质数**（费马小定理失效），只要 $\gcd(a, mod) == 1$，`pow(a, -1, mod)` 依然能正确算出逆元！若不互质，则会抛出 `ValueError`。

### 四、性能碾压：内置 `pow` vs 手写快速幂

我们做一个简单的速度对比测试（计算 $2^{10^7} \pmod{10^9+7}$）：

```python
import time

MOD = 10**9 + 7
a = 2
b = 10**7

# 1. 内置 pow
t0 = time.time()
ans1 = pow(a, b, MOD)
t1 = time.time()
print(f"内置 pow 耗时: {t1 - t0:.6f} 秒")

# 2. 手写 Python 快速幂
def my_pow(a, b, mod):
    res = 1
    a %= mod
    while b > 0:
        if b & 1:
            res = (res * a) % mod
        a = (a * a) % mod
        b >>= 1
    return res

t2 = time.time()
ans2 = my_pow(a, b, MOD)
t3 = time.time()
print(f"手写快速幂 耗时: {t3 - t2:.6f} 秒")
```
**运行结果通常为**：
* 内置 `pow`：**~ 0.000003 秒**（数微秒）
* 手写快速幂：**~ 0.000035 秒**
* 内置的实现比手写的解释器执行快了 **10 倍左右**，因为底层全由纯 C 语言指针和位运算搞定，没有任何 Python 字节码解释开销。

---

### 五、三大避坑点与限制

1. **类型必须是整数**：
   在三参数模式下，`a, b, mod` **必须全部为整数（int）**。如果传入了浮点数（比如用了 `math.pow` 算出来的结果，或者 `/` 出来的数），会直接报 `TypeError`。
2. **`mod` 不能为 0**：
   `pow(a, b, 0)` 会抛出 `ValueError: pow() 3rd argument cannot be 0`。
3. **不能用于自定义对象（矩阵）**：
   如果你定义了一个二维列表代表矩阵，`pow(matrix, b, mod)` 无法工作。此时**必须手写**之前讲过的快速幂算法。

在 AtCoder 征战中，遇到**大数幂、取模、模逆元、分数取模**，内置的 `pow(a, b, mod)` 是你的第一选择，既短小、又安全、还快到了极致。
