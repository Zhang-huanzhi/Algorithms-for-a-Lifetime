在不加任何剪枝的最坏情况下，生成子集和的**理论时间复杂度**是受数学规律限制的：因为 $M$ 个数共有 $2^M$ 个子集，只要输出所有子集，理论时间复杂度下界就是 **$O(2^M)$**。

但在**实际理论复杂度**和**实际运行耗时**上，这 4 种方法有非常明显的优劣之分：

---

### 一、 理论时间复杂度对比（设半段长度为 $M$）

| 方法 | 理论时间复杂度 | 为什么是这个复杂度？ |
| :--- | :--- | :--- |
| **方法 1：滚动集合法** | **$O(2^M)$** | **最优！** 每一步生成的集合大小翻倍：$1 + 2 + 4 + \dots + 2^{M-1} = 2^M - 1$。无多余循环。 |
| **方法 2：DFS / 回溯** | **$O(2^M)$** | **最优！** 递归树总共有 $2^{M+1} - 1$ 个节点，每个节点只做一次加法。 |
| **方法 3：itertools 组合** | **$O(M \cdot 2^M)$** | 差一点。枚举出组合后，`sum(comb)` 平均还需要耗费 $O(M/2)$ 的求和时间。 |
| **方法 4：二进制状态压缩** | **$O(M \cdot 2^M)$** | 差一点。外层 $2^M$ 次循环，内层必须做 $M$ 次位移和判断：`for i in range(M)`。 |

> 📌 **理论结论**：
> - **方法 1（滚动集合）** 和 **方法 2（DFS）** 的理论复杂度最低，为 **$O(2^M)$**。
> - 状态压缩由于多了一层内层 `range(M)` 的扫描，理论复杂度是 **$O(M \cdot 2^M)$**（多了 $M$ 倍运算）。

---

### 二、 实际场景下：哪个方法跑得最快？

这取决于是否带有**剪枝条件**（Pruning）：

#### 情况 A：有剪枝（题目所有数都是正数 $A_i \ge 1$）👉 **方法 2（DFS + 剪枝）最快**
因为本题中卡片数字都是正数（$A_i > 0$），如果当前累加和已经超过 $K$，**后续分支可以直接扔掉（剪枝）**：

```python
def dfs(index, current_sum):
    if current_sum > k:  # 剪枝！直接砍掉整棵子树
        return
    if index == n:
        sums.add(current_sum)
        return
    dfs(index + 1, current_sum)
    dfs(index + 1, current_sum + arr[index])
```
- **效果**：在实际数据中，剪枝可能把 $2^{15} = 32768$ 次操作直接削减到几百次甚至几十次！

---

#### 情况 B：纯生成所有可能（无剪枝 / 数据有负数）👉 **方法 1（滚动集合）最快**
如果必须把所有子集都算出来，**方法 1（滚动集合）**在 Python 中是绝对的性能冠军：
1. 它没有 Python 递归带来的栈开销（避免函数调用开销）；
2. 内部集合推导式和集合并集 `|=` 直接跑在 **Python 底层的 C 语言** 中；
3. 并且自带**去重效果**（如果数组里有重复元素，集合大小甚至远小于 $2^M$）。

---

### 总结排序

- **理论时间复杂度**：
  $$\text{方法1 (滚动集合)} = \text{方法2 (DFS)} < \text{方法4 (状压)} \approx \text{方法3 (itertools)}$$

- **在 Python 中的实际运行速度**：
  $$\mathbf{带剪枝的 DFS} > \mathbf{滚动集合法} > \mathbf{状压 / itertools}$$
