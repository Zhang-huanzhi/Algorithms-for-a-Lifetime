判断用 **BFS** 还是 **DFS**，在算法竞赛中有一套非常清晰、不纠结的**决策法则**。

---

### 一句话核心法则（黄金口诀）

> **求“最短 / 最少 / 层级扩散” $\to$ 必选 BFS**  
> **求“所有方案 / 树上递归 / 组合回溯” $\to$ 必选 DFS**

---

### 快速决策对照表

| 题目特征 / 问题目标 | 推荐算法 | 核心原因 |
| :--- | :---: | :--- |
| **最短步数 / 最少操作 / 最短路径**（无权图） | **BFS** | BFS 是按层推进，**第一次到达终点必为最优解**，可立刻提前退出（DFS 必须搜遍所有路径才能比大小）。 |
| **多源扩散 / 时间同步**（如：火灾第几秒蔓延全图） | **BFS** | 所有起点一起入队，天然支持多波前同步推进。 |
| **拓扑排序（判断 DAG / 入度拓扑序）** | **BFS** | Kahn 算法（入度为 0 入队），逻辑最清晰。 |
| **树上问题**（子树大小、树形 DP、树的直径/重心） | **DFS** | 树天然是递归结构，**自底向上汇总子节点信息**是 DFS 的本能。 |
| **排列组合 / 所有可行解 / 回溯**（数独、全排列） | **DFS** | 空间复杂度只和递归深度成正比 $O(depth)$，BFS 存所有分支会瞬间内存爆炸（MLE）。 |
| **连通块大小 / 岛屿数量**（Flood Fill） | **两者皆可** | 若不求最短路，只求“数连通块”或“算格子总数”，两者都能做。 |

---

### 底层原理：空间与形态的权衡

选择两者的本质，是在**时间和空间**之间做权衡：

```text
       BFS（横向扩展，水波扩散）              DFS（纵向深入，一条路走到黑）
       
             (根)                                   (根)
            /  |  \                                 / 
         [1]  [1]  [1]   <- 一层层平推            [1]
         / \  / \  / \                            /
        [2][2][2][2]..                           [2]  <- 直插到底，再回溯
```

1. **BFS 空间取决于“宽度”**：
   * 队列里存的是**某一层的全部节点**。如果分支很多（分叉大），队列占用的内存会非常大。
   * 但它能保证**步数由小到大**单调递增。
2. **DFS 空间取决于“深度”**：
   * 栈里只存**当前这条路径上的节点**。空间仅为 $O(\text{递归最大深度})$，极省内存。
   * 但它搜到的第一条完整路径，长度通常是随机的，无法保证最短。

### 针对 Python / AtCoder 选手的实战直觉

1. **网格图（Grid）求连通性**：
   虽然 DFS 也能数岛屿，但如果网格比较大（例如 $1000 \times 1000$），Python 写递归 DFS 很容易触碰默认的 1000 层栈限制，即使调大 `sys.setrecursionlimit` 也容易段错误（RE）。因此在 Python 中，**网格图一律优先写 BFS，稳定不爆栈**。
2. **遇到树（Tree）的题目**：
   只要题目明说是树，90% 都是 **DFS 递归自底向上** 返回信息（比如算子树大小、深度等），几乎不需要犹豫。
