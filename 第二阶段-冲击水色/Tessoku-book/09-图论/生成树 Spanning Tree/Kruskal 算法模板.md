
### 模板代码

```python
import sys

from atcoder.dsu import DSU

def kruskal(n, edges, is_max=True):
    """
    通用生成树求解函数
    :param is_max: True 为最大生成树, False 为最小生成树
    """
    # 【核心开关】：控制排序方向
    # 最小生成树 reverse=False；最大生成树 reverse=True
    edges.sort(key=lambda edge: edge[0], reverse=is_max)

    dsu = DSU(n + 1)
    mst_weight = 0
    edges_count = 0

    for w, u, v in edges:
        # 如果两点未连通，说明加入该边不会成环
        if not dsu.same(u, v):
            dsu.merge(u, v)
            mst_weight += w
            edges_count += 1
            if edges_count == n - 1:
                break

    # 如果遍历完所有边，边数仍不足 n - 1，说明图本身不连通，无法构成生成树
    if edges_count < n - 1:
        return -1  # 或返回 None / 抛出异常

    return mst_weight

```

**无论是最小生成树还是最大生成树，整个代码逻辑 $100\%$ 一模一样，唯一的区别只在 `edges.sort(..., reverse=...)` 这一个参数上。**

---

### 一、 算法核心思想：贪心 + 并查集

生成树要求我们挑选出若干条边，满足两个硬性条件：
1. **树的属性**：无环、连通、边数恰好是 $N - 1$ 条。
2. **极值属性**：所有被选中的边，其权重之和最大（或最小）。

#### 贪心策略（为什么这样是对的？）
* 如果求**最小生成树**：我们自然希望优先挑选**权重极小**的边。
* 如果求**最大生成树**：我们自然希望优先挑选**权重极大**的边。

Kruskal 算法的做法非常直观：
> **把所有边按权值排好序，从最优的边开始一条一条挑。能要就要，会形成环的就扔掉，直到凑齐 $N - 1$ 条边为止。**

---

### 二、 逐行深度拆解

#### 1. 边的排序（核心开关）
```python
edges.sort(key=lambda edge: edge[0], reverse=is_max)
```
* **原理**：贪心选择的前提是有序。
* **实现**：
  * `edge[0]` 表示按照权重 $w$ 作为排序的依据（因为存储结构为 `(w, u, v)`）。
  * 当 `is_max=True` 时，`reverse=True`，边按权重**从大到小（降序）**排列，先挑最大的边，得到**最大生成树**。
  * 当 `is_max=False` 时，`reverse=False`，边按权重**从小到大（升序）**排列，先挑最小的边，得到**最小生成树**。

#### 2. 初始化并查集与状态量
```python
dsu = DSU(n + 1)
mst_weight = 0
edges_count = 0
```
* **`DSU(n + 1)`**：
  * 因为题目中顶点的编号一般是 $1 \sim N$（从 1 开始计）。
  * 并查集是用来**维护连通块**的工具。初始时，每个顶点各自为一个独立的集合，谁也没跟谁连通。
* **`mst_weight`**：记录生成树的边权总和。
* **`edges_count`**：记录当前已经成功选中的边数。

#### 3. 遍历候选边与判环（算法的核心循环）
```python
for w, u, v in edges:
    # 如果两点未连通，说明加入该边不会成环
    if not dsu.same(u, v):
        dsu.merge(u, v)
        mst_weight += w
        edges_count += 1
        if edges_count == n - 1:
            break
```
* **`dsu.same(u, v)` 为什么能判环？**
  * 在图论中，**如果两个点 $u$ 和 $v$ 已经可以通过现有的边互相到达（即在同一个并查集集合内），此时如果你再在它们之间连一条直接的边 $(u, v)$，就一定会闭合成环！**
  * 因此，`if not dsu.same(u, v)` 的含义就是：**加这条边安全，不会破坏“树”的无环特征**。
* **`dsu.merge(u, v)`**：
  * 既然这条边可用，就把 $u$ 所在的集合和 $v$ 所在的集合合并为同一个连通块。
* **`mst_weight += w`**：累加权重。
* **`edges_count += 1` 配合提前退出**：
  * 一棵包含 $N$ 个顶点的树，**有且仅有 $N - 1$ 条边**。
  * 当 `edges_count == n - 1` 时，说明全部 $N$ 个顶点已经被串联成一棵完整的树了，后续无论再看什么边都会形成环，无需再看，直接 `break` 结束循环（关键剪枝，提升效率）。

#### 4. 连通性检查（防御性设计）
```python
if edges_count < n - 1:
    return -1
return mst_weight
```
* **为什么需要这一步？**
  * 如果输入的图本身是个**非连通图**（比如本来就是孤立的几个岛屿，怎么搭桥都凑不满 $N-1$ 条边）。
  * 遍历完所有的 $M$ 条边后，`edges_count` 依然没有达到 $N - 1$，说明根本无法构成一棵覆盖所有点的生成树。返回 `-1` 代表“无解/不连通”。

---

### 三、 复杂度分析（为什么这个算法极快？）

* **时间复杂度：$O(M \log M)$**
  1. **排序边**：边一共有 $M$ 条，对 $M$ 条边排序需要 $O(M \log M)$ 的时间。
  2. **并查集操作**：并查集经过路径压缩后，单次查询和合并的均摊时间是几乎等于常数的 $O(\alpha(N))$（阿克曼反函数）。遍历 $M$ 条边耗时约为 $O(M)$。
  3. **总时间**：受限于排序，总耗时为 $O(M \log M)$。对于 $M = 10^5$ 的规模，通常只需 0.1 秒左右即可跑完。

* **空间复杂度：$O(N + M)$**
  * 存储 $M$ 条边需要 $O(M)$ 空间。
  * 并查集维护 $N$ 个节点的父节点数组需要 $O(N)$ 空间。

### 总结口诀
> **边按权值排好序，贪心依次选边取；  
> 并查集判两端点，若不连通并进去；  
> 凑满 $N-1$ 提前退，未满说明难连聚。**
