如果说 **Kruskal 算法** 是**“以边为中心”**（加边法），那么 **Prim（普里姆）算法** 就是**“以点为中心”**（加点法）。

它在本质上和求单源最短路的 **Dijkstra 算法几乎有 95% 的相似度**。

---

### 一、 Prim 算法的核心思想（贪心“滚雪球”）

用一个形象的比喻：**“修路连村庄”**。

1. **起点**：随便抓一个村庄（比如 1 号村庄）作为大本营，把它划入“已连通区”。
2. **贪心扩张**：看所有**从“已连通区”通往“未连通区”的路**，挑一条**成本最低（权值最小）**的路，把对面的村庄拉进大本营。
3. **重复**：不断重复这个过程，大本营（已连通区）像滚雪球一样越来越大，直到所有村庄都被拉进来。

> **核心逻辑**：每次只挑**离当前已连通集合最近的一个新点**拉进来。

---

### 二、 标准代码实现（优先队列 / 堆优化）

在竞赛中，未经优化的朴素 Prim 是 $O(V^2)$ 的，几乎没人用。我们用的都是**堆优化（Heap）**的 Prim，时间复杂度为 $O(E \log V)$。

这里用纯原生 Python 实现（**最小生成树**）：

```python
import heapq
import sys


def prim(n, adj):
    """
    :param n: 顶点数
    :param adj: 邻接表，adj[u] 存储 (v, w)，表示 u 到 v 有一条权为 w 的边
    :return: 最小生成树权值之和，若不连通返回 -1
    """
    # 记录节点是否已经被拉入“生成树集合”中
    visited = [False] * (n + 1)

    # 小顶堆：存放候选边，格式为 (边权 w, 目标点 to)
    # 如果想存树的形状，可以存 (边权 w, 目标点 to, 起点 from)
    pq = []

    # 1. 任意选一个点作为起点（比如 1 号点），将其加入连通区
    # 将 1 号点的所有出边加入候选堆
    visited[1] = True
    for v, w in adj[1]:
        heapq.heappush(pq, (w, v))

    mst_weight = 0
    node_count = 1  # 当前已连通的点数（初始有 1 号点）

    # 2. 滚雪球过程
    while pq and node_count < n:
        w, u = heapq.heappop(pq)  # 挑一条连接到新世界的最短边

        # 如果这个点已经在生成树里了，跳过（防止成环）
        if visited[u]:
            continue

        # 把点 u 拉入生成树
        visited[u] = True
        mst_weight += w
        node_count += 1

        # 将点 u 连接出去的所有、通往“未访问点”的边扔进堆里
        for next_node, next_w in adj[u]:
            if not visited[next_node]:
                heapq.heappush(pq, (next_w, next_node))

    # 如果最后拉进来的点数不够 n 个，说明原图不连通
    if node_count < n:
        return -1

    return mst_weight
```

*(注：如果是求**最大生成树**，只需把边权取相反数 `-w` 放进小顶堆，弹出时再取反回来即可。)*

### 三、 Prim vs Kruskal：深度对比

很多初学者容易搞混这两个算法，一张表理清它们的区别：

| 维度 | Kruskal（克鲁斯卡尔） | Prim（普里姆） |
| :--- | :--- | :--- |
| **核心策略** | **加边**（全局挑最短的边） | **加点**（挑离当前集合最近的点） |
| **底层数据结构**| **并查集 (DSU)** + 排序 | **优先队列 (Heap / 堆)** |
| **输入图格式** | 边集数组 `edges = [(w, u, v)]` | 邻接表 `adj[u] = [(v, w)]` |
| **时间复杂度** | $O(E \log E)$，受边数影响大 | $O(E \log V)$，受点数影响大 |
| **天然优势场景**| **稀疏图**（边比较少） | **稠密图**（边极多，接近完全图） |

### 四、 针对你的目标（AtCoder 1200+），到底要不要练 Prim？

直白地告诉你结论：**在冲刺 1200 ~ 1400 的阶段，Prim 了解原理即可，不要花大量精力去刷它。**

原因有两点：
1. **AtCoder 的数据特征**：
   AtCoder 的图论题几乎都是稀疏图（$N, M \le 2 \times 10^5$）。这种数据规模下，**Kruskal 永远能过，而且跑得极快**。
2. **Kruskal 的功能更强、更好写**：
   * Kruskal 代码更短（不用建图建邻接表，读入直接排序）；
   * Kruskal 的边排序过程可以顺便做**离线处理、动态加边、连通性阈值判断**，这些性质在思维题里极其强大；
   * 而 Prim 几乎只能老老实实算个权值和，很难做性质扩展。

**一句话总结**：
知道 Prim 像 **Dijkstra** 一样是靠**堆优化**在滚雪球加点即可；上考场做题，**无脑起手 Kruskal** 是通往 1200+ 性价比最高的选择！
