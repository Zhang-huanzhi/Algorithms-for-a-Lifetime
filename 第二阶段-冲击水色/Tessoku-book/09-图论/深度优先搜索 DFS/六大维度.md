### DFS 六大维度全景速查表

| 维度 | 对立的两极 / 分类 | 核心机制与代码标志 | 核心区别点 | 典型应用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 实现机制** | **递归函数**<br>vs<br>**显式迭代栈** | • 递归：`def dfs(...)`<br>• 迭代栈：`stack = [start]` + `while` | 递归直观但有**爆栈风险**；显式栈稍长但**绝对安全**且速度快。 | • 递归：树问题、代码量优先<br>• 显式栈：$N \ge 10^5$ 大图防爆栈 |
| **2. 路径获取** | **动态追踪**<br>vs<br>**静态织网** | • 动态：`path.append()` + `path.pop()`<br>• 静态：`parent[next] = curr` 搜完倒推 | 动态必须**严格维护现场**；静态让遍历和路径提取**彻底解耦**。 | • 动态：收集所有方案、组合题<br>• 静态：找单一路径、最短路 |
| **3. 状态恢复** | **不恢复 (永久标记)**<br>vs<br>**回溯恢复 (撤销现场)** | • 不恢复：`visited[u] = True` 完事<br>• 回溯：`visited[u] = True` 退出时 `= False` | 不恢复是 $O(V+E)$ **线性图遍历**；恢复是 $O(2^N)$ 或 $O(N!)$ **指数级穷举**。 | • 不恢复：连通块、拓扑排序、找一条路<br>• 恢复：全排列、N皇后、数独 |
| **4. 搜索对象** | **显式图**<br>vs<br>**隐式图 (状态空间)** | • 显式：`for v in adj[u]:`<br>• 隐式：`for dx, dy in dirs:` 或枚举下一手动作 | 显式是物理给定的“点和边”；隐式是**规则推演出来的“棋局/状态”**。 | • 显式：网络连通、树、物理图<br>• 隐式：走迷宫、华容道、八数码拼图 |
| **5. 信息流向** | **自顶向下 (推土机)**<br>vs<br>**自底向上 (汇报汇总)** | • 自顶向下：`dfs(u, depth + 1, sum + val)`<br>• 自底向上：`ans = sum(dfs(v) for v in children)` | 自顶向下靠**参数层层下推**；自底向上靠**函数 `return` 结果汇总**。 | • 自顶向下：求路径和是否存在、标记深度<br>• 自底向上：求子树大小、树形 DP、重心 |
| **6. 搜索边界** | **纯暴搜**<br>vs<br>**记忆化 (DP)**<br>vs<br>**剪枝 (Pruning)** | • 纯暴搜：一条路走到黑<br>• 记忆化：`if state in memo: return`<br>• 剪枝：`if cost > best: return` | 纯暴搜毫无防线；记忆化**避免重复子问题**；剪枝**提前掐断死路**。 | • 纯暴搜：空间小的小数据爆搜<br>• 记忆化：背包、区间/状态压缩 DP<br>• 剪枝：旅行商 (TSP)、背包最优解 |

### 一句话定位法

写任何一个 DFS 前，在脑子里过一遍这六个开关，代码的框架就自然成型了。例如：
* **全排列**：递归 + 动态追踪 + **必须回溯恢复** + 隐式图 + 自顶向下 + 纯暴搜。
* **树形 DP（算子树大小）**：递归 + 无需路径 + 不恢复 + 显式图 + **自底向上返回** + 纯遍历。
* **你刚才写的这道题（B62）**：**显式栈** + **静态织网 (Parent)** + **不恢复** + 显式图 + 自顶向下 + 纯遍历。
