### DFS 实现方式全景对比表

| 版本分类                  | 实现结构                | 路径记录方式                                |      爆栈风险       |          代码难度          | 最适用场景                                                            |
| :-------------------- | :------------------ | :------------------------------------ | :-------------: | :--------------------: | :--------------------------------------------------------------- |
| **版本 1：经典递归回溯**       | 函数递归                | **动态维护**<br>`path.append()` + `pop()` | **有**<br>需提递归上限 | 中等<br>(需处理多层 `return`) | • 搜**所有解** (如全排列、N皇后)<br>• 子集搜索、数独求解                             |
| **版本 2：递归 + 织网**      | 函数递归                | **静态记录**<br>`parent` 数组倒推             | **有**<br>需提递归上限 |     简单<br>(无需手动回溯)     | • 树上查询 (如求两点路径、LCA)<br>• 树形 DP / 后序遍历                            |
| **版本 3：迭代栈 + 织网**<br> | 显式栈<br>`list.pop()` | **静态记录**<br>`parent` 数组倒推             |      **无**      |   **极简**<br>(最不易写错)    | • **找任意一条路径** (本题最优)<br>• 连通块遍历<br>• 与 BFS 架构统一 (改 `popleft` 即可) |
| **版本 4：迭代栈硬模拟**       | 显式栈<br>(存节点+邻居索引)   | **栈本身**<br>栈内容物即为正向路径                 |      **无**      | **极高**<br>(边界指针极易 Bug) | • 极度受限环境 (禁止递归且内存严苛)<br>• 面试时考查对“底层调用栈”的理解                       |

---

### 极简选型决策指南

* **搜“所有的解”** $\to$ 选 **版本 1**（必须靠回溯撤销现场去试探下一条路）。
* **搜“一条路径”且怕爆栈** $\to$ 选 **版本 3**（栈负责驱动，`parent` 负责记路，解耦彻底、最稳健）。
* **搜“最短路径”** $\to$ 把 **版本 3** 的 `stack.pop()` 改成 `queue.popleft()`（秒变 **BFS**）。

---

在图论和回溯中，DFS（深度优先搜索）根据 **“实现方式”** （递归 vs 迭代栈）以及   **“如何记录路径”** （ 动态 Path 数组 vs 静态 Parent 数组）的组合，实际上会派生出 **4 大经典版本**。

很多人学 DFS 时觉得一会儿这样写、一会儿那样写，就是因为把这 4 个流派的细节混在了一起。

下面用最直观的方式，把这 4 个版本做一次统一的对比和梳理：

---

### 版本一：【递归 + 动态 Path 数组】（最经典、教学最常教）
* **核心思维**：走一步，把脚印加入 `path`；走不通，把脚印从 `path` 里擦掉（回溯）。
* **控制关键**：函数必须返回 `bool`（找到了吗？），一旦找到就**立刻顺次 return True**，锁死当前 `path` 不再让它被 `pop()` 掉。
* **代码骨架**：
  ```python
  def dfs(u):
      visited[u] = True
      path.append(u)
      if u == target:
          return True  # 找到了！通知上一层别回溯了！

      for v in adj[u]:
          if not visited[v]:
              if dfs(v): 
                  return True  # 收到成功的信号，直接往上交差
      
      path.pop()  # 死胡同，抹掉脚印
      return False
  ```
* **适用场景**：全排列、N 皇后、求**所有**可能路径（只要把终止条件的 `return True` 改成存答案并继续搜即可）。
* **痛点**：找“单一路径”时，新手极容易忘记层层传递 `return True`，导致路径被错误地 `pop` 掉。

---

### 版本二：【递归 + Parent 数组】（最省心、无脑的递归）
* **核心思维**：递归只负责“漫延（连线）”，每到一个新点就认领父亲 `parent[v] = u`；搜完后用 `while` 倒推还原路线。
* **代码骨架**：
  ```python
  def dfs(u):
      if u == target:
          return True
      for v in adj[u]:
          if parent[v] == -1:
              parent[v] = u
              if dfs(v): return True
      return False

  # 搜完倒推
  curr = target
  while curr != start: ...
  ```
* **特点**：不需要维护 `path.append()` 和 `pop()`，递归写起来极短。但依然有 Python 递归爆栈需要加 `sys.setrecursionlimit` 的问题。

---

### 版本三：【迭代显式栈 + Parent 数组】（最推荐的实战写法）
* **核心思维**：
  * **栈（Stack）** 只管提供“深度优先”的前进动力（先进后出）。
  * **Parent 数组** 负责记录路线（顺便充当 `visited` 数组）。
  * **两者完全解耦**：栈爱怎么弹就怎么弹，压根不管路径连不连贯；等找到终点时，让 `parent` 出来把路顺藤摸瓜理出来。
* **代码骨架**：
  ```python
  stack = [start]
  parent[start] = 0

  while stack:
      u = stack.pop()
      if u == target: break
      for v in adj[u]:
          if parent[v] == -1:
              parent[v] = u
              stack.append(v)
  ```
* **特点**：**极其好写、绝无爆栈风险、速度极快**。
* **额外彩蛋**：只要把 `stack.pop()` 换成 `queue.popleft()`，DFS **秒变 BFS**（还能白捡一个“最短路”特性）。

---

### 版本四：【迭代显式栈 + 纯模拟系统调用栈】（最硬核、最容易翻车）
* **核心思维**：不用 `parent`，强行让 `stack` 在任何时刻**都代表正向的一整条路径**。
* **难点**：普通栈做不到回溯。为了知道何时“退栈”，你必须在栈里记录“这个节点目前看到了第几个邻居”。
* **代码骨架**：
  ```python
  # 栈中存放 (当前节点, 看到第几个邻居了)
  stack = [(start, 0)]
  visited[start] = True

  while stack:
      u, idx = stack[-1]
      if u == target: break
      
      if idx < len(adj[u]):
          v = adj[u][idx]
          stack[-1] = (u, idx + 1) # 下次看下一个
          if not visited[v]:
              visited[v] = True
              stack.append((v, 0)) # 深入一层
      else:
          stack.pop() # 所有邻居都看过了，回溯出栈
  ```
* **特点**：底层完全等价于计算机执行递归指令的原理。纯炫技写法，**竞赛极度不推荐**，极容易因为边界条件或索引越界写出死循环。
