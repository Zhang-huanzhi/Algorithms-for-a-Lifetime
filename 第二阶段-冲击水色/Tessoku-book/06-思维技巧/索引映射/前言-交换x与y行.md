### 一、 核心算法技巧：索引映射 / 间接寻址

#### 1. 核心思想：逻辑视图 $\neq$ 物理存储
当你面对一个**“需要频繁对大块数据（一整行、一整列、整个大对象）进行位置调整，但内部元素本身不变”**的问题时，**不要去搬运数据本身，而是去搬运数据的“编号/地址”**。

在这段代码中，数据被拆成了两层：
* **物理层（`grid`）**：存放实际数字的二维矩阵。读入之后，**自始至终一个字节都不动**。
* **逻辑层（`row`）**：一个长度为一维的置换数组（目录）。`row[i]` 的含义是：**“当前在逻辑上的第 `i` 行，实际上存储在物理矩阵 `grid` 的第 `row[i]` 行。”**

```text
物理矩阵 grid（永远不动）        逻辑目录 row（只改这里）
0: [1, 2, 3]                  row[0] = 0  ──▶ 指向 grid[0]
1: [4, 5, 6]                  row[1] = 1  ──▶ 指向 grid[1]
2: [7, 8, 9]                  row[2] = 2  ──▶ 指向 grid[2]

当执行交换 0 行和 1 行后：
                              row[0] = 1  ──▶ 指向 grid[1]
                              row[1] = 0  ──▶ 指向 grid[0]
                              row[2] = 2  ──▶ 指向 grid[2]
```

#### 2. 为什么叫“间接寻址”？
* 直接寻址：`grid[x][y]`（一步到位）。
* 间接寻址：`grid[row[x]][y]`（先通过 `row[x]` 查到真正的物理行号，再取列 `y`）。

多出来的这一次查表几乎没有性能损耗（$O(1)$），却换来了**交换整行数据从 $O(N)$ 降维到 $O(1)$** 的巨大收益。

### 二、 这个技巧的“举一反三”与常见变体

掌握了这个思想，遇到下面这些经典变体题时可以直接秒杀：

1. **同时交换行和列（二维映射）**
   * 再加一个 `col = list(range(n))`。
   * 换列时交换 `col[x], col[y]`；查询时输出 `grid[row[x]][col[y]]`。
2. **矩阵整体翻转 / 旋转 / 循环移位（状态变量映射）**
   * 如果题目要求“把整个数组循环右移 $k$ 位”或“整体左右翻转”，也不需要真的移动数组元素。
   * 只需维护两个简单变量：`offset`（偏移量）和 `is_reversed`（是否翻转标记），查询时通过数学公式算出原始下标即可，这在算法中也常被归类为**“懒标记 / 延迟计算”**思想。
3. **间接排序（Indirect Sort / Argsort）**
   * 如果有一堆很长的字符串或包含几十个字段的大结构体要排序，直接交换它们本身很慢（拷贝成本高）。
   * 可以只对下标数组 `idx = [0, 1, ..., n-1]` 排序（比较规则看 `data[idx[i]]`），排完后通过 `data[idx[i]]` 按顺序访问，物理数据原地不动。
4. **如果需要反查位置（双向映射 / 逆置换）**
   * 如果题目多问一句：“**初始的第 $k$ 行，现在跑到第几行了？**”
   * 可以再维护一个逆数组 `pos[]`（满足 `pos[row[i]] = i`），每次交换 `row[x], row[y]` 时同步更新 `pos`，依然可以做到 $O(1)$ 回答。
