### 一、 核心技巧：状态标记（数据不动，坐标动）

#### 1. 为什么不能直接模拟？
题目中 $N, Q \le 200,000$。
如果每次遇到操作 `2` 都真的去把数组反转一遍（比如 `arr.reverse()`），单次操作的时间复杂度是 $O(N)$。如果 $Q$ 次操作全是反转，总时间复杂度就是 $O(NQ) \approx 4 \times 10^{10}$，在 1 秒的时限内必然 **TLE（超时）**。

#### 2. 破局思路：用“视角变化”代替“数据搬移”
观察发现：**数组反转两次就会变回原样**。也就是说，数组无论怎么反转，永远只有两种状态：
* **正向状态**（`state = True`）
* **反向状态**（`state = False`）

既然只有两种状态，我们根本不需要真的去移动内存里的 $N$ 个元素，只需要维护一个布尔变量 `state`：
* **遇到反转操作（操作 2）**：只需要把 `state` 取反（`state = not state`），时间复杂度瞬间从 $O(N)$ 降到了 **$O(1)$**！
* **遇到修改/查询操作（操作 1、3）**：根据当前的 `state` 做一次**下标映射**即可。
  * 在 0-indexed（下标从 0 开始）下，长度为 $n$ 的数组：
    * 正向时，第 `x` 个元素的真实下标就是 `x`。
    * 反向时，原来的尾巴变成了头，第 `x` 个元素的真实下标就是 `n - 1 - x`（或者利用 Python 的负数索引写成 `~x` / `-x - 1`）。

这样一来，每次操作都是 $O(1)$，总时间复杂度降到了 **$O(N + Q)$**，轻松通过。

### 二、 举一反三：这类技巧的常见变体

这种 **“不真正修改整个数组，而是用一个变量记录全局状态，访问时再换算”** 的思想在算法竞赛中非常高频，俗称 **懒标记（Lazy）思想** 或**维护全局状态**。常见的同类题还有：

1. **数组循环左移 / 右移 $k$ 位**
   * 技巧：不要真的移动数组，维护一个全局偏移量 `offset`。查询位置 `x` 时，去查 `arr[(x + offset) % n]`。
2. **给整个数组的所有元素都加上 $v$**
   * 技巧：不要遍历数组去加，维护一个全局变量 `global_add += v`。
   * 查询 `arr[x]` 时输出 `arr[x] + global_add`；如果单点修改 `arr[x] = y`，则存入 `y - global_add`。
3. **数组反转 + 在数组头部/尾部插入元素**（经典变体，如 AtCoder ABC158 D）
   * 技巧：这种题**才需要用到 `deque`（双端队列）**！正向时头插用 `appendleft`、尾插用 `append`；反向时反过来即可。
