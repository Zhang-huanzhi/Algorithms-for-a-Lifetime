如果你在 **AtCoder** 上使用 Python 并且目标是 **1200+（水色）**，那么 **`sortedcontainers` 是你必须掌握的“神级外挂库”**。

在 C++ 中，选手有 `std::set`、`std::multiset`、`std::map`（底层为红黑树），支持 $O(\log N)$ 的插入、删除和有序二分查找。而 Python 原生标准库中：
* `list` 插入/删除中间元素是 $O(N)$。
* `heapq`（堆）只能看堆顶，**无法 $O(\log N)$ 删除任意指定元素**，也不能按排名查找。

为了解决这个问题，第三方库 **`sortedcontainers`** 应运而生。最重要的是：**AtCoder 评测系统原生预装了该库**，你可以直接 `import` 使用！

---

### 一、三大核心结构

`from sortedcontainers import SortedList, SortedSet, SortedDict`

1. **`SortedList`（最常用，相当于 C++ 的 `std::multiset` + 排名树）**：
   * 自动保持元素升序排列，**允许重复元素**。
2. **`SortedSet`（相当于 C++ 的 `std::set`）**：
   * 自动升序排列，**不允许重复元素**。
3. **`SortedDict`（相当于 C++ 的 `std::map`）**：
   * 键（Key）自动升序排列的字典。

在竞赛中，**90% 以上的场景使用的是 `SortedList`**。

---

### 二、底层原理：为什么它极快？

很多语言的有序集合采用红黑树或 AVL 树，但纯 Python 写红黑树会有巨大的对象开销和指针跳转，速度极慢。

`SortedList` 底层采用了**分块列表（B 树变种 / 块状链表）**思想：
* 将 $N$ 个元素拆分成若干个大小约为 $L \approx \sqrt{N}$ 的连续子列表。
* 插入/删除时先二分找到对应的块，再调用 Python 底层 C 实现的 `list.insert()` / `list.pop()`。
* 这使得它兼顾了**二分查找的对数复杂度**和**C 原生数组的高速内存局部性**，在 AtCoder $N = 10^5 \sim 2 \times 10^5$ 的数据规模下，通常能在 0.5 秒内轻松通过。

### 三、`SortedList` 核心 API 与时间复杂度

| 操作 | 语法 | 时间复杂度 | 对应说明 |
| :--- | :--- | :--- | :--- |
| **插入元素** | `sl.add(x)` | $O(\log N)$ | 插入后自动保持有序 |
| **删除指定值** | `sl.remove(x)` / `sl.discard(x)` | $O(\log N)$ | `remove` 不存在会报错，`discard` 不会 |
| **按索引删除** | `sl.pop(index)` | $O(\log N)$ | 比如弹出最大值：`sl.pop(-1)` |
| **按排名/索引访问** | `sl[k]` | $O(\log N)$ | **C++ `std::set` 做不到**，可直接查第 $k$ 小 |
| **二分查找** | `sl.bisect_left(x)` / `sl.bisect_right(x)` | $O(\log N)$ | 找到第一个 $\ge x$ 或 $> x$ 的下标 |
| **统计频次** | `sl.count(x)` | $O(\log N)$ | 快速统计 $x$ 出现了多少次 |
| **求元素个数** | `len(sl)` | $O(1)$ | 当前集合大小 |

### 四、快速上手示例

```python
from sortedcontainers import SortedList

# 1. 初始化
sl = SortedList([5, 1, 3, 3])
# sl 内部自动排好序: [1, 3, 3, 5]

# 2. 插入新元素
sl.add(2)
# sl: [1, 2, 3, 3, 5]

# 3. 按下标随机访问（找第 k 小 / 中位数）
print(sl[0])   # 最小值: 1
print(sl[-1])  # 最大值: 5
print(sl[2])   # 第 3 小的值: 3

# 4. 二分查找前驱/后继
idx = sl.bisect_left(3)   # 第一个 >= 3 的位置（下标 2）
idx = sl.bisect_right(3)  # 第一个 > 3 的位置（下标 4）

# 5. 删除元素
sl.remove(3)   # 删除一个 3，sl 变为: [1, 2, 3, 5]
sl.pop(0)      # 弹出最小值，sl 变为: [2, 3, 5]
```

### 五、在 AtCoder 中的经典应用场景（1200+ 常见题型）

#### 场景 1：动态维护中位数 / 第 $k$ 大数
* **题目特征**：不断有数据流插入或删除，要求实时输出当前集合的中位数。
* **做法**：普通数组排序会 $T = O(N^2)$；使用 `sl.add(x)` 后，直接访问 `sl[len(sl) // 2]`，单次耗时 $O(\log N)$。

#### 场景 2：动态前驱与后继查询（最近邻搜索）
* **题目特征**：集合动态变化，每次询问“当前集合中最接近 $X$ 的元素是哪个？”
* **做法**：
  ```python
  idx = sl.bisect_left(x)
  # 候选值只有两个：sl[idx]（后继） 和 sl[idx - 1]（前驱）
  # 比较两者的 abs 差值即可
  ```

#### 场景 3：滑动窗口极值/任意元素删除
* **题目特征**：在长度为 $K$ 的滑动窗口中维护最大值、最小值或集合状态，窗口右移时需要**删除移出窗口的特定元素**。
* **做法**：`heapq` 无法高效删除任意值（需打懒标记），而 `SortedList` 直接 `sl.remove(out_val)` 即可。

### 六、竞赛中的注意事项与避坑指南

1. **平台支持情况**：
   * **AtCoder**：**原生支持**，放心使用。
   * **LeetCode**：原生支持。
   * **Codeforces**：**不支持**（CF 上只能自己手写 Treap / 分块，或者转用 C++）。
2. **初始化方式**：
   * 如果一开始就有一批数据，**不要**一个一个 `add()`（耗时 $O(N \log N)$）；
   * **直接传入可迭代对象初始化**：`sl = SortedList(initial_list)`，内部使用归并建表，耗时仅 $O(N \log N)$ 且常数极小。
3. **避免在循环中对 `SortedList` 进行切片**：
   * `sl[1:5]` 这类切片操作会生成新列表，复杂度是 $O(K)$。如果频繁进行大范围切片，容易超时（TLE）。
