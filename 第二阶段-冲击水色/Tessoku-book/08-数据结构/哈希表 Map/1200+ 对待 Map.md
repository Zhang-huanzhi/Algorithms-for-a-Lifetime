在 AtCoder 中，目标达到 **1200+（水色/Cyan）**，意味着你必须能够稳定做出 **ABC 的 C 题和 D 题，并经常突破 E 题**。

在这个分段，**单纯考“增删查改”的哈希题（如你刚做的 A54/B54）只能算签到考点（Diff < 600）**。
想要冲上 1200+，哈希表（在 Python 中即 `dict` / `Counter` / `set`）主要是作为**将算法复杂度从 $O(N^2)$ 降到 $O(N)$** 或**辅助高级算法**的核心工具。

以下是冲击 1200+ 必须掌握的 **5 大哈希表核心考点** 与对应经典例题：

---

### 考点一：前缀和 / 模运算 + 哈希表（最经典高频考点）
* **核心思维**：
  区间和查询通常是 $S[r] - S[l] = K$。直接双重循环是 $O(N^2)$，移项转化为寻找前面出现过的 $S[l] = S[r] - K$。
  利用哈希表在遍历 $r$ 的同时动态记录历史 $S[l]$ 的频次，将复杂度降为 $O(N)$。
* **经典例题**：
  1. **ABC 200 C - Ringo's Favorite Numbers 2** (Diff: 470)
     * *考点*：余数分组 $(A_i - A_j) \pmod{200} = 0 \iff A_i \equiv A_j \pmod{200}$，哈希表统计频次后做组合数。
  2. **ABC 233 D - Count Interval** (Diff: 880，**必刷经典**)
     * *考点*：求有多少个连续子数组的和恰好等于 $K$。
  3. **ABC 105 D - Candy Distribution** (Diff: 1180)
     * *考点*：区间和能被 $M$ 整除，即 $(S_r - S_l) \equiv 0 \pmod M \implies S_r \equiv S_l \pmod M$。

---

### 考点二：状态压缩（奇偶性/异或）+ 哈希表
* **核心思维**：
  当题目要求“某个区间内某些元素的频次全为偶数”或“某种模式出现次数”时，直接维护频次不可行。可以将频次的**奇偶性压缩成二进制状态（Bitmask）**，利用异或前缀和 + 哈希表在 $O(N)$ 内求解。
* **经典例题**：
  1. **ABC 295 D - Three Days Ago** (Diff: 1040，**近年极高频考题**)
     * *考点*：统计有多少个子串经过重排可以变成两个相同的串（即子串中每个数字 `0~9` 出现的次数都必须是偶数）。用 10 位的状态前缀和 + 哈希表。
  2. **ABC 365 D 或类似的区间奇偶配对题**

---

### 考点三：大范围稀疏状态记忆化搜索（Map 做 DP）
* **核心思维**：
  普通线性 DP 数组需要大小连续（如 `dp[100000]`）。但如果输入规模 $N \le 10^{18}$，状态空间非常大却非常**稀疏**（有效访问状态数只有几万个），必须使用哈希表做记忆化存储（Python 中可直接用 `dict` 或 `@functools.lru_cache(None)`）。
* **经典例题**：
  1. **ABC 275 D - Yet Another Recursive Function** (Diff: 600)
     * *考点*：$f(x) = f(\lfloor x/2 \rfloor) + f(\lfloor x/3 \rfloor)$，$N \le 10^{18}$，用哈希表记忆化。
  2. **ABC 340 C - Divide and Divide** (Diff: 935)
     * *考点*：$f(N) = N + f(\lfloor N/2 \rfloor) + f(\lceil N/2 \rceil)$，哈希表记忆化递归。

---

### 考点四：折半搜索 (Meet in the Middle) + 哈希查找
* **核心思维**：
  当 $N \approx 40$ 时，暴力枚举为 $O(2^{40}) \approx 10^{12}$ 超时。
  将其分成前后两半：前半部分 $2^{20} \approx 10^6$ 算出的所有结果放入哈希表；后半部分 $2^{20}$ 枚举时在哈希表中以 $O(1)$ 查找匹配，整体复杂度优化到 $O(2^{N/2})$。
* **经典例题**：
  1. **ABC 271 F - XOR on Grid Path** (Diff: 1390，冲 1200+ 关键题)
     * *考点*：网格从左上走到右下求异或和为 0 的路径数。从起点和终点分别走到对角线折半，哈希表记录异或结果。
  2. **典型 90 题 - 051 - Typical Shop** (Diff: 1350)
     * *考点*：选 $K$ 个物品使其总和 $\le P$，经典的折半搜索。

---

### 考点五：多重集判等与随机权值哈希 (Zobrist Hash)
* **核心思维**：
  判断两个集合、前缀的元素集合是否完全一致，如果直接排序或用集合比较需要 $O(K \log K)$。
  为每个数值赋予一个随机 64 位整数（利用哈希碰撞概率极低的性质），集合的异或和/加和相同即视为集合相同。
* **经典例题**：
  1. **ABC 250 E - Prefix Equality** (Diff: 1250)
     * *考点*：询问数组 $A$ 的前 $x$ 项构成的集合与数组 $B$ 的前 $y$ 项构成的集合是否相等。利用集合哈希或预处理。
  2. **ABC 367 D - Pedometer** (Diff: 1100+)
     * *考点*：环形前缀和与模运算匹配。

---

### 💡 Python 选手在 AtCoder 使用哈希表的避坑建议

1. **避免多次无意义查询**：
   ```python
   # 慢（查询了两次哈希）
   if x in memo:
       ans += memo[x]
   
   # 快（利用 get 或 defaultdict）
   ans += memo.get(x, 0)
   ```
2. **离散化时：二分查找往往优于哈希表**：
   如果仅需对大数字进行**坐标离散化（Coordinate Compression）**，使用 `vals = sorted(set(A))` 配套 `bisect_left` 比将每个数值存进字典速度更快，内存占用小得多。
3. **警惕哈希冲突退化（Anti-Hash Test Cases）**：
   虽然 AtCoder 较少有针对 Python `dict` 的专门 Hack 数据，但在处理海量整数哈希时，对值做异或混淆（如 `x ^ RANDOM_MASK`）存入字典是防止最坏情况退化为 $O(N)$ 链表的有效防护手段。
