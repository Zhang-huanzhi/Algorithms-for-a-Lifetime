树状数组（Binary Indexed Tree，简称 **BIT**，又称 **Fenwick Tree**）的核心思想可以总结为一句话：

> **利用二进制数字的特性，把前缀区间拆分成 $\log N$ 个特定的子区间来管理。**

---

### 一、面临的痛点：传统方法的两难

假设我们有一个数组维护动态数据：
1. **普通数组**：
   - 单点修改：$O(1)$
   - 区间求和（遍历累加）：$O(N)$
2. **前缀和数组（Prefix Sum）**：
   - 区间求和（两数相减）：$O(1)$
   - 单点修改（后面所有的前缀和都要重新算）：$O(N)$

**树状数组的目的**：找一个折中点，让 **单点修改** 和 **区间求和** 的时间复杂度都能达到 **$O(\log N)$**。

---

### 二、核心武器：`lowbit(x)`

树状数组的一切精髓都在于这个操作：
$$\text{lowbit}(x) = x \ \& \ (-x)$$

**它表示什么？**
- 它返回 $x$ 的二进制表示中，**最低位的 $1$ 所代表的数值**。
- **例子**：
  - $6$ 的二进制是 $(110)_2$，最低位的 $1$ 在倒数第二位，所以 $\text{lowbit}(6) = (010)_2 = 2$。
  - $8$ 的二进制是 $(1000)_2$，最低位的 $1$ 在倒数第四位，所以 $\text{lowbit}(8) = (1000)_2 = 8$。
  - $7$ 的二进制是 $(0111)_2$，最低位的 $1$ 在末尾，所以 $\text{lowbit}(7) = (0001)_2 = 1$。

> **为什么是 `x & -x`？**  
> 计算机中使用补码表示负数，$-x = \sim x + 1$（取反加 1）。取反加 1 之后，原数最低位的 $1$ 会保留下来，而该位左边的所有位全部取反，该位右边的位全都是 0。两者按位与运算，刚好就只剩下了最低位的那个 $1$。

---

### 三、树状数组的管辖范围

我们定义一个树状数组 `tree[]`（从下标 1 开始）：
- **`tree[i]` 维护的是原数组 $A$ 中以 $i$ 结尾、长度为 $\text{lowbit}(i)$ 的一段区间的和**。
- 区间范围是：**$(i - \text{lowbit}(i), i]$**

我们来看前 8 个位置，`tree[i]` 到底管辖哪几个数：

| 下标 $i$ | 二进制 | $\text{lowbit}(i)$ | 管辖的长度 | `tree[i]` 实际存储的和 |
| :--- | :--- | :--- | :--- | :--- |
| **1** | $0001_2$ | **1** | 1 | $A_1$ |
| **2** | $0010_2$ | **2** | 2 | $A_1 + A_2$ |
| **3** | $0011_2$ | **1** | 1 | $A_3$ |
| **4** | $0100_2$ | **4** | 4 | $A_1 + A_2 + A_3 + A_4$ |
| **5** | $0101_2$ | **1** | 1 | $A_5$ |
| **6** | $0110_2$ | **2** | 2 | $A_5 + A_6$ |
| **7** | $0111_2$ | **1** | 1 | $A_7$ |
| **8** | $1000_2$ | **8** | 8 | $A_1 + A_2 + \dots + A_8$ |

从上表可以发现神奇的规律：
1. **所有奇数位置**：$\text{lowbit}$ 都是 1，所以它们只管自己那 1 个数。
2. **2 的幂次方位置**（2, 4, 8, ...）：管辖的是从 $1$ 到自身的所有数的前缀总和。
3. 其他偶数位置：管辖一小段特定长度的子区间。

---

### 四、怎么算前缀和？（`query` 查询过程）

假设我们要算前缀和 $\text{sum}(7) = A_1 + A_2 + \dots + A_7$。

我们把 $7$ 写成二进制：$7 = 4 + 2 + 1$。
树状数组的拆分正是基于此：
1. 先加上以 7 结尾的区间：`tree[7]`（长度是 $\text{lowbit}(7) = 1$，包含了 $A_7$）。
2. 下标跳跃：$7 - \text{lowbit}(7) = 6$。
3. 加上以 6 结尾的区间：`tree[6]`（长度是 $\text{lowbit}(6) = 2$，包含了 $A_5 + A_6$）。
4. 下标跳跃：$6 - \text{lowbit}(6) = 4$。
5. 加上以 4 结尾的区间：`tree[4]`（长度是 $\text{lowbit}(4) = 4$，包含了 $A_1 + A_2 + A_3 + A_4$）。
6. 下标跳跃：$4 - \text{lowbit}(4) = 0$，结束！

把它们加起来：
$$\text{sum}(7) = \text{tree}[7] + \text{tree}[6] + \text{tree}[4] = (A_7) + (A_5 + A_6) + (A_1 + A_2 + A_3 + A_4)$$
不重不漏，刚好加到了 $A_1 \sim A_7$！

代码极其简短：
```python
def query(idx):
    res = 0
    while idx > 0:
        res += tree[idx]
        idx -= idx & -idx  # 每次减去 lowbit
    return res
```
> **时间复杂度**：每一次减去 $\text{lowbit}$，就相当于把二进制中最右边的一个 `1` 抹成 `0`。一个数在二进制下的 `1` 最多只有 $\log_2 N$ 个，所以查询只需要循环 **$O(\log N)$** 次！

### 五、怎么做单点更新？（`add` 更新过程）

假设我们要给 $A_3$ 加上一个值 $x$。
根据前面的管辖关系，只要某个 `tree[i]` 的管辖区间**包含 $A_3$**，它就需要加上 $x$。

谁管辖了 $A_3$ 呢？
1. $3$ 自己肯定管辖了：更新 `tree[3]`。
2. 往上找它的父节点：$3 + \text{lowbit}(3) = 3 + 1 = 4$。`tree[4]` 管辖了 $A_1 \sim A_4$（包含 3），所以更新 `tree[4]`。
3. 继续往上：$4 + \text{lowbit}(4) = 4 + 4 = 8$。`tree[8]` 管辖了 $A_1 \sim A_8$（包含 3），所以更新 `tree[8]`。
4. 继续往上直到超过数组长度 $N$。

代码：
```python
def add(idx, val):
    while idx <= n:
        tree[idx] += val
        idx += idx & -idx  # 每次加上 lowbit
```
> **时间复杂度**：每一次加上 $\text{lowbit}$ 都会向高位进位，循环次数同样不会超过树的高度，时间复杂度为 **$O(\log N)$**。

### 六、为什么它叫“树”状数组？

很多初学者疑惑：这明明是一个一维数组，树在哪？
如果你画出节点间的跳跃关系（子节点通过 `+ lowbit` 指向父节点）：

```text
               tree[8] (1~8)
              /   |   \
             /    |    \
      tree[4](1~4) \    tree[6](5~6)
      /    \        \       |
  tree[2] tree[3]  tree[5] tree[7]
   (1~2)    (3)      (5)    (7)
    |
  tree[1]
    (1)
```
- 叶子节点全是奇数（$\text{lowbit} = 1$）。
- 向上跳跃的过程（`idx += lowbit`）本质上是在**沿着树枝向父节点爬升**。
- 向下查询的过程（`idx -= lowbit`）本质上是在**前缀区间上做树的分治累加**。

它巧妙地**把一棵逻辑上的二叉树（分治结构）用简单的二进制位运算压缩在了一个一维数组里**，不需要指针，不需要建树，优雅且高效！
