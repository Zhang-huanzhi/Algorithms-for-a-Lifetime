学习字符串哈希（String Hash）最爽的地方在于：**它的解题套路非常固定，识别特征明显，代码模板几乎一字不改**。

掌握以下这套“识别特征 + 核心模板 + 经典题型组合技”，在面试和算法竞赛中遇到绝大多数字符串哈希题都能秒杀。

---

### 一、 题型识别信号（什么时候该想到哈希？）

当你在题目中看到以下**三个信号**之一，脑子里直接弹出“字符串哈希”：

1. **区间对比高频发生**：
   * 题面有大量的查询（$Q \ge 10^4$），问“子串 $A$ 和子串 $B$ 是否相同？”
2. **需要快速判断“回文串”**：
   * 判断一个子串正着读和反着读是否一样（求正向哈希和反向哈希，比对是否相等）。
3. **结合“二分查找”求最长公共前缀（LCP）**：
   * 问“两个后缀的最长公共前缀有多长？”（具有单调性：如果前 10 个字符相同，那前 5 个肯定也相同，可以直接二分长度，用哈希 $O(1)$ 验证）。

### 二、 万能代码套路（肌肉记忆模板）

做题时不要现场想推导，直接默写固定骨架。

#### 1. 骨架三步法：
* **第 1 步：配置常数**（选好基数和模数，防卡选双哈希）。
* **第 2 步：一次性前缀打表**（计算 $O(N)$ 的 `pow` 数组和 `h` 数组）。
* **第 3 步：写一个提取函数**（用减法公式 $O(1)$ 提取子串）。

#### 2. Python 竞赛通用模板：
```python
# --- 步骤 1：固定参数 ---
MOD1, BASE1 = 10**9 + 7, 13331
MOD2, BASE2 = 10**9 + 9, 13337


# --- 步骤 2：预处理 (构建前缀与幂次) ---
def build_hash(s):
    n = len(s)
    pow1 = [1] * (n + 1)
    pow2 = [1] * (n + 1)
    h1 = [0] * (n + 1)
    h2 = [0] * (n + 1)

    for i in range(n):
        val = ord(s[i]) - ord("a") + 1
        pow1[i + 1] = (pow1[i] * BASE1) % MOD1
        pow2[i + 1] = (pow2[i] * BASE2) % MOD2
        h1[i + 1] = (h1[i] * BASE1 + val) % MOD1
        h2[i + 1] = (h2[i] * BASE2 + val) % MOD2

    # --- 步骤 3：O(1) 查询区间 [l, r] (注意这里是 1-based 还是 0-based) ---
    def get_hash(l, r):  # 假设是 1-based 下标
        length = r - l + 1
        v1 = (h1[r] - h1[l - 1] * pow1[length]) % MOD1
        v2 = (h2[r] - h2[l - 1] * pow2[length]) % MOD2
        return (v1, v2)

    return get_hash
```

### 三、 经典题型套路合集（拿到模板后怎么破题？）

几乎所有的字符串哈希难题，都是用上面的模板配合其他算法打**“组合拳”**：

#### 套路 1：单次比对（最基础）
* **题型**：像本题（AtCoder A56），每次给出两个区间 $[a, b]$ 和 $[c, d]$，问是否相等。
* **解法**：直接 `get_hash(a, b) == get_hash(c, d)`。

#### 套路 2：二分答案 + 哈希（高频考点）
* **场景**：求两个字符串的**最长公共前缀（LCP）**，或者**最长重复子串**。
* **套路分析**：
  * 如果长度为 $K$ 的子串相同，那么长度为 $K-1$ 的前缀必然也相同；如果长度为 $K$ 的子串不同，那更长的肯定不同。这具备**单调性**！
  * **套路解法**：二分长度 $mid \in [1, \min(len_1, len_2)]$。在二分内部，用哈希 $O(1)$ 判断长度为 $mid$ 的前缀是否相等。
  * **复杂度**：从暴力的 $O(N)$ 降到 $O(\log N)$。

#### 套路 3：哈希 + 哈希表 / 滑动窗口（去重与统计）
* **场景**：给你一个长字符串，问“长度为 $K$ 的不同子串有多少个？”（如 LeetCode 187 重复的DNA序列）
* **套路解法**：
  * 枚举所有长度为 $K$ 的滑动窗口 $[i, i+K-1]$；
  * 用哈希在 $O(1)$ 算出每个窗口的哈希值；
  * 把哈希值丢进一个 `set`（集合）里；
  * 最后 `len(set)` 就是答案。
  * **复杂度**：从 $O(N \times K)$ 暴降到 $O(N)$！

#### 套路 4：正反哈希比对（极速判回文）
* **场景**：查询子串 $S[l \dots r]$ 是不是回文串？
* **套路解法**：
  * 构建**两份**哈希：一份是正向字符串的前缀哈希，另一份是反转字符串（Reverse）的前缀哈希。
  * 如果 $S[l \dots r]$ 是回文串，那么**它的正向哈希值必然等于反向哈希值**。
  * 依然只需 $O(1)$ 一步比对，彻底告别逐字双指针回文检查。

### 四、 防翻车实战细节（必坑指南）

1. **字符映射不要从 0 开始**：
   * `'a'` 不要映射为 `0`，最好从 `1` 开始（如 `ord(c) - ord('a') + 1`）。
   * *原因*：如果 `'a'` 是 `0`，那么 `"a"`, `"aa"`, `"aaa"` 算出来的哈希值全是 `0`，无法区分。
2. **基数 $B$ 的选取原则**：
   * $B$ 必须**严格大于字符集的大小**（小写字母 26 个，选 $B \ge 27$，通常选质数如 $131$、$13331$）。
3. **警惕 Python I/O 陷阱**：
   * 哈希题目通常伴随着几万到几十万次查询。Python 如果在循环里用 `input()` 或 `sys.stdin.readline()` 极易发生 I/O 超时（TLE）。必须用 `sys.stdin.read().split()` 一次性读入。
4. **遇事不决写双哈希**：
   * 遇到只要几百次的小题，单哈希随便写；
   * 只要查询次数超过 $10^4$，不要心存侥幸，**直接上双哈希**，100% 避免被卡。
