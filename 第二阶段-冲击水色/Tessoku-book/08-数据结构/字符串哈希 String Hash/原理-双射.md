字符串哈希（String Hash），尤其是竞赛和工程中最常用的**多项式滚动哈希（Polynomial Rolling Hash）**，其核心本质可以用一句话概括：

> **把字符串看作一个“高进制的大整数”，并利用“前缀和与差分”的思想，在 $O(1)$ 时间内截取任意子串的数值。**

为了彻底讲透它的数学与算法原理，我们分四个递进的层面来剖析：

---

### 一、 字符编码：把字符映射为数字
计算机无法直接对字母做加减乘除，第一步是将字符数字化。  
对于仅含小写字母 `'a' ~ 'z'` 的字符串，通常做如下映射：
* `'a' \to 1`
* `'b' \to 2`
* $\dots$
* `'z' \to 26`

*(注意：通常不映射为 0，因为 0 乘任何数都为 0，会导致无法区分 `"a"`、`"aa"`、`"aaa"` 等前导字符)*。

---

### 二、 多项式编码：进制转换原理
我们平时熟悉的十进制数字，比如字符串 `"427"`，它的数值表示是：
$$4 \times 10^2 + 2 \times 10^1 + 7 \times 10^0 = 427$$

同理，对于任意字符串 $S = s_1 s_2 \dots s_k$，我们可以选定一个大于字符种类数的**基数 $B$（Base，相当于进制数）**，将其编码为一个多项式的值：
$$\text{Hash}(S) = s_1 \cdot B^{k-1} + s_2 \cdot B^{k-2} + \dots + s_{k-1} \cdot B^1 + s_k \cdot B^0 = \sum_{i=1}^{k} s_i \cdot B^{k-i}$$

* **为什么只要进制 $B$ 足够大，哈希值就绝对唯一？**  
  根据数论基础，在不溢出的情况下，任何一个有限序列在 $B$ 进制（$B > \max(s_i)$）下的表示都是**一一对应（双射）**的。不同的字符串，算出的数值必然不同。

---

### 三、 核心技巧：前缀哈希与 $O(1)$ 区间提取
如果每次提取子串都要重新从头乘到尾，时间复杂度依然是 $O(L)$。字符串哈希能做到 $O(1)$ 的精髓在于**类似前缀和（Prefix Sum）的数学差分推导**。

#### 1. 前缀哈希的递推构建（$O(N)$ 预处理）
定义 $H[i]$ 为字符串前 $i$ 个字符组成的子串（即前缀 $S[1 \dots i]$）的哈希值。  
根据进制乘法，递推关系为：
$$H[0] = 0$$
$$H[i] = H[i-1] \times B + s_i$$

展开来看就是：
* $H[1] = s_1$
* $H[2] = s_1 B + s_2$
* $H[3] = s_1 B^2 + s_2 B + s_3$
* $\dots$
* $H[i] = s_1 B^{i-1} + s_2 B^{i-2} + \dots + s_i$

#### 2. 任意区间 $[l, r]$ 的数学提取（$O(1)$ 查询）
假设我们要获取子串 $S[l \dots r]$ 的哈希值，它的理论多项式应该是（长度为 $L = r - l + 1$）：
$$\text{Hash}(S[l \dots r]) = s_l B^{L-1} + s_{l+1} B^{L-2} + \dots + s_r$$

我们手头有：
* 前缀 $r$ 的哈希值：$H[r] = (s_1 B^{r-1} + \dots + s_{l-1} B^{r-l+1}) + (s_l B^{r-l} + \dots + s_r)$
* 前缀 $l-1$ 的哈希值：$H[l-1] = s_1 B^{l-2} + s_2 B^{l-3} + \dots + s_{l-1}$

观察两者的关系：$H[l-1]$ 的每一项正好比 $H[r]$ 中多余的前缀项**低了 $L = r - l + 1$ 次方**！  
因此，只需将 $H[l-1]$ “左移” $L$ 位（即乘以 $B^L$）：
$$H[l-1] \times B^L = s_1 B^{r-1} + s_2 B^{r-2} + \dots + s_{l-1} B^{r-l+1}$$

两式相减，多余的前缀部分被完全抵消：
$$\text{Hash}(S[l \dots r]) = H[r] - H[l-1] \times B^{r - l + 1}$$

只要我们预先计算并保存了 $B$ 的各次幂数组 $P[k] = B^k$，上述式子只需**一次查表、一次乘法、一次减法**即可完成，复杂度严格为 **$O(1)$**。

---

### 四、 现实约束：模运算与哈希碰撞（Collision）

在理论上，如果字符串长度为 100,000，算出的数字将达到 $B^{100000}$，这是一个天文数字，计算机会发生大数运算性能骤降甚至内存溢出。

#### 1. 模数引入
为了控制数值大小在机器整型范围内，计算过程中的每一步都必须引入**大质数模数 $M$（Modulo）**：
* 递推：$H[i] = (H[i-1] \times B + s_i) \pmod M$
* 幂次：$P[i] = (P[i-1] \times B) \pmod M$
* 提取区间：$\text{Hash}(l, r) = (H[r] - H[l-1] \times P[r - l + 1]) \pmod M$

*(在做模运算减法时，可能出现负数，因此在 C++/Java 等语言中提取时需写成 `(H[r] - H[l-1] * P[len] % M + M) % M`，而在 Python 中 `%` 运算符对负数会自动规范为正数)*。

#### 2. 哈希碰撞与生日悖论
取模操作将原本无限的数值空间映射到了有限的 $[0, M-1]$ 集合中。根据鸽巢原理，**必然存在不同字符串算出相同哈希值的情况（哈希碰撞）**。

* **为什么 $M = 10^9+7$ 在大量查询下不够安全？**  
  根据**生日悖论**，在一个大小为 $M$ 的集合中随机选取约 $\sqrt{M}$ 个元素，就会有 50% 以上的概率产生至少一对冲突。
  对于 $M \approx 10^9$，阈值 $\sqrt{10^9} \approx 3.16 \times 10^4$。当字符串查询数量达到数十万次（如本题的 $Q = 200,000$）时，单纯的单哈希有极大概率产生误判（WA）。

#### 3. 工业与竞赛级防护方案
1. **双哈希（Double Hash）**：  
   同时选取两套互不相同的质数对 $(B_1, M_1)$ 和 $(B_2, M_2)$（如 $M_1 = 10^9+7, M_2 = 10^9+9$）。只有当两个子串在两套系统下的哈希值都相等时才认定相等。  
   此时等效模数达到了 $M_1 \times M_2 \approx 10^{18}$，发生碰撞所需的元素量级上升至 $\sqrt{10^{18}} = 10^9$，在 $10^5 \sim 10^6$ 级别的查询下碰撞概率可以忽略不计。
2. **大素数单哈希（$M = 2^{61}-1$）**：  
   选取梅森素数 $M = 2^{61} - 1$，空间足够大且利用二进制位运算（移位与掩码）可以在 64 位整型下进行极速取模，也是一种单哈希的高效防碰撞解法。

### 原理精髓总览

| 模块 | 数学本质 | 计算机作用 |
| :--- | :--- | :--- |
| **字符转数字** | 离散符号映射 | 使文本具备算术性质 |
| **$B$ 进制多项式** | 进制数唯一表达 | 确保不同字符串数值不同 |
| **前缀数组差分** | $H[r] - H[l-1] \cdot B^L$ | 避开扫描，实现 $O(1)$ 截取任意子串 |
| **大质数取模** | 有限域 $\mathbb{Z}_M$ 约束 | 控制数字大小，常数级开销运算 |
| **双哈希机制** | 笛卡尔积复合验证 | 彻底规避生日悖论引发的哈希碰撞 |
