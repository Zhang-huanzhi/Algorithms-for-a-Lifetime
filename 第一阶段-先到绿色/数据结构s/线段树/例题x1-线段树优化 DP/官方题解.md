这份官方题解非常经典，它给出了**两种**解决该问题的方法：

1. **第一种（前半部分）**：通过观察状态性质，将 $O(N^3)$ 的朴素 DP 优化为可以用**线段树**维护的 $O(N \log N)$ 在线 DP。
2. **第二种（最后一段）**：通过更深一步的数学推导，将问题神奇地转化为了**最长递增子序列（LIS）**问题，同样是 $O(N \log N)$，但代码实现会极其简单。

下面我为您详细拆解这两个思路：

---

### 思路一：线段树优化的 DP ($O(N \log N)$)

#### 1. 状态定义与降维
首先，朴素的 DP 定义是 $d[i][p][q]$ 表示处理到第 $i$ 个数时，$x=p, y=q$ 时的最大得分 $c$。这显然会超时和超内存。

**关键性质**：
在完成第 $k$ 步操作后，$x$ 和 $y$ 中**必然有一个值等于前 $k$ 个数中的最大值**，即：
$$\max(x, y) = \max(P_1, P_2, \dots, P_k)$$

因为每次操作都会把其中一个变量更新为 $\max(\text{原值}, P_k)$，这保证了其中一个变量总是会一路上升并紧跟当前的最大值。

利用这个性质，我们不需要同时记录 $x$ 和 $y$。我们只需要记录**较小的那个变量**的值：
* 设 $d[i][p]$ 表示：处理完第 $i$ 个数后，$\min(x, y) = p$ 时，最大得分 $c$ 的值。（若该状态不可达，则为 $-\infty$）。
* 此时，较大的那个变量的值隐式地等于 $M_i = \max(P_1, \dots, P_i)$。

#### 2. 状态转移
设当前要处理第 $i$ 个数 $P_i$，处理前的最大值为 $M_{i-1} = \max(P_1, \dots, P_{i-1})$。分两种情况讨论：

##### ① 情况 1：$P_i < M_{i-1}$ （新加入的数小于当前最大值）
此时，最大值没有变，依然是 $M_{i-1}$。我们只能选择更新“较小的那个变量 $j$”：
* 如果我们更新 $j$（前提是 $j < P_i$），新值会变成 $\max(j, P_i) = P_i$。此时得分 $c$ 会加 $1$。
  我们可以从所有满足 $1 \le j < P_i$ 的状态转移过来，转移后的新位置是 $P_i$：
  $$d[i][P_i] = \max_{1 \le j < P_i} (d[i-1][j] + 1)$$
* 当然，我们也可以选择不增加 $c$（比如当 $j \ge P_i$ 时更新它，值仍为 $j$，或者更新大变量 $M_{i-1}$ 但因为 $M_{i-1} > P_i$ 所以值不变且 $c$ 不增加）。因此，对于 $p = P_i$，它也保留不进行该次有效更新的值 $d[i-1][P_i]$。
  综合起来，对于新状态 $p = P_i$：
  $$d[i][P_i] = \max \left( d[i-1][P_i], \ \max_{1 \le j < P_i} d[i-1][j] + 1 \right)$$
* 对于其他所有 $p \neq P_i$ 的位置，值保持不变：
  $$d[i][p] = d[i-1][p]$$

##### ② 情况 2：$P_i > M_{i-1}$ （新加入的数是新的全局最大值）
此时，不管我们更新 $x$ 还是 $y$，其中一个都会被迫变成新的最大值 $P_i$。
* 为了让以后更好转移，我们希望**较小的那个变量的值尽可能小**。
* 因此，我们总是选择去更新那个“原本较大的变量 $M_{i-1}$”，由于 $M_{i-1} < P_i$，这必定会让得分 $c$ 增加 $1$。而较小的那个变量的值 $p$ 则保持原样不变。
* 这意味着，所有的 DP 状态值都统一加 $1$：
  $$d[i][p] = d[i-1][p] + 1 \quad (\text{对于所有 } p)$$

#### 3. 如何用线段树实现
因为这些转移都是“单点更新”、“区间求最大值”和“全局加 $1$”，我们可以直接用一棵**线段树**（带懒标记 lazy tag，用于全局加 1）来维护 $d$ 数组：
* 遇到情况 ①：在线段树中查询区间 $[1, P_i-1]$ 的最大值，加 $1$ 后，与原位置 $P_i$ 的值取 $\max$，然后单点更新线段树中的 $P_i$ 位置。
* 遇到情况 ②：在线段树中进行全局区间加 $1$ 操作。

总时间复杂度为 $O(N \log N)$。

### 思路二：转化成 LIS（最长递增子序列）问题

题解最后一段给出了一个极其巧妙的简化。

#### 1. 拆分序列 $P$
我们可以把排列 $P$ 中的元素分成两类：
* **A 类（前缀最大值 / 破纪录的数）**：满足 $P_i > \max(P_1, \dots, P_{i-1})$ 的元素。
* **B 类（非前缀最大值）**：不满足上述条件的元素。我们将这些元素提出来，保持相对顺序，组成一个新的序列 $Q$。

#### 2. 核心结论
$$\text{最终的最大得分 } c = (\text{A 类元素的个数}) + (\text{序列 } Q \text{ 的最长递增子序列 LIS 的长度})$$

#### 3. 为什么这个结论成立？
* **对于 A 类元素**：正如前面“情况 2”所述，每当遇到一个 A 类元素（即创纪录的最大值），我们都可以选择更新当时的“较大变量”，使其变成新最大值。由于它比之前的最大值还要大，所以**必然能让 $c$ 增加 $1$**。因此，所有 A 类元素都能无条件贡献 $1$ 分。
* **对于 B 类元素（即序列 $Q$）**：它们比当前的全局最大值要小。如果想让某个 B 类元素 $P_i$ 贡献得分，我们就必须把系统里“较小的那个变量”（假设当时的值为 $y$）更新为 $P_i$。
  * 要想成功得分，必须满足 $y < P_i$。
  * 更新后，这个较小的变量的值就变成了 $P_i$。
  * 下一个能让我们得分的 B 类元素 $P_j$（$j > i$），它的值就必须大于当前较小变量的新值（即满足 $P_j > P_i$）。
  * 依此类推，能触发得分的 B 类元素必须满足：值一个比一个大。这正好对应了序列 $Q$ 中的一个**严格递增子序列**。

因此，最大得分就是 A 类元素带来的保底分数，加上在剩余元素 $Q$ 中能选出的最长递增子序列（LIS）的长度。

#### 4. 算法实现步骤
使用思路二，代码会非常好写：
1. 遍历一遍 $P$，记录当前的运行最大值。
2. 如果 $P_i > \text{max\_so\_far}$，则将 A 类计数加 $1$，并更新 $\text{max\_so\_far}$。
3. 否则，将 $P_i$ 放入数组 $Q$ 中。
4. 用二分法（例如 `bisect`）求出数组 $Q$ 的 LIS 长度。
5. 答案即为：$\text{A类计数} + \text{LIS}(Q)$。

该方法的时间复杂度同样是 $O(N \log N)$，但空间和代码常数极小，且无需实现复杂的线段树。
