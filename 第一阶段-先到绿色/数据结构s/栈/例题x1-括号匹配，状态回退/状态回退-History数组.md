### 一、 为什么要状态回退？

最根本的原因是：**题目中存在“删除末尾字符”的操作，而字符的删除会彻底改变括号序列的合法性。**

#### 1. 业务场景的客观需要
假设我们的字符串 $S$ 经历了以下变化：
1. 一开始 $S = $ `(()`。此时它是不合法的（多了一个左括号），系统应该输出 `No`。
2. 接着，执行操作 2（删除末尾字符）。$S$ 变成了 `()`。此时它变成了合法的，系统应该输出 `Yes`。

由此可见，每一次“删除”操作，我们都必须知道**删除后的新字符串是否合法**。

#### 2. 规避 TLE（运行超时）的性能需要
如果不做“状态回退”，我们唯一的办法就是：每次遇到删除操作，就把剩下的字符串**重新扫描一遍**。
* 假设字符串长度为 $10^5$，我们删除了最后一个字符。重新扫描需要运行 $10^5$ 次循环。
* 如果题目交替给“添加、删除、添加、删除”，我们每次都要重扫。在 $8 \times 10^5$ 的高数据量下，这种没有“记忆”的重复计算会产生巨大的计算量，导致程序严重超时。

**因此，为了能在 $O(1)$ 的极短时间内瞬间得知删除后的新状态，我们必须让状态具备“回退（撤销）”的能力。**

### 二、 如何实现状态回退？

History 数组，保存上一个状态的状态。

1. **这是个撤销问题吗？** （是的，有删除/回退操作）
    
2. **我的状态是什么？** （例如：是一个当前的得分 score）
    
3. **我应该存状态还是存增量？** （score 只是一个整数，极小，选择“策略 A：直接存状态”）
    
4. **我的账本怎么建？** （建一个 score_history = [0]）
    
5. **如何 Do 和 Undo？** （每加分就 append 新分数；撤销就 pop，然后让当前分数等于 score_history[-1]）


在这道题中，状态回退的实现并没有使用复杂的逆向推理，而是巧妙地利用了**“历史记录本（列表的顺序存储）”**和**“栈的 `pop()` 操作”**。

#### 1. 技术原理：用“列表”记录时间线
我们定义了两个列表 `arr`（当前高度）和 `brr`（最低高度）。
这两个列表**不仅仅记录了当前的数值，还记录了过去每一步的数值**。列表的下标就是“时间轴”。

* 初始状态（第 0 步）：
  `arr = [0]`
  `brr = [0]`

* 第 1 步，加入 `(`：
  `arr = [0, 1]`  （当前高度变成 1）
  `brr = [0, 0]`  （历史最低仍是 0）

* 第 2 步，加入 `(`：
  `arr = [0, 1, 2]`  （当前高度变成 2）
  `brr = [0, 0, 0]`

* 第 3 步，加入 `)`：
  `arr = [0, 1, 2, 1]`  （当前高度降为 1）
  `brr = [0, 0, 0, 0]`

#### 2. 回退操作：物理切断时间线
现在，我们执行**操作 2（删除最后一个字符 `)`）**。

在代码中，我们只做了两件事：
```python
arr.pop()
brr.pop()
```
`pop()` 函数会删除列表的最后一个元素。执行之后，列表变成了：
* `arr = [0, 1, 2]`
* `brr = [0, 0, 0]`

**奇迹发生了：**
当我们再次用 `arr[-1]` 和 `brr[-1]` 读取当前状态时，读到的是 `arr[-1] == 2`，`brr[-1] == 0`。
这**恰好就是第 2 步（还没加入 `)` 之前）的状态**！

#### 3. 核心总结
通过这种设计，我们**把“删除字符”物理上等价为了“删除历史记录的最后一页”**。

我们没有去费脑筋计算“删除了一个右括号后，高度该怎么变”；我们只是**把时间拨回了添加这个右括号之前的那一刻**。因为历史数据一直在列表里完好保存着，所以 `pop()` 掉最新的，露出来的自然就是上一步的正确状态。这就是最简单、最优雅的状态回退实现方式。
