版本一：
``` python
import sys


def main():
    
    n, m = map(int, sys.stdin.readline().strip().split())

    # 用一个集合记录已被占用的格子坐标 (r, c)
    occupied = set()

    ans = 0
    for _ in range(m):
        r, c = map(int, sys.stdin.readline().strip().split())

        # 定义当前尝试放置的 4 个格子坐标
        targets = [
            (r, c),
            (r + 1, c),
            (r, c + 1),
            (r + 1, c + 1)
        ]

        # 检查这 4 个格子中是否有任何一个已被占用
        can_place = True
        for pos in targets:
            if pos in occupied:
                can_place = False
                break

        # 如果都可以放置
        if can_place:
            ans += 1
            # 将这 4 个格子加入已被占用的集合中
            for pos in targets:
                occupied.add(pos)

    print(ans)


if __name__ == "__main__":
    main()
```

版本二：
``` python
import sys

def main():
    n, m = map(int, sys.stdin.readline().strip().split())

    # 仅存储已成功放置方块的左上角坐标 (r, c)
    placed_blocks = set()
    ans = 0

    for _ in range(m):
        r, c = map(int, sys.stdin.readline().strip().split())

        # 检查周围 3x3 区域的 9 个候选左上角坐标
        has_overlap = False
        for dr in [-1, 0, 1]:
            for dc in [-1, 0, 1]:
                nr = r + dr
                nc = c + dc
                # 如果这个相邻位置已经有方块的左上角，说明会发生重叠
                if (nr, nc) in placed_blocks:
                    has_overlap = True
                    break
            if has_overlap:
                break

        # 如果不重叠，说明可以放置
        if not has_overlap:
            ans += 1
            placed_blocks.add((r, c))

    print(ans)

if __name__ == "__main__":
    main()```

---


这两个版本的代码在**解决问题的切入点（抽象层级）、时空常数、以及代码的通用性**上存在着本质的区别。我们可以把它们分别称为 **“细粒度格子法”**（版本一）和 **“粗粒度对象法”**（版本二）。

以下是它们的核心不同点对比：

---

### 1. 数据的存储单位不同（空间占用的差异）

* **版本一（细粒度格子法）**：
  * **存储什么**：存储的是每一个**被占用的独立格子**的坐标。
  * **数据规模**：由于每个方块占 $4$ 个格子，如果成功放置了 $k$ 个方块，集合（`occupied`）里就会存入 $4k$ 个坐标元组。
  * **最大空间占用**：约 $4M$ 个元素。

* **版本二（粗粒度对象法）**：
  * **存储什么**：存储的是每一个**成功放置的方块本身**（仅用其左上角坐标代表）。
  * **数据规模**：如果成功放置了 $k$ 个方块，集合（`placed_blocks`）里就只存入 $k$ 个坐标元组。
  * **最大空间占用**：约 $M$ 个元素。
  * **优势**：版本二的空间占用只有版本一的 **$1/4$**。在内存限制更严格或者 $M$ 极大的情况下，版本二更为安全。

---

### 2. 冲突检测的逻辑不同

* **版本一（直接检测）**：
  * **逻辑**：非常直观。我要占 $(r, c)$ 等四个格子，那我就去查这四个格子是否有人占了。
  * **操作次数**：每次操作进行固定 $4$ 次 `in` 查询。如果能放，再进行 $4$ 次 `add` 插入。

* **版本二（间接/几何检测）**：
  * **逻辑**：利用了几何规律（切比雪夫距离）。我不查格子，我查“我的周围九宫格邻域内，有没有其他方块的左上角”。如果有，说明我们两个大方块在空间上重叠了。
  * **操作次数**：每次操作进行最多 $9$ 次 `in` 查询（由于遇到重叠会提前 `break`，平均查询次数通常少于 9 次）。如果能放，进行 $1$ 次 `add` 插入。

---

### 3. 代码的扩展性与应用场景不同

* **版本一（更通用，适合复杂形状）**：
  * **优点**：这种“记录每一个被占用格子”的思路**通用性极强**。如果题目里的方块不是 $2 \times 2$，而是 L 型、 $1 \times 3$ 的长条、或者是任意不规则形状，版本一只需要修改 `targets` 列表即可直接运行。
  * **缺点**：当方块体积变大（比如 $10 \times 10$）时，每次要存入和查询的格子数量会平方级增加。

* **版本二（更专精，针对特定形状的高效解）**：
  * **优点**：针对 $2 \times 2$ 这种对称且固定的形状，通过数学推导将图形相交问题简化为点距问题，省去了大量冗余坐标的存储，属于**特化的高效解法**。
  * **缺点**：如果方块形状改变（如长方形、不规则多边形），重叠的数学判定公式（如 $|r_1-r_2| \le 1$）就会失效，需要重新推导复杂的判定边界。

---

### 总结

* **版本一** 的思路是 **“从格子的微观视角出发”**，简单直观，容错率高，适合处理异形方块。
* **版本二** 的思路是 **“从物体的宏观几何关系出发”**，通过数学化简，只记录物体抽象后的质点，在内存占用和对象创建的开销上表现得更加优秀。
