import sys

def main():

    n, m = map(int, sys.stdin.readline().strip().split())

    arr = [ [0] * (n + 1) for _ in range(n + 1)]

    # 直接模拟吧,不过肯定会TLE， 这个N数据范围10**9
    # 不对呀，这n范围这么大，直接开两位数组，会直接MLE吧
    # 不管了，先试试暴力模拟
    ans = 0
    for _ in range(m):
        r, c = map(int, sys.stdin.readline().strip().split())

        state = True
        for i in range(r, r + 2):
            for j in range(c, c + 2):
                if arr[i][j] == 1:
                    state = False
                    break

        if state:
            ans += 1
            # 将原先的涂黑
            for i in range(r, r + 2):
                for j in range(c, c + 2):
                    arr[i][j] = 1

    print(ans)




if __name__ == "__main__":
    main()

在这道题的测试数据中，有的测试点 $N$ 比较小（如 $N \le 10^4$），有的中等（如 $N \approx 5 \times 10^4$），而有的非常大（如 $N = 10^9$）。

根据 $N$ 的大小，您的暴力代码会触发以下三种不同的运行状态，这也解释了为什么结果中**既有 AC，又有 MLE，还有大量的 RE**：

---

### 1. 为什么会有 AC（12个测试点）？
* **原因**：测试数据中包含一部分**小规模数据**（例如样例 1 的 $N=4$，以及一些隐藏的 $N$ 较小的测试点）。
* 对于这些测试点，二维数组 `arr` 实际占用的内存非常小（可能只有几百 KB 到几 MB），程序能够正常、快速地运行完毕并输出正确答案，因此拿到了 12 个 **AC**。

---

### 2. 为什么部分测试点是 MLE（3个测试点）？
* **原因**：这些测试点的 $N$ 处于**中等规模**（例如 $N$ 在几万左右）。
* 在这个规模下，Python **成功向操作系统申请到了内存**，程序开始正常向下执行。
* 但是，随着数组的创建和后续运行，程序实际占用的内存逐渐上升，最终**超过了题目设定的 1024 MiB 限制**。
* 评测系统的安全沙箱（Sandbox）在后台实时监控着内存占用，一旦发现该程序使用的内存超过了 1024 MiB，就会强制干预并杀掉进程，并明确地记录为 **MLE (Memory Limit Exceeded)**。

---

### 3. 为什么大部分超大测试点（包括样例 2）是 RE（21个测试点）？
* **原因**：这些测试点的 $N$ **极其庞大**（例如样例 2 的 $N = 10^9$）。
* 当程序执行到 `[ [0] * (n + 1) for _ in range(n + 1)]` 时，Python 解释器会计算出需要申请数千万 GB 的超大物理内存。
* **操作系统或 Python 解释器在第一关就拒绝了这一请求**，并直接在 Python 内部抛出了 **`MemoryError` 异常**（运行时异常）。
* 由于您的代码中没有使用 `try-except` 来捕获和处理这个 `MemoryError`，Python 解释器会直接**崩溃退出**，并返回一个非零的错误退出码。
* 对于评测系统而言，它还没来得及因为“内存超限（1024 MiB）”去主动杀死您的程序，您的程序就已经**因为内部异常自己崩溃了**。因此，评测系统只能将其判定为 **RE (Runtime Error)**。

---

### 总结

在评测系统中，**程序自己崩溃（抛出未捕获异常）** 和 **被评测系统因超限而强制杀死** 是两种不同的判定路径：
* **超大 $N$** $\to$ 内存申请大到荒谬 $\to$ Python 内部直接抛出 `MemoryError` 崩溃 $\to$ **判定为 RE**。
* **中等 $N$** $\to$ 成功创建数组 $\to$ 运行中内存缓慢超过 1024 MiB 限额 $\to$ 被系统强制掐死 $\to$ **判定为 MLE**。
