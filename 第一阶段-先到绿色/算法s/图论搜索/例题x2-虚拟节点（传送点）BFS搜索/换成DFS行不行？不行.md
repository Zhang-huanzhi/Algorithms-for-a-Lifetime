求最短路都是用BFS， BFS相比于DFS， 有一个很大的特点，就是能保证 第一次到达就是最短路， 而DFS不行，DFS非常容易绕路， 你自个脑子模拟下吧，单纯文本解释有点复杂。
其实就正确率来讲，DFS可以的，BFS一定也可以，但BFS可以的，DFS不一定行。
但有些题效率上来讲， DFS会好一点，因为DFS只会保存起点到当前节点的一条路径，而BFS是同时保留所有路径的，所以说BFS非常容易MLE。

实现起来很简单
``` python
while q:  
    x, y, step = q.popleft()
```

换成:
``` python
while q:  
    x, y, step = q.popleft()
```

**结论：不行。**

如果简单地把 `q.popleft()` 换成 `q.pop()`，代码会从 **BFS（广度优先搜索）** 变成 **DFS（深度优先搜索）**。这样做会导致两个致命问题：**答案错误（WA）** 和 **超时（TLE）**。

以下是具体原因分析：

---

### 原因一：DFS 不能保证“第一次到达就是最短路”

这是 BFS 和 DFS 最本质的区别：
* **BFS（队列 `popleft`）**：像水波一样向外扩散，第一波触碰到终点的一定是最短路径。
* **DFS（栈 `pop`）**：不撞南墙不回头。它会沿着一条路径一直走到底，直到走不通了才回溯。
  * 也就是说，DFS 第一次到达终点 $(H, W)$ 时的步数，**极大概率是一条绕了远路的极长路径**，而不是最短路径。

---

### 原因二：关键优化 `arr[curr] = []` 将彻底失效（导致 WA 或 TLE）

我们在上一轮讨论的黄金优化：
```python
arr[curr] = []  # 传送一次后立即清空
```
**这个优化的成立，100% 依赖于“第一次遇到该字母时，一定是最短路”这个前提。**

在 DFS 中：
1. 假设 DFS 沿着一条非常绕的路径，在第 $100$ 步时走到了字母 `a`。
2. 此时，代码执行 `arr['a'] = []`，把所有其他的 `a` 传送点清空了，并把它们标记为 $101$ 步。
3. 但实际上，可能起点 $(1,1)$ 的旁边（只需 $1$ 步）就有一个 `a`。最合理的路线本应该是：$1$ 步走到 `a` $\to$ 传送（共 $2$ 步）。
4. 可是，因为 DFS 先走了那条 $100$ 步的死胡同，并提前**清空**了 `arr['a']`，导致那条只需 $2$ 步的完美路线再也无法使用。
5. **结果**：程序算出来的答案会比正确答案大得多，导致 **WA（答案错误）**。

> **那如果不清空 `arr` 呢？**
> 如果在 DFS 中不清空 `arr`，由于 DFS 会尝试所有可能的路径（包括各种绕路），程序会在传送点之间无限循环、来回试探，导致 **TLE（超时）** 甚至栈溢出。

---

### 总结：如何选择 BFS 和 DFS？

* **求无权图的最短路 / 最小步数**：必须用 **BFS**。因为它的层序遍历特性保证了高效性和最先到达即最优。
* **求可行性 / 连通性 / 所有方案数 / 拓扑排序**：可以使用 **DFS**。因为此时我们不关心是不是最短路径，只关心“能不能到”或“一共有多少种走法”。
