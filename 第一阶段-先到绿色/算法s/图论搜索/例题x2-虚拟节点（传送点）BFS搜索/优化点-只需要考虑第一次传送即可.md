在 BFS 的过程中，假设我们访问了某个传送格子。如果与该传送格子写有相同字符的另一个传送格子之前已经被访问过，那么我们无需考虑从当前这个格子发起传送。

所以请在第一次传送后，清空此传送列表，以优化时间复杂度

# 这个代码为什么会TLE？
``` python
import sys  
from collections import defaultdict, deque  
  
  
def main():  
  
    h, w = map(int, sys.stdin.readline().strip().split())  
  
    grip = []  
    for _ in range(h):  
        grip.append(list(sys.stdin.readline().strip()))  
  
    # 建一个传送表,用字典吧  
    arr = defaultdict(list)  
    for i in range(h):  
        for j in range(w):  
            curr = grip[i][j]  
            if curr != '.' and curr != '#':  
                arr[curr].append((i, j))  
  
    # print(arr)  
  
    # BFS搜索  
    q = deque()  
    # 三元组，x坐标，y坐标，步数  
    q.append((0, 0, 0))  
    visited = [ [-1] * w for _ in range(h)]  
    visited[0][0] = 0  
    directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]  
  
    while q:  
        x, y, step = q.popleft()  
        if x == h - 1 and y == w - 1:  
            print(step)  
            break  
  
        # 操作一，走一个  
        for dx, dy in directions:  
            nx = x + dx  
            ny = y + dy  
            new_step = step + 1  
  
            if 0 <= nx < h and 0 <= ny < w:  
                if grip[nx][ny] != '#':  
                    if visited[nx][ny] == -1:  
                        visited[nx][ny] = new_step  
                        q.append((nx, ny, new_step))  
  
        # 操作二，传送  
        curr = grip[x][y]  
        if curr != '.':  
            for nx, ny in arr[curr]:  
                # print((nx, ny))  
                if visited[nx][ny] == -1:  
                    visited[nx][ny] = step + 1  
                    q.append((nx, ny, step + 1))  
              
    else:  
        print(-1)  
  
if __name__ == "__main__":  
    main()
```

---


### 为什么会 TLE？
在“操作二，传送”部分，当您走到一个传送字符（例如 `a`）时，会遍历 `arr['a']` 里的所有传送点并放入队列。
由于这些点被放入队列后，之后您还会从队列中取出这些点。当您再次取出另一个 `'a'` 点时，如果不清空 `arr['a']`，代码会**重新遍历一遍**所有 `'a'` 的位置。
如果图中有 $10,000$ 个 `'a'`，这会导致程序重复执行 $10,000 \times 10,000 = 10^8$ 次操作，从而直接超时。

### 解决方案
在遍历完 `arr[curr]` 后，将该字符对应的列表**清空**（即 `arr[curr] = []`）。因为所有的同名传送点在第一次遇到时就已经全部加入队列了，后续无需重复遍历。

同时，建议将 `curr != '.'` 细化为 `'a' <= curr <= 'z'`，确保只对英文字母进行传送。

### 修改后的代码

您只需要在传送逻辑结束后加上 `arr[curr] = []` 即可。修改后的循环部分如下：

```python
        # 操作二，传送
        curr = grip[x][y]
        if 'a' <= curr <= 'z':  # 确保是传送字母
            for nx, ny in arr[curr]:
                if visited[nx][ny] == -1:
                    visited[nx][ny] = step + 1
                    q.append((nx, ny, step + 1))
            arr[curr] = []  # 【关键：清空已使用的传送点，防止重复遍历导致 TLE】
```

### 官方题解翻译

> 如果迷宫的规模较小，可以通过简单的 BFS（广度优先搜索）来解决。然而，由于格子的数量为 $O(HW)$，且从每个格子出发的转移数（即当前格子通过 1 次行动可以到达的格子数）在结合了“步行”和“传送”后，最坏情况下可达到 $O(HW)$，这会导致总计算量达到 $O(H^2W^2)$。在当前题目的数据范围限制下，这种做法会超时（TLE）。
> 
> 在这里，我们注意到以下事实：
> 
> * **在 BFS 的过程中，假设我们访问了某个传送格子。如果与该传送格子写有相同字符的另一个传送格子之前已经被访问过，那么我们无需考虑从当前这个格子发起传送。**
> 
> 因为，相比于从“当前访问的格子”发起传送，从“之前已经访问过的、具有相同字符的格子”发起传送显然会更优（或至少一样优）。
> 
> 因此，**对应每种字符，我们只需要在“第一次访问到该字符的格子”时执行传送转移即可。** 这样一来，整体的计算量就变成了 $O(\sigma HW)$（其中 $\sigma$ 为字符种类的数量，即最多 $26$），这个复杂度足够快，可以顺利通过。

---

### 详细解析（为什么这个结论成立？）

为了更直观地理解，我们可以从以下三个方面来拆解官方题解：

#### 1. 为什么不优化会超时？（为什么是 $O(H^2W^2)$）
假设网格大小为 $1000 \times 1000$（格子总数 $N = 10^6$），且整张地图里几乎所有的格子都是字母 `a`。
如果你在 BFS 中，每走到一个 `a` 都要把地图上其他所有的 `a` 遍历一遍放进队列里，那么：
* 格子总数是 $O(HW)$。
* 每次传送要遍历的格子数也是 $O(HW)$。
* 总复杂度就会退化为 $O((HW)^2) = O(10^{12})$，这在 2 秒内是绝对无法运行完的。

#### 2. 核心贪心思想：为什么“只有第一次遇到该字母时传送”是最优的？
BFS 的本质是**按步数从小到大（层序）进行搜索**。
* 假设我们在第 $D$ 步时，**第一次**走到了某个带有字母 `a` 的格子。此时，我们通过传送，可以在第 $D+1$ 步到达地图上**所有**其他的 `a` 格子。
* 随后，在第 $D' \ge D$ 步时，我们又走到了另一个写着 `a` 的格子。如果我们此时再次发起传送，到达其他 `a` 格子的步数将是 $D'+1$ 步。
* 因为 $D' \ge D$，所以 $D'+1 \ge D+1$。这意味着，**第二次及以后发起传送所能到达的所有终点，其步数一定不会比第一次传送时更少。**

因此，后续遇到的相同传送点，**完全没有必要再次发起传送**。

#### 3. 优化后的复杂度
因为小写英文字母只有 $26$ 种，所以 $\sigma \le 26$。
* **步行转移**：每个格子只有上下左右 $4$ 个方向，总共最多转移 $4 \times HW$ 次。
* **传送转移**：每种字母的传送列表只会在“第一次遇到”时遍历一次。因为所有字母的格子总数加起来就是 $HW$，所以这部分总共也只会被遍历 $1$ 次，即 $O(HW)$。

最终的总时间复杂度为 $O(HW)$（常数最大为 $\sigma = 26$），对于 $10^6$ 大小的数据，运行时间一般在 0.1~0.2 秒左右，非常高效。这也是为什么在您上一轮修改的代码中，加上 `arr[curr] = []`（清空已使用的传送列表）之后，代码就能顺利通过的原因。
