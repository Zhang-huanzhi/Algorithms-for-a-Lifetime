### 1. 标准的“二维数组”写法（更容易看懂）

如果我们不进行任何空间优化，完全按照状态机的逻辑来写，代码应该是下面这样的。这里我们开辟了一个 $N \times 2$ 的二维数组：

* `dp[i][0]` 代表第 $i$ 天是雨天（R）
* `dp[i][1]` 代表第 $i$ 天是晴天（S）

```python
# 声明一个 N x 2 的二维数组
dp = [[0] * 2 for _ in range(n)]

# 1. 初始化第 1 天（i = 0）
if s[0] == "S":
    dp[0][0] = -xrr[0]  # 晴改雨
    dp[0][1] = 0  # 保持晴
else:
    dp[0][0] = 0  # 保持雨
    dp[0][1] = -xrr[0]  # 雨改晴

# 2. 状态转移
for i in range(1, n):
    if s[i] == "S":
        cost_r, cost_s = xrr[i], 0
    else:
        cost_r, cost_s = 0, xrr[i]

    # 今天是雨(0)，由昨天是雨(0)或昨天是晴(1)转移来
    dp[i][0] = max(dp[i - 1][0], dp[i - 1][1]) - cost_r

    # 今天是晴(1)，由昨天是雨(0，带奖励)或昨天是晴(1)转移来
    dp[i][1] = max(dp[i - 1][0] + yrr[i - 1], dp[i - 1][1]) - cost_s

# 3. 最终答案
print(max(dp[n - 1][0], dp[n - 1][1]))
```

在这个标准版本中，`dp[i][j]` 是一个货真价实的**二维数组**。

---

### 2. 为什么能优化成“两个单变量”？

请仔细观察上面的状态转移方程：

$$\text{dp}[i][0] = \max(\text{dp}[i-1][0], \text{dp}[i-1][1]) - \text{cost\_r}$$

你会发现：**我们在计算第 $i$ 天的数据时，只用到了第 $i-1$ 天的数据。**
至于第 $i-2$ 天、第 $i-3$ 天……甚至更早的数据，在计算完之后，就**再也用不到了**。

既然旧数据用不到了，我们为什么还要在内存里保留一个长度为 $200,000$ 的庞大表格呢？

我们只需要两个变量：
* 用 `dp0` 代替 `dp[i-1][0]`（昨天的雨天状态）
* 用 `dp1` 代替 `dp[i-1][1]`（昨天的晴天状态）

每次计算出新一天的 `new_dp0` 和 `new_dp1` 后，直接覆盖掉旧的 `dp0` 和 `dp1` 即可。

---

### 总结

您觉得它是一维的，是因为**代码在物理存储上被压缩了**。

但在**逻辑结构上**，它依然是二维的：
* **第一维**：天数 $i$（通过循环的轮次隐式表达了）。
* **第二维**：天气的状态 $0$ 和 $1$（通过 `dp0` 和 `dp1` 两个独立的变量表达了）。

在写 DP 题时，通常建议**先写出带二维数组的直观版本**。等调试通过后，如果发现空间开销太大，再把它压缩成几个滚动变量。您能一眼看出代码里没有二维数组，说明您已经对代码的物理结构非常敏感了！
