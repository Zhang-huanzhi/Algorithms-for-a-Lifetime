初始化为 `0` 其实在动态规划中**非常常见**，但具体初始化为什么值，**完全取决于你求解的 DP 问题类型**。

为了方便记忆，我们可以把 DP 问题的初始化总结为以下几个“黄金法则”：

---

### 1. 求最小值问题（Min DP）
*   **规则**：**绝对不能初始化为 `0`**。
*   **原因**：如果你把未达到的状态初始化为 `0`，那么在执行 `min(0, 某个正数)` 时，结果永远会是 `0`。这会导致真正有用的答案无法更新上去。
*   **正确做法**：初始化为**正无穷大**（如 Python 中的 `float('inf')` 或 C++ 中的 `0x3f3f3f3f`）。

---

### 2. 求方案数/路径数问题（Counting DP）
*   **规则**：**必须初始化为 `0`**。
*   **原因**：因为在游戏刚开始时，到达任何未知地点的方案数自然是 `0` 种。只有起点会被手动初始化为 `1`。
*   **正确做法**：全部初始化为 `0`，起点设为 `1`。

---

### 3. 求最大值问题（Max DP）
这里要分两种情况：

*   **情况 A：所有数据都是正数，且没有严格的步骤/路线限制**
    *   **做法**：可以直接初始化为 `0`。因为不可能存在比 `0` 更小的解。

*   **情况 B：数据中存在负数，或者像本题一样，有严格的“非空/先后顺序”限制**
    *   **做法**：必须初始化为**负无穷大**（`-float('inf')`）。
    *   **原因**：
        1. 如果有负数，最终答案可能是 `-5`。如果用 `0` 初始化，`max(0, -5)` 就会选 `0`，从而得出错误答案。
        2. 如果有路线限制，初始化为 `0` 会让算法误以为“这里有一条得分为 0 的合法路径”，从而允许算法偷懒。

---

### 一个核心的思维转变：区分“数值 0”与“状态不存在”

写 DP 代码时，最重要的一点是问自己：
> **“这个格子现在进不去，是因为得分为 0，还是因为根本无法到达？”**

*   如果只是**目前得分为 0**：初始化为 `0`。
*   如果是**根本无法到达（非法状态）**：
    *   在求最大值时，设为 $-\infty$。
    *   在求最小值时，设为 $+\infty$。

在实际竞赛和面试中，很多程序员为了保险起见，**只要是求最值（Max/Min）问题，都会习惯性地初始化为负无穷/正无穷**。这是一种非常安全且不易出错的好习惯。
