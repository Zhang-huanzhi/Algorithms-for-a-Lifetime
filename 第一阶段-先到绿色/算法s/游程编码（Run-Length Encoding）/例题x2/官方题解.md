这份官方题解的核心思路是：**通过寻找 1122 字符串的“分界线”来高效统计数量**。

下面为您详细拆解题解的内容。

---

### 核心思路：寻找分界线

对于任意一个 1122 字符串，它一定可以被分成左右两部分（例如 `111222` 可以分成左边的 `111` 和右边的 `222`）。这两部分之间有一个明确的“分界线”（从 `1` 变为 `2` 的地方）。

我们可以遍历原字符串 $S$ 中所有相邻的两个字符 $S_i$ 和 $S_{i+1}$（这里设下标从 1 开始），将它们作为分界线的候选位置：

1. **必要条件**：要让这个位置能作为 1122 字符串的分界线，必须满足 $S_i + 1 = S_{i+1}$（即右边的数字比左边刚好大 1）。如果不满足，这个位置就无法形成 1122 字符串。
2. **计算贡献**：如果满足上述条件，我们分别向左和向右数：
   * 向左看：与 $S_i$ 相同的连续字符有多少个（记为 $c_1$）。
   * 向右看：与 $S_{i+1}$ 相同的连续字符有多少个（记为 $c_2$）。
   * **该分界线能形成的 1122 字符串数量就是 $\min(c_1, c_2)$**。

#### 例子解析：$S = 11223$
* **位置 1**（$S_1=1, S_2=1$）：不满足 $S_1 + 1 = S_2$，贡献为 $0$。
* **位置 2**（$S_2=1, S_3=2$）：满足 $1 + 1 = 2$。
  * 向左看：`1` 连续出现了 2 次（$c_1 = 2$）。
  * 向右看：`2` 连续出现了 2 次（$c_2 = 2$）。
  * 贡献为 $\min(2, 2) = 2$（对应的子串是 `12` 和 `1122`）。
* **位置 3**（$S_3=2, S_4=2$）：不满足 $S_3 + 1 = S_4$，贡献为 $0$。
* **位置 4**（$S_4=2, S_5=3$）：满足 $2 + 1 = 3$。
  * 向左看：`2` 连续出现了 2 次（$c_1 = 2$）。
  * 向右看：`3` 连续出现了 1 次（$c_2 = 1$）。
  * 贡献为 $\min(2, 1) = 1$（对应的子串是 `23`）。

总答案为 $2 + 1 = 3$。

基于这个核心思路，题解给出了两种具体的实现方法。

---

### 解法 1：游程编码（Run-Length Compression）

**游程编码（RLE）**是一种将连续相同字符压缩为 `(字符, 出现次数)` 的方法。
例如，字符串 `11223` 压缩后得到：`[('1', 2), ('2', 2), ('3', 1)]`。

#### 算法步骤：
1. 对字符串 $S$ 进行游程编码。
2. 遍历压缩后的相邻两项 $a[i]$ 和 $a[i+1]$。
3. 如果满足 $int(a[i][0]) + 1 == int(a[i+1][0])$（即前一个字符加 1 等于后一个字符），则将 $\min(a[i][1], a[i+1][1])$ 累加到答案中。

#### 代码 1 解析（Python）：
```python
from itertools import groupby

s = input()
# groupby 可以自动将相邻的相同字符分在一组
# a 存储的是 (字符, 出现次数) 的列表
a = [(v, len(list(x))) for v, x in groupby(s)]

ans = 0
# 遍历相邻的两个压缩块
for i in range(len(a) - 1):
    # 如果前一个字符代表的数字加 1 等于后一个字符
    if int(a[i][0]) + 1 == int(a[i+1][0]):
        # 累加较小的那个出现次数
        ans += min(a[i][1], a[i+1][1])
print(ans)
```
* **时间复杂度**：$O(N)$。因为分组和遍历只需扫描一次字符串。

### 解法 2：直接双指针扩展（愚直に求める）

如果我们不进行预压缩，也可以直接用双指针在原字符串上向两边扩展。

#### 算法步骤：
1. 遍历每个位置 $i$（从 $0$ 到 $N-2$）。
2. 如果发现 $S_i + 1 == S_{i+1}$：
   * 用指针 $j$ 从 $i$ 开始往左走，直到遇到不同的字符。此时向左连续的相同字符个数为 $i - j$。
   * 用指针 $k$ 从 $i+1$ 开始往右走，直到遇到不同的字符。此时向右连续的相同字符个数为 $k - i - 1$。
   * 将 $\min(i - j, k - i - 1)$ 累加到答案中。

#### 代码 2 解析（Python）：
```python
s = input()
n = len(s)
ans = 0

for i in range(n - 1):
    # 只有当相邻字符满足 +1 关系时才开始向两边扩展
    if int(s[i]) + 1 != int(s[i+1]):
        continue
    
    # 往左扩展，数左边有多少个连续的 s[i]
    j = i
    while j != -1 and s[j] == s[i]:
        j -= 1
        
    # 往右扩展，数右边有多少个连续的 s[i+1]
    k = i + 1
    while k != n and s[k] == s[i+1]:
        k += 1
        
    # 累加两边连续长度的较小值
    ans += min(i - j, k - i - 1)

print(ans)
```

#### 为什么这个解法的时间复杂度也是 $O(N)$，而不是 $O(N^2)$？
虽然代码里有嵌套的 `while` 循环，但请注意：
* `while` 循环只有在 $S_i + 1 == S_{i+1}$（字符发生变化且递增）时才会触发。
* 每个字符最多只会被左向扩展扫过一次，被右向扩展扫过一次。它们不会被重复扫描。
* 因此，所有 `while` 循环的执行次数总和也是 $O(N)$ 级别的，整体运行非常快。
