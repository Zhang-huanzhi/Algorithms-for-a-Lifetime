结论先行：**这道题不能使用纯粹的 `offset`（全局偏移量）。**

可以说，**只要题目出现了“带有条件限制的全局修改”（比如：只对 $\ge 1$ 的数减 1、只对偶数加 1、或者 $\max(A_i - 1, 0)$），`offset` 技巧就会立刻失效。**

下面为你深度剖析**为什么条件限制是 `offset` 的死穴**，以及如果强行用 `offset` 会发生什么。

---

### 一、 `offset` 的适用本质是什么？

`offset` 能够生效的唯一前提是：**所有元素“步调一致”**。

* **能用 `offset` 的场景**：
  “把数组里的**所有**元素都减 1”。
  * 逻辑：原本 $A = [2, 5, 0]$，`offset += 1` 后，逻辑上的 $A$ 变成了 $[1, 4, -1]$。所有元素**相对差值不变**，只需要 $O(1)$ 改变 `offset` 即可。

* **不能用 `offset` 的场景（本题）**：
  “把数组里**大于等于 1 的**元素减 1”。
  * 初始 $A = [2, 5, 0]$。
  * 按照规则，减 1 后应该变成 $[1, 4, 0]$。
  * 但如果你直接 `offset += 1`，逻辑上的 $A$ 会变成 $[1, 4, -1]$。原本是 $0$ 的那个元素**被错误地一起扣掉了 1**！

---

### 二、 如果我硬要用 `offset` 修复它，会发生什么？

你可能会想：“那我能不能在 `offset += 1` 之后，**把那些本来是 0 的元素再补加 1** 恢复回来呢？”

我们来看如果强行修复，算法会变成什么样：

1. 执行操作 2 时，全局 `offset += 1`。
2. 找到所有原来是 $0$ 的元素（现在变成了 $-1$），给它们的真实值 $+1$，把它们拉回 $0$。

**这样修看似可行，但复杂度直接炸裂：**
* 初始时，数组里有 **$N$ 个 $0$**。
* 如果连续来 $Q$ 次操作 2，每一次你都要把这 $N$ 个 $0$ 找出来补偿 $+1$。
* 时间复杂度会变成 $O(N \times Q)$，彻底 **TLE（超时）**。

#### 相比之下，官方题解为什么快？
* **强行用 offset**：去补偿那些 **$0$**。但 $0$ 的数量最多有 **$N$ 个**（极大）。
* **官方题解**：去修改那些 **$\ge 1$ 的数**。由于初始全是 0，$\ge 1$ 的数**全靠操作 1 产生**，数量最多只有 **$Q$ 个**（极小）。

这就是为什么官方题解去维护“非零元素”可以做到均摊 $O(Q)$，而 `offset` 去维护“零元素”会导致 $O(N \times Q)$。

---

### 三、 避坑指南：什么时候能用 `offset`？

在算法竞赛中，你可以用以下规则快速判断能不能用 `offset`：

| 题目操作描述 | 能否用 `offset`？ | 原因 / 替代方案 |
| :--- | :--- | :--- |
| **“所有元素加/减 $x$”** | **✅ 能** | 所有数步调一致，直接 $O(1)$ 改 `offset` |
| **“所有元素乘 $x$”** | **✅ 能** | 可以用全局乘法标记 `scale` |
| **“若 $A_i \ge 1$ 则减 1”** | **❌ 不能** | **零值下界限制**打破了相对差值 |
| **“$A_i = \max(A_i - 1, 0)$”** | **❌ 不能** | 同样是零值下界截断，破坏了线性关系 |
| **“区间 $[L, R]$ 元素加 $x$”** | **❌ 不能（纯 offset）** | 需要改用 **差分数组** 或 **线段树 Lazy 标记** |

### 总结

**只要题目要求“只有满足某些条件的数才变，其他数不变”，全局 `offset` 就失效了。** 

遇到这种“只有大于 0 的数才扣减”的题目，标准的正确姿势就是：**用列表/集合维护所有非零元素的下标，只对有效元素做操作**。
