能想到 `for` 循环累加是非常正常且直观的，因为这正是题目字面意思的直接翻译。大部分人在拿到这道题时，第一步写出来的也都是 `for` 循环。

从“`for` 循环累加”跨越到这个 $O(1)$ 的公式，其实并不是凭空想象的，而是通过以下两种非常经典的**思维路径**推导出来的。

---

### 思路一：滑动窗口直觉法（最直观的物理模型）

我们可以把求和的过程想象成一个**“滑动的窗口”**：

假设 $K = 3$，我们要计算 $A_i$。
* $A_{i-1}$ 的值，是它前面 3 项的和：
  $$\text{旧窗口 } [A_{i-4}, A_{i-3}, A_{i-2}] \implies A_{i-1} = A_{i-4} + A_{i-3} + A_{i-2}$$
* 现在窗口向右移动一格，要计算 $A_i$。$A_i$ 是当前前面 3 项的和：
  $$\text{新窗口 } [A_{i-3}, A_{i-2}, A_{i-1}] \implies A_i = A_{i-3} + A_{i-2} + A_{i-1}$$

对比新旧两个窗口，你会发现它们高度重叠：
1. 窗口向右移动时，**滑入**了新成员：$A_{i-1}$
2. 窗口向右移动时，**滑出**了老成员：$A_{i-4}$（即 $A_{i-K-1}$）

所以，**新窗口的和 = 旧窗口的和 + 滑入的元素 - 滑出的元素**：
$$A_i = A_{i-1} + A_{i-1} - A_{i-K-1}$$
合并同类项，就得到了：
$$A_i = 2A_{i-1} - A_{i-K-1}$$

---

### 思路二：相邻项代数作差法（最严谨的数学推导）

如果你喜欢用公式推导，可以把相邻的两项公式写在纸上对比：

第一步，写出 $A_i$ 的展开式：
$$A_i = \color{blue}{A_{i-1}} + \color{red}{A_{i-2} + A_{i-3} + \dots + A_{i-K}}$$  —— (等式 1)

第二步，写出前一项 $A_{i-1}$ 的展开式：
$$A_{i-1} = \color{red}{A_{i-2} + A_{i-3} + \dots + A_{i-K}} + A_{i-K-1}$$  —— (等式 2)

第三步，观察红色标记的重叠部分：
我们把等式 2 变形，把红色重叠部分孤立出来：
$$\color{red}{A_{i-2} + A_{i-3} + \dots + A_{i-K}} = A_{i-1} - A_{i-K-1}$$

第四步，把这个红色部分代入等式 1 中：
$$A_i = \color{blue}{A_{i-1}} + (A_{i-1} - A_{i-K-1})$$
$$A_i = 2A_{i-1} - A_{i-K-1}$$

---

### 💡 总结：以后如何自己想到？

只要在算法题中看到**“前一个状态和后一个状态，计算的数据范围只有微小的边界变化”**，就可以立刻联想到这套方法：

1. **写出前后两项的完整公式**。
2. **观察它们重叠的部分**。
3. **用“新加入的”和“滑出的”来代替重叠的计算**。

这样，原本需要遍历计算的 $O(K)$ 复杂度，就变成了只需要加减一次的 $O(1)$ 复杂度。
