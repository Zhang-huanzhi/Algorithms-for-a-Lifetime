**“原地修改”（In-place Modification）** 是算法题中一种非常经典且实用的编程技巧。

简单来说，它的核心思想是：**不再额外开辟新的数组或数据结构，而是直接在输入给我们的数据（原数组）上进行修改、标记或状态转换，用来存储中间计算结果或历史状态。**

下面以本题为切入点，并扩展到算法面试/竞赛中常见的几种“原地修改”套路，为你彻底讲透这个技巧。

---

### 一、 在本题中，“原地修改”妙在哪里？

#### 1. 常规思路 vs 原地修改对比

* **常规思路（增加辅助数组）：**
  开一个 `bool` 数组 `eaten[N]` 记录哪天吃了。
  ```python
  # 移出窗口时需要做 if 分支判断
  if i >= M:
      if eaten[i - M]:
          window_sum -= A[i - M]
  ```
* **原地修改思路（本题解法）：**
  没吃就直接把原数组的值改成 `0`：`A[i] = 0`。
  ```python
  # 移出窗口时无需任何 if 判断，直接减！
  if i >= M:
      window_sum -= A[i - M]
  ```

#### 2. 它带来的三大优势：
1. **语义的自然转换（核心思想）**：
   * 原数组 $A[i]$ 一开始的含义是 **“当天提供的点心卡路里”**；
   * 一旦第 $i$ 天过去，我们其实**不再关心原本提供了多少**，我们只关心 **“高桥君实际摄入了多少”**。
   * 因此，把 $A[i]$ 修改为 $0$，是将它的语义变成了“当天实际摄入量”。
2. **消除了分支判断（代码极其清爽）**：
   * 如果不吃记为 $0$，那么滑出窗口时减去 $0$，数学上等于“什么都没减”，完全不会破坏窗口和。这消除了 `if eaten[...]` 的分支判断，逻辑变成了纯粹的算术运算。
3. **空间复杂度降至 $O(1)$**：
   * 省去了额外维护 `eaten` 布尔列表的内存开销。

### 二、 算法题中“原地修改”的常见经典套路

在算法题（尤其是 LeetCode、Codeforces、AtCoder）中，原地修改技巧经常被用来实现 **$O(1)$ 辅助空间复杂度**。以下是 4 个最常见的模式：

#### 套路 1：语义覆盖 / 标记为无效值（本题所用）
* **原理**：用一个不可能出现的值（如 $0$、$-1$、`None`）覆盖原数据，表示该位置已被处理、被删除或状态为假。
* **经典例题**：
  * **26. 删除有序数组中的重复项**：利用双指针，直接把不重复的元素覆盖到原数组的前部。

---

#### 套路 2：正负号标记法（极高频）
* **场景**：数组长度为 $N$，里面的数字范围在 $[1, N]$ 之间，想要在 $O(1)$ 空间内标记“某个数字是否出现过”。
* **原理**：如果数字 $x$ 出现过，我们把索引为 $x-1$ 的位置上的数**变成负数**（`A[x-1] = -abs(A[x-1])`）。
  * 符号（正/负）：代表该下标对应的数字是否出现过（负代表出现过）；
  * 绝对值（`abs(A[i])`）：依然保留了该位置原本的数值，不破坏原本的信息！
* **经典例题**：
  * **448. 找到所有数组中消失的数字**
  * **442. 数组中重复的数据**

---

#### 套路 3：位运算编码（同时保存过去和现在的状态）
* **场景**：网格或数组在某一轮更新中，新状态依赖旧状态，但又不能开新矩阵（需要同步更新）。
* **原理**：计算机中的 `int` 是由二进制位组成的（比如 32 位）。我们可以用**最低位（第0位）存旧状态，第1位存新状态**。
  * 例如：`00` 表示 过去死，现在死；`10` 表示 过去死，现在活；`01` 表示 过去活，现在死；`11` 表示 过去活，现在活。
  * 全部算完后，统一将所有数右移一位（`val >> 1`），就完成了状态更新。
* **经典例题**：
  * **289. 生命游戏 (Game of Life)**

---

#### 套路 4：除法与取模编码（一格存两个数）
* **场景**：同样是不开新数组，想要在位置 $i$ 同时保存 $old\_val$ 和 $new\_val$。
* **原理**：利用数学公式：$\text{编码值} = new\_val \times MOD + old\_val$（其中 $MOD$ 大于数组中任何可能的最大值）。
  * 取旧值时用：$\text{编码值} \pmod{MOD}$
  * 取新值时用：$\lfloor \text{编码值} / MOD \rfloor$

---

### 三、 使用“原地修改”的避坑指南

原地修改虽然精妙，但在使用时必须注意以下两点：

1. **原数据后续是否还会用到？**
   * 如果修改了某个位置的值，而后续的算法步骤还需要读取该位置的原有数据，就会引发 Bug（这时就要考虑“正负号标记”或“位运算编码”这种保留原信息的方式，或者只能乖乖开新数组）。
2. **实际工程 vs 算法竞赛**：
   * **算法竞赛 / 刷题中**：为了追求极致的时间和空间效率，原地修改是被极度推崇的。
   * **日常工程代码中**：除非内存极其受限，通常尽量避免直接篡改入参（遵循纯函数/不可变数据原则），以免对调用方产生意料之外的副作用。
