## 前言

在 Python 中设置递归深度非常简单，只需要使用内置的 `sys` 模块。

对于要稳定通过 AtCoder D 题的选手来说，这几乎是写 DFS 时的**"标配"动作**。

---

## 1. 设置方法

在代码的最顶端（通常在 import 之后）加入以下两行：

python

```python
import sys

# 将递归深度设置为 100 万（或者根据需要设置）
sys.setrecursionlimit(1000000)
```

---

## 2. 为什么要设置？（默认值是多少？）

- **默认值**：Python 的默认递归深度通常只有 **1000**。
- **D 题的规模**：AtCoder ABC-D 题的数据范围通常是 `N = 2×10⁵`。如果你写一个 DFS 去遍历一个长链状的图，递归深度会达到 20 万。
- **后果**：如果你不设置，程序会在达到第 1000 层时报错：`RecursionError: maximum recursion depth exceeded`。在比赛中，你会看到一个无情的 **RE (Runtime Error)**。

---

## 3. 设置多少比较合适？

在算法竞赛中，通常推荐设置为：

- **10⁶ (一百万)**：这是最常用的，足以应付绝大多数 `10⁵` 级别的数据。
- **2×10⁵ + 100**：如果你想更精准一点，根据题目 `N` 的范围来定。

**代码示例：**

python

```python
import sys

# 假设题目 N = 200,000
sys.setrecursionlimit(200000)  # 建议比 N 稍微大一点，给系统留点余量
```

---

## 4. 三个重要的注意事项

### (1) 递归深度的副作用：内存

递归深度本质上是在申请**系统栈（System Stack）**的空间。每一层递归都会占用一定的内存。如果递归太深（比如设到了 `10⁸`），虽然不会报错，但可能会导致 **MLE (Memory Limit Exceeded)**。

不过在 AtCoder 1024MB 内存的环境下，设置为 `10⁶` 是非常安全的。

### (2) PyPy 3 的特殊性

在 AtCoder 上，很多人喜欢用 PyPy 3 提交，因为它运行速度快。

- PyPy 3 同样需要 `sys.setrecursionlimit`。
- 但要注意，PyPy 的递归开销比 CPython 大，如果递归深度真的达到几十万，PyPy 有时会比 CPython 更容易爆栈。

### (3) 终极方案：手动模拟栈

如果你发现设置了递归深度依然 RE，或者题目对内存限制极严，最稳妥的方法是**弃用递归**，自己写一个 `list` 当作栈，用 `while` 循环来写 DFS：

```python
# 手动栈 DFS 示意（不会有递归深度限制问题）
stack = [start_node]
while stack:
    curr = stack.pop()
    for neighbor in adj[curr]:
        if not visited[neighbor]:
            visited[neighbor] = True
            stack.append(neighbor)
```

## 总结

**"写 DFS，先设 Limit"** 应该成为你的肌肉记忆。

在你的笔记里可以记下这一条：

**AtCoder 避坑指南：** 只要代码里出现了 `def dfs()` 并且有递归调用，第一行必须写 `sys.setrecursionlimit(1000000)`，否则 `N > 1000` 时必崩。
