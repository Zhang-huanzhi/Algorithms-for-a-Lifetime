很多同学在面对双指针时都会有同样的困惑：**“看题解时觉得很简单，自己写时不知道怎么起步，还总是写出死循环或边界错误（Off-by-one error）。”**

其实，掌握双指针的关键在于**识别特征信号**和**套用固定的高品质模板**。下面为你整理一套非常实用、不易出错的判定方法和代码模板。

---

### 一、 什么时候该用双指针？（三大特征信号）

当你拿到一道题，如果题目中出现以下三个信号之一，就可以优先考虑双指针：

#### 1. 单调性（最核心的信号）
* **特征**：数组是有序的（或可以排序），或者某种物理量具有单调性（比如：区间越长，区间和必然越大；区间越短，不同的字符数必然越少）。
* **思考**：如果我固定左端点，右端点向右移动时，状态是不是单向变化的？如果是，必用双指针。

#### 2. 关键词是“子数组”或“连续子区间”
* **特征**：题目要求寻找“满足条件的**最长/最短子数组**”或“满足条件的**子区间个数**”。
* **注意**：必须是**连续**的。如果是子序列（不连续），一般不用双指针（可能用动态规划）。

#### 3. 尝试降低维度（从 $O(N^2)$ 降到 $O(N)$）
* **特征**：你很容易写出一个两层 `for` 循环的暴力解法，但发现**内层循环的指针不需要每次都回到起点**，而是可以继承上一次的位置。

---

### 二、 同向双指针（尺取法 / 滑动窗口）的两套黄金模板

同向双指针主要有两种写起来最舒服、最不容易写错边界的模板。

#### 模板 A：固定左指针 $L$，主动扩展右指针 $R$（最推荐，本题使用的就是这套）
这套模板最适合用于：**求以 $L$ 为起点的最长合法区间，或者计数类问题。**

```python
r = 0 # 右指针初始化在起点
ans = 0

for l in range(n):  # 左指针一步步往右走
    # 只要满足条件，右指针就一直往右扩展
    while r < n and check_valid(l, r):
        # 1. 在这里更新窗口内的状态（如果需要）
        r += 1
        
    # 此时，[l, r-1] 是以 l 为起点的最大合法区间！
    # 2. 在这里更新你的答案
    # 比如：本题中贡献的对子数是 r - l
    ans += (r - l)
    
    # 3. 在 l 即将向右移动前，把 l 的影响从状态中移除（如果需要）
    # (例如：current_sum -= arr[l])
```
* **核心优势**：循环结束后，`r` 所在的位置就是第一个**不满足**条件的位置，因此合法区间长度就是 $r - l$，边界极其清晰，绝不会多加或少加。

---

#### 模板 B：固定右指针 $R$，被动收缩左指针 $L$
这套模板最适合用于：**寻找满足某种条件的最短/最长子数组。**

```python
l = 0  # 左指针初始化
ans = 0 # 或者是 float('inf') 视求最大还是最小而定

for r in range(n):  # 右指针主动往右扫
    # 1. 把当前 r 对应的元素纳入窗口状态中
    # update_state(arr[r])
    
    # 2. 当窗口内的状态不符合要求（或者符合要求需要收缩）时
    while check_invalid():
        # 3. 将 l 的影响从窗口状态中移除
        # remove_state(arr[l])
        l += 1  # 左指针向右收缩
        
    # 此时 [l, r] 是一个确定的合法窗口
    # 4. 在这里更新你的答案
    # ans = max(ans, r - l + 1)  # 如果求最长
    # ans = min(ans, r - l + 1)  # 如果求最短
```

### 三、 对撞双指针（头尾双指针）模板

对撞双指针通常用于：**排序数组的二数之和、回文判定等。** 它的模板相对最简单：

```python
l = 0
r = n - 1

while l < r:
    current_val = arr[l] + arr[r]
    
    if current_val == target:
        # 找到了答案
        return (l, r)
    elif current_val < target:
        l += 1  # 和太小了，左指针右移以增大和
    else:
        r -= 1  # 和太大了，右指针左移以减小和
```

### 四、 避坑口诀与建议

1. **“右指针不回头”**：写完代码后检查一下，你的 `r` 变量有没有在循环里被重置（比如出现 `r = l` 这种语句）。如果有，说明写错了，双指针退化成了 $O(N^2)$ 暴力。
2. **“先定一个，再动另一个”**：不要让两个指针在各自的循环里同时乱动。永远推荐用 `for` 循环固定其中一个（比如左指针），然后在里面用 `while` 移动另一个（右指针）。
3. **“草稿纸画图”**：写边界时，在草稿纸上画 3 个元素 $[A, B, C]$，手动模拟一下第二步和第三步，看看指针会不会越界，基本上就能保证 100% 一次性写对。
