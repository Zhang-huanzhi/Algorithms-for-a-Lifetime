双指针版本省了数组空间，但边界更容易写错。对于比赛来说，位置数组版本更容易证明正确。

---
``` python
import sys  
  
def main():  
    input = sys.stdin.readline  
  
    N, A, B = map(int, input().split())  
    S = input().strip()  
  
    a_pos = []  
    b_pos = []  
  
    for i, ch in enumerate(S, start=1):  
        if ch == 'a':  
            a_pos.append(i)  
        else:  
            b_pos.append(i)  
  
    ans = 0  
    before_a = 0  
    before_b = 0  
  
    for l in range(1, N + 1):  
        ai = before_a + A - 1  
  
        if ai >= len(a_pos):  
            break  
  
        left_r = a_pos[ai]  
  
        bi = before_b + B - 1  
  
        if bi >= len(b_pos):  
            right_r = N  
        else:  
            right_r = b_pos[bi] - 1  
  
        if right_r >= left_r:  
            ans += right_r - left_r + 1  
  
        if S[l - 1] == 'a':  
            before_a += 1  
        else:  
            before_b += 1  
  
    print(ans)  
  
if __name__ == "__main__":  
    main()
```


这段代码是一个**非常优雅、巧妙且高效的 $O(N)$ 解法**。

它同样利用了“固定左端点，寻找合法右端点区间 $[left\_r, right\_r]$”的思想，但它**没有使用复杂的指针移动（`while` 循环）**，而是通过**预处理字符位置 + $O(1)$ 数组查表**的方式，极大地简化了代码逻辑。

以下是对这段代码的详细拆解和分析：

---

### 一、 核心设计思想：位置预处理

普通双/三指针需要在循环中不断用 `while` 往右探路。而这段代码采用了一种“空间换时间”的聪明做法：
* **预处理**：在开始循环前，先用两个列表 `a_pos` 和 `b_pos` 记录字符 `'a'` 和 `'b'` 在字符串中出现的所有 **1-based 索引位置**。
* **查表**：由于记录了位置，对于任何一个左端点 $l$，我们不需要一步步向右数 `'a'` 和 `'b'` 的个数，而是可以直接通过**查表**，在 $O(1)$ 的时间内计算出 $r$ 的范围。

---

### 二、 代码逐段解析

#### 1. 预处理位置
```python
a_pos = []
b_pos = []

for i, ch in enumerate(S, start=1):
    if ch == 'a':
        a_pos.append(i)
    else:
        b_pos.append(i)
```
* 如果 $S = \text{"abba"}$，那么 `a_pos = [1, 4]`，`b_pos = [2, 3]`。
* 这让我们能够通过下标直接知道“第 $k$ 个 `'a'` 在哪里”。

#### 2. 初始化状态变量
```python
ans = 0
before_a = 0
before_b = 0
```
* `before_a` 和 `before_b` 分别表示**当前左端点 $l$ 左侧（不包含 $l$）**已经出现了多少个 `'a'` 和 `'b'`。
* 随着 $l$ 逐渐向右移动，这两个计数器会对应增加。

#### 3. 寻找最小合法右边界 `left_r`（满足 `'a' \ge A`）
```python
ai = before_a + A - 1

if ai >= len(a_pos):
    break

left_r = a_pos[ai]
```
* 因为在 $l$ 之前已经有了 `before_a` 个 `'a'`，那么在 $l$ 之后（包含 $l$）的第 $A$ 个 `'a'`，实际上就是整条字符串中的第 `(before_a + A)` 个 `'a'`。
* 对应在 `a_pos` 列表（0-indexed）中的下标就是 `ai = before_a + A - 1`。
* `left_r = a_pos[ai]` 就是第 $A$ 个 `'a'` 的具体位置。这就是合法的**最小右边界**。
* **极佳的优化点**：如果 `ai >= len(a_pos)`，说明整个字符串剩下的 `'a'` 已经不够 $A$ 个了。因为随着 $l$ 右移，后面的 `'a'` 只会更少，所以这里可以直接 `break` 结束整个程序，非常高效。

#### 4. 寻找最大合法右边界 `right_r`（满足 `'b' < B`）
```python
bi = before_b + B - 1

if bi >= len(b_pos):
    right_r = N
else:
    right_r = b_pos[bi] - 1
```
* 我们要求 `'b'` 的个数严格小于 $B$，这意味着子串**不能包含自 $l$ 起的第 $B$ 个 `'b'`**。
* 在 $l$ 之前已经有了 `before_b` 个 `'b'`，因此自 $l$ 起的第 $B$ 个 `'b'`，就是整条字符串中的第 `before_b + B` 个 `'b'`，对应在 `b_pos` 中的下标为 `bi = before_b + B - 1`。
* 如果这个 `'b'` 存在，那么最大合法的右边界就是这个 `'b'` 的位置减 1，即 `right_r = b_pos[bi] - 1`。
* 如果 `bi >= len(b_pos)`，说明从 $l$ 开始到字符串末尾，整个区间的 `'b'` 数量本来就不足 $B$ 个。此时我们可以把右边界一直延伸到字符串末尾，即 `right_r = N`。

#### 5. 统计答案与状态转移
```python
if right_r >= left_r:
    ans += right_r - left_r + 1

if S[l - 1] == 'a':
    before_a += 1
else:
    before_b += 1
```
* 如果最大合法右边界 `right_r` 大于等于最小合法右边界 `left_r`，说明区间 $[left\_r, right\_r]$ 存在，合法的子串数量为 `right_r - left_r + 1`。
* 在 $l$ 循环结束、即将变为 $l+1$ 之前，我们要把当前的字符 `S[l - 1]` 归入“左侧已出现字符”，更新 `before_a` 或 `before_b` 的值。

---

### 三、 总结：为什么这个解法极好？

1. **逻辑极其清晰**：
   相比传统的双指针维护（需要写好几个复杂的 `while` 条件，容易出现“差一错误” / Off-by-one error），这个解法利用数学下标映射，把查找边界的过程变成了纯粹的 **$O(1)$ 数组查表**。
2. **效率极高**：
   * **时间复杂度 $O(N)$**：只需遍历一次字符串预处理，之后主循环中无嵌套循环，单次循环仅有常数次查表操作。加上 `break` 的提前剪枝，运行速度非常快。
   * **空间复杂度 $O(N)$**：额外使用了两个存储位置的列表，空间开销完全在可接受范围内。
