这道题用**双指针（Two Pointers）**解法是最优雅、效率最高的。下面我们从**数学本质、核心逻辑到具体步骤**，详细拆解双指针的解题思路。

---

### 一、核心洞察：为什么能用双指针？

很多同学一开始会觉得：*“高桥君在数轴上左右横跳，剩下的饼干越来越散，每次不是都得在所有剩余饼干里找最近的吗？”*

其实不然。请看数轴的一个关键性质：
1. **已捡区域是连续向外扩散的**：
   高桥君从 $0$ 出发，每次都贪心地选最近的。这就保证了——**在任何时刻，所有已被捡起的饼干一定紧密包围在原点 $0$ 的左右两侧**。
2. **候选目标永远只有 2 个**：
   * 左边未捡的饼干里，**只有最靠近当前位置的那一个（也就是剩余负数里最大的那个）** 才有可能是最近的，更左边的必然更远。
   * 右边未捡的饼干里，**只有最靠近当前位置的那一个（也就是剩余正数里最小的那个）** 才有可能是最近的，更右边的必然更远。

> **结论**：虽然总共有 $N$ 块饼干，但在任意时刻，高桥君只需要在 **“左边下一个”** 和 **“右边下一个”** 之间做**二选一**。这天然契合**双指针**模型！

---

### 二、算法具体设计

#### 1. 数据拆分与预排序
我们将所有饼干按正负拆分成两个序列，并按**离原点 $0$ 由近及远**排序：
* **负数列表 `neg`**（降序排列）：例如原始负数是 `[-11, -1, -4]` $\to$ 排序为 `[-1, -4, -11]`
  * 用左指针 `i` 指向下一个待捡的负数（从下标 `0` 开始）。
* **正数列表 `pos`**（升序排列）：例如原始正数是 `[5, 2]` $\to$ 排序为 `[2, 5]`
  * 用右指针 `j` 指向下一个待捡的正数（从下标 `0` 开始）。

#### 2. 双指针贪心决策（循环 $N$ 次）
维护高桥君当前所在的真实坐标 `curr`（初始为 `0`）和总路程 `ans`：

每一轮决策时，取出两个候选饼干：
* 左候选：$L = \text{neg}[i]$，到它的距离为 $d_L = |\text{curr} - L|$
* 右候选：$R = \text{pos}[j]$，到它的距离为 $d_R = |\text{curr} - R|$

**决策规则**：
* 如果某一边已经没有饼干了（指针越界），则别无选择，直接走另一边。
* 如果两边都有饼干：
  * 若 $d_L \le d_R$：去捡左边的 $L$，路程累加 $d_L$，更新当前位置 `curr = L`，左指针 `i++`。（**注意**：题意规定距离相同时选坐标更小的，即选负数，因此取 $\le$）
  * 若 $d_L > d_R$：去捡右边的 $R$，路程累加 $d_R$，更新当前位置 `curr = R`，右指针 `j++`。

### 三、图解样例演练

以样例 1 为例：`A = [-1, -4, 2, -11]`
* 拆分排序后：
  * `neg = [-1, -4, -11]` （`i` 指向 `-1`）
  * `pos = [2]` （`j` 指向 `2`）
* 初始状态：`curr = 0`, `ans = 0`

| 步骤 | 当前位置 `curr` | 左候选 `neg[i]` 及距离 | 右候选 `pos[j]` 及距离 | 比较与决策 | 新位置 `curr` | 累加距离 `ans` |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **第 1 步** | $0$ | `-1` ($d_L = 1$) | `2` ($d_R = 2$) | $1 < 2 \to$ **选左** (`i++`) | $-1$ | $0 + 1 = \mathbf{1}$ |
| **第 2 步** | $-1$ | `-4` ($d_L = 3$) | `2` ($d_R = 3$) | $3 = 3 \to$ **选左** (`i++`)<br>*(平局优先选更小的)* | $-4$ | $1 + 3 = \mathbf{4}$ |
| **第 3 步** | $-4$ | `-11` ($d_L = 7$) | `2` ($d_R = 6$) | $7 > 6 \to$ **选右** (`j++`) | $2$ | $4 + 6 = \mathbf{10}$ |
| **第 4 步** | $2$ | `-11` ($d_L = 13$) | 无（`pos`已空） | 只剩左边 $\to$ **选左** (`i++`) | $-11$ | $10 + 13 = \mathbf{23}$ |

最终输出 **`23`**。

### 四、复杂度与优势总结

1. **时间复杂度：$O(N \log N)$**
   * 排序两个列表耗时 $O(N \log N)$。
   * 双指针推进过程每个元素仅访问一次，耗时 $O(N)$。
   * 整体为极其轻量的 $O(N \log N)$。

2. **空间复杂度：$O(N)$**
   * 仅需两个扁平列表存储正负坐标。

3. **与平衡树 / `SortedList` 解法对比**：
   * `SortedList` 每次查找和删除需要 $O(\log N)$ 的树结构调整，总共需要 $N$ 次树操作。
   * 双指针法把 $O(\log N)$ 的开销**一次性压缩在开头的排序中**，后面的模拟完全是纯线性 $O(1)$ 指针移动，**常数极小，执行速度通常比平衡树快 4~5 倍**。


``` python
import sys

def main():
    # 快速一次性读取全部输入
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    n = int(input_data[0])
    arr = list(map(int, input_data[1:]))

    # neg: 负数按从大到小排（离 0 近的在前，如 -1, -4, -11）
    # pos: 正数按从小到大排（离 0 近的在前，如 2, 5, 8）
    neg = sorted([x for x in arr if x < 0], reverse=True)
    pos = sorted([x for x in arr if x > 0])

    x, y = 0, 0          # 负数和正数列表的指针
    len_neg = len(neg)
    len_pos = len(pos)
    
    curr = 0             # 当前实际坐标，从 0 开始
    ans = 0              # 总移动距离

    # 循环 n 次，每次捡起一个饼干
    for _ in range(n):
        # 计算到左边（负数）和右边（正数）的真实距离，越界则设为无穷大
        d_left = abs(curr - neg[x]) if x < len_neg else float('inf')
        d_right = abs(curr - pos[y]) if y < len_pos else float('inf')

        # 选距离近的；相等时优先选坐标更小的负数 (<=)
        if d_left <= d_right:
            ans += d_left
            curr = neg[x]
            x += 1
        else:
            ans += d_right
            curr = pos[y]
            y += 1

    print(ans)

if __name__ == "__main__":
    main()
```
