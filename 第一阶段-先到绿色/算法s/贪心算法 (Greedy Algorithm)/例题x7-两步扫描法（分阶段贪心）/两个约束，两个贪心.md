### 一、 核心逻辑：从“最难的约束”开始破局

这道题有两个约束：
1. **数量约束**：必须选 $K$ 个。
2. **颜色约束**：必须包含**至少** $M$ 种不同的颜色。

您的核心逻辑是：**“先用最划算的方式强行满足最难的‘颜色约束’，然后再用无约束的纯暴力贪心去填满‘数量约束’。”**

---

### 二、 您的代码思路逐步拆解

#### 第一步：奠定贪心基石（排序）
```python
arr.sort(key = lambda x:(-x[1], x[0]))
```
* **思路**：将所有宝石按价值从大到小（降序）排序。
* **逻辑**：排序后，只要我们从左往右看，**一旦某个颜色第一次出现，它就一定是该颜色中价值最高的那颗宝石**（我们称之为该颜色的“天花板宝石”）。

#### 第二步：第一阶段——强行满足“颜色约束”（Stage 1）
```python
for i in range(n):
    ...
    if cnt == m:
        break
    if c not in temp:
        cnt += 1
        temp.add(c)
        visited[i] = True
        ans += value
```
* **思路**：我们要凑齐 $M$ 种颜色。既然要凑，当然要选每一选定颜色中最好的那颗。
* **逻辑**：
  1. 通过从左往右遍历，利用 `c not in temp`，我们拿到了前 $M$ 个**首次出现**的不同颜色的宝石。
  2. 因为数组是降序的，这 $M$ 个宝石实际上就是：**所有颜色中，“天花板”最高的前 $M$ 个颜色的天花板宝石**。
  3. 选完这 $M$ 个宝石后，我们的“颜色约束”已经 **100% 提前宣告满足**（我们已经有了 $M$ 种不同的颜色）。
  4. 用 `visited[i] = True` 标记它们，防止第二阶段重复选择。

#### 第三步：第二阶段——无约束最大化价值（Stage 2）
```python
cnt = 0
for i in range(n):
    if cnt == k - m:
        break
    if not visited[i]:
        ans += arr[i][1]
        cnt += 1
```
* **思路**：现在我们手里有 $M$ 个宝石，且颜色各不相同。我们还需要 $K - M$ 个宝石。
* **逻辑**：
  1. 既然颜色约束已经满足了，接下来的 $K - M$ 个位置放什么颜色都无所谓了（甚至重复也无所谓）。
  2. 为了让总和最大，我们只需要**在剩下所有没被选过的宝石中，挑价值最大的前 $K - M$ 个**。
  3. 因为数组已经是降序的，所以我们再次从头（`i = 0`）开始扫描，只要遇到 `not visited[i]` 的宝石就直接收下，直到收满 $K - M$ 个。

---

### 三、 为什么这个逻辑在数学上一定是正确的？

您可能会想：*万一我不选前 $M$ 个最大的颜色，而是选第 $M+1$ 大的颜色，会不会在第二阶段反而能凑出更大的总和？*

答案是：**绝对不会。**

* **证明**：
  假设我们用某个较小的颜色 $X$ 替代了我们选中的某个大颜色 $Y$。
  1. 在第一阶段，我们被迫选了 $X$ 的天花板宝石（价值较小），失去了 $Y$ 的天花板宝石（价值较大），这造成了**价值亏损**。
  2. 虽然在第二阶段我们可以自由选择，但由于 $Y$ 的天花板宝石已经被释放到了未选池中，我们最多也只能在第二阶段把它选回来。
  3. 无论怎么组合，替换成较小颜色 $X$ 带来的收益，绝对无法弥补失去大颜色 $Y$ 带来的亏损。

因此，**先强行锁定前 $M$ 个价值最大的颜色代表，再用剩余的最大值补齐**，在数学上被证明是无可挑剔的全局最优解。您的代码用最少的行数和最直观的双重扫描，完美地践行了这一数学真理。
