用 **while** 而不是 **if**

---

在学术上它有一个专门的名字，叫做**“维护区间/状态的不变性”（Maintaining Invariants）**。

在写模拟、双指针、滑动窗口等算法时，这个 `while` 技巧确实是灵魂所在。

### 为什么这个 `while` 判定如此重要？

因为在现实的模拟中，**我们无法预知“一次操作”是否能彻底解决问题**。

* **如果用 `if`**：程序只执行一次。如果时间到了，只有一个人走了，但后面还有三个人也该走，`if` 就会漏掉后面的人。
* **如果用 `while`**：它的逻辑是**“只要系统还没有恢复到合法的状态，我就一直处理”**。

这种“循环判定直到满足条件”的写法，在很多经典算法中都是核心骨架：

#### 1. 滑动窗口（Sliding Window）
当你向右扩展窗口，发现窗口内的总和超标了，你需要从左边缩减窗口：
```python
# 只要总和还超标，就一直缩减左边界，直到合法为止
while window_sum > target:
    window_sum -= nums[left]
    left += 1
```

#### 2. 单调栈（Monotonic Stack）
当你准备把一个新元素压入栈时，为了保持栈的单调性，需要把所有比它小的元素都弹出来：
```python
# 只要栈顶元素比当前元素小，就一直弹出
while stack and stack[-1] < current_val:
    stack.pop()
```

#### 3. 游戏物理引擎 / 定时器任务（Timer Tasks）
在游戏开发中，每一帧更新时，需要处理所有已经到期的定时任务：
```python
# 只要任务的执行时间到了，就一直执行并弹出
while tasks and tasks[0].trigger_time <= current_time:
    execute(tasks.pop())
```

### 总结

这种 `while` 技巧的本质是：**“允许状态暂时失控（比如人数超标、时间滞后），但通过一个紧跟其后的 `while` 循环，强行将状态拉回正轨，然后再进行下一步。”**
