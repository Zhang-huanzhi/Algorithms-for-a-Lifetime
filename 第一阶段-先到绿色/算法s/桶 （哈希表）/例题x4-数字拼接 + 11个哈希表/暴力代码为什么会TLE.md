``` python
import itertools
import sys
from itertools import product, repeat


def main():
    
    n, m = map(int, sys.stdin.readline().strip().split())

    arr = list(map(int, sys.stdin.readline().strip().split()))

    # 尝试暴力
    cnt = 0
    for comb in itertools.product(range(n), repeat=2):

        x1, x2 = comb

        y = int(str(arr[x1]) + str(arr[x2]))

        if y % m == 0:
            cnt += 1

    print(cnt)

if __name__ == "__main__":
    main()
```


---

你写的这段暴力代码是一个非常典型的 **“TLE（超时）教科书案例”**。

在算法竞赛中，这段代码超时主要由两个致命原因共同导致：**极高的算法复杂度** 和 **极重的垃圾回收（GC）负担**。

我们用具体的数据来算一笔账，看看它为什么一定会超时。

---

### 原因 1：可怕的 $O(N^2)$ 循环次数（根本原因）

题目给出的数据范围是：$N \le 2 \times 10^5$。

你的代码使用了 `itertools.product(range(n), repeat=2)`，这会生成所有可能的下标配对。其总循环次数为：
$$\text{循环次数} = N^2 = (2 \times 10^5)^2 = 40,000,000,000 \text{ 次}（400 亿次）$$

**在 Python 中：**
通常单秒能执行的简单操作次数在 $10^7$（1000 万次）左右。
* 即使你的循环体里**什么都不写（空循环）**：
  $$4 \times 10^{10} \div 10^7 = 4000 \text{ 秒} \approx 1.1 \text{ 小时}$$
* 光是跑完这个空循环，就需要一个多小时，而题目限时只有 **2 秒**。

---

### 原因 2：循环体内的“重型操作”（雪上加霜）

你的循环体内不仅不是空循环，反而塞满了 Python 中**最慢的几种操作**：

```python
x1, x2 = comb  # 1. 元组解包（有开销）
y = int(str(arr[x1]) + str(arr[x2]))  # 2. 两次 str() + 一次拼接 + 一次 int()
if y % m == 0:  # 3. 大数取模
```

让我们看看每运行一次循环，Python 在底层要默默做什么：
1. **创建和销毁临时对象：** 
   每一次 `str()` 转换、每一次字符串 `+` 拼接、每一次 `int()` 转换，Python 都要在内存中申请新空间创建新对象。
   在 400 亿次循环中，你的代码会产生 **超过 1200 亿个临时垃圾对象**！
2. **触发垃圾回收（GC）：**
   内存中瞬间堆满了几千亿个没用的字符串，Python 的垃圾回收机制（Garbage Collector）会被疯狂触发，试图去清理内存。这会占用大量的 CPU 时间，甚至直接导致程序卡死。

---

### 对比：为什么优化后的代码能过？

你之前写的优化代码，时间复杂度是 $O(10N)$。

* **循环次数：** 
  $$10 \times N = 10 \times (2 \times 10^5) = 2,000,000 \text{ 次}（200 万次）$$
* **底层开销：**
  只有简单的整数乘法 `p * 10 % m` 和哈希表查询 `cnt[k][key]`。
  没有任何字符串转换，没有新对象创建，没有任何内存垃圾。

**结果对比：**
* 暴力代码：需运算 **400 亿次**，且每次都是重型操作 $\implies$ **耗时 11 小时以上（TLE）**
* 优化代码：需运算 **200 万次**，且每次都是极轻的数学运算 $\implies$ **耗时 0.1 秒（AC）**

通过写出这段暴力代码并与之对比，你能更深刻地体会到**算法优化（将 $O(N^2)$ 降到 $O(N)$）**在面对大数据量时的巨大威力。
