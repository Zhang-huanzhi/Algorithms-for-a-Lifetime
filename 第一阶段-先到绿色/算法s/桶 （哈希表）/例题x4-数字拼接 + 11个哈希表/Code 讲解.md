``` python
import itertools  
import sys  
from collections import Counter  
  
  
def main():  
      
    n, m = map(int, sys.stdin.readline().strip().split())  
  
    arr = list(map(int, sys.stdin.readline().strip().split()))  
  
    cnt = [ Counter() for _ in range(11)]  
  
    # 预处理，这道题不要求 i < j    for x in arr:  
        k = len(str(x))  
        cnt[k][x % m] += 1  
  
    ans = 0  
  
    # 算特征值  
    for x in arr:  
        p = 10  
        for k in range(1, 11):  
  
            key = (-(x * p)) % m  
            ans += cnt[k][key]  
  
            p = (p * 10) % m  
  
    print(ans)  
  
if __name__ == "__main__":  
    main()
```

这三个问题都问到了最核心的**数学原理**和**计算机性能优化**。

我们一个一个来彻底搞懂它们：

---

### 问题 1：`cnt[k][x % m] += 1` 为什么这里需要取模？

**一句话回答：如果不取模，你就无法利用哈希表“一次性”查出所有符合条件的数。**

#### 详细解释：
我们最终要判断的条件是：两个数拼接后，**模 $M$ 的余数是否为 0**。
这属于**同余问题**。在模 $M$ 的世界里，数字 $4$ 和数字 $15$（假设 $M=11$）是**完全等价**的，因为：
* $4 \bmod 11 = 4$
* $15 \bmod 11 = 4$

假设在某一步，我们需要一个 $A_j$，满足 $A_j \bmod 11 = 4$。
* 如果你在哈希表里存的是**原数**：你存了 `4` 和 `15`。
* 当你查询“余数为 4”的数时，你必须去搜 `4`、`15`、`26`、`37`……直到无穷大。这在计算机里是**无法实现**的。

**取模的妙处：**
如果你在存入哈希表时就对 $M$ 取模，那么 `4` 和 `15` 都会变成 `4`。它们都会被放进 `cnt[k][4]` 这个格子里。
当你需要“模 $M$ 余 4”的数时，你只需要一步查询 `cnt[k][4]`，就能知道有多少个数字符合要求（比如这里是 2 个）。

### 问题 2：为什么特征值是这样写的：`key = (-(x * p)) % m`？

这是由**移项公式**严格推导出来的。

#### 详细数学推导：
我们希望：
$$(10^k \cdot A_i + A_j) \equiv 0 \pmod M$$

把含有 $A_j$ 的项留在左边，其他移到右边（这在同余方程中完全适用）：
$$A_j \equiv - (10^k \cdot A_i) \pmod M$$

在你的代码中：
* `x` 就是 $A_i$
* `p` 就是 $10^k$
* 所以 $10^k \cdot A_i$ 就是 `x * p`。

带入公式，我们需要的 $A_j \bmod M$（即 `key`）必须等于：
$$\text{key} = (- (x \cdot p)) \bmod M$$

#### 举个例子：
假设 $M = 11$，我们算出来 $10^k \cdot A_i = 10$。
我们需要找一个 $A_j$，使得 $(10 + A_j) \bmod 11 = 0$。很明显，我们需要 $A_j \bmod 11 = 1$。

用我们的公式计算：
$$\text{key} = (-10) \bmod 11 = 1$$
*(注：在 Python 中，`(-10) % 11` 的结果就是 `1`)*。
公式计算出的结果与实际完全相符！如果不加负号，你算出来的 `key` 就是 `10`，那就错了（$10 + 10 = 20$，不是 11 的倍数）。

### 问题 3：为什么 $p$ 也需要取模？`p = (p * 10) % m`

**两个原因：数学正确性 + 防止大数运算变慢。**

#### 1. 数学正确性（同余性质）
在模运算中，有一个非常重要的性质：
$$(A \times B) \bmod M = ((A \bmod M) \times (B \bmod M)) \bmod M$$

也就是说，我们在算 $(A_i \times 10^k) \bmod M$ 时，并不需要真的用很大的 $10^k$ 去乘。我们可以让 $10^k$ 每次乘 10 的时候都取模，结果是完全一样的。
例如，算 $10^2 \bmod 7$：
* 方法 A（不取模）：$100 \bmod 7 = 2$
* 方法 B（每次取模）：$10 \bmod 7 = 3 \implies (3 \times 10) \bmod 7 = 30 \bmod 7 = 2$
两种方法结果完全相同。

#### 2. 防止大数运算变慢（性能优化）
在 Python 中，整数虽然可以无限大，但是**大整数的乘法和取模非常慢**。
如果 $M$ 很大，而我们不给 `p` 取模，`p` 就会变成 $10, 100, 1000 \dots 10^{10}$。
如果这道题的位数不是 10 位，而是 10 万位，不取模的话，`p` 会变成一个有 10 万位的超级怪物，电脑会直接卡死。
而每次都 `% m`，可以保证 `p` 的大小永远**不会超过 $M$**（最大也就是 $10^9$ 左右），计算机做这种小整数乘法的速度是极快的。
