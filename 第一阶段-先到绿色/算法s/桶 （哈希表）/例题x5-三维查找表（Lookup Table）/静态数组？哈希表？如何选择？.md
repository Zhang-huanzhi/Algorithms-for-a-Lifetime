# Code 哈希 查找表
``` python
import sys  
from collections import defaultdict  
from operator import index  
  
  
def main():  
  
    n = int(sys.stdin.readline().strip())  
  
    arr = []  
    for _ in range(n):  
        a, b = map(int, sys.stdin.readline().strip().split())  
        arr.append((a, b))  
  
    m = int(sys.stdin.readline().strip())  
  
    brr = []  
    # 三维布尔数组  
    memo = set()  
    for _ in range(m):  
        s = list(sys.stdin.readline().strip())  
        brr.append(s)  
        s_len = len(s)  
  
        for i in range(s_len):  
            memo.add((s_len, i + 1, s[i]))  
  
  
    # 检验  
    out = []  
    for xrr in brr:  
  
        if len(xrr) != n:  
           out.append("No")  
           continue  
  
  
        for  idx, comb in enumerate(arr):  
            a, b = comb  
            target_char = xrr[idx]  
            if (a, b, target_char) not in memo:  
                out.append("No")  
                break  
  
        else:  
            out.append("Yes")  
  
    print("\n".join(out))  
  
if __name__ == "__main__":  
    main()
```

# Code 静态数组 查找表

``` python
import sys
from collections import defaultdict
from operator import index


def main():

    n = int(sys.stdin.readline().strip())

    arr = []
    for _ in range(n):
        a, b = map(int, sys.stdin.readline().strip().split())
        arr.append((a, b))

    m = int(sys.stdin.readline().strip())

    brr = []
    # 三维布尔数组
    memo = [ [ [False] * 27 for _ in range(11)] for _ in range(11)]
    for _ in range(m):
        s = list(sys.stdin.readline().strip())
        brr.append(s)
        s_len = len(s)

        for i in range(s_len):
            memo[s_len][i + 1][ord(s[i]) - ord('a')] = True


    # 检验
    out = []
    for xrr in brr:

        if len(xrr) != n:
           out.append("No")
           continue

        index = 0
        for  a, b in arr:
            target_char = ord(xrr[index]) - ord('a')
            if not memo[a][b][target_char]:
                out.append("No")
                break
            index += 1
        else:
            out.append("Yes")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```

这两份代码代表了在算法设计中处理“查找表”时，两种最经典的实现方式。

以下是这两份代码的对比分析，以及在实际开发或算法竞赛中如何选择这两种结构的系统指南。

---

### 一、 两份代码的对比分析

| 维度 | Code 1：哈希查找表 (`set`) | Code 2：静态数组查找表 (`list`) |
| :--- | :--- | :--- |
| **底层数据结构** | 哈希表（CPython 底层的哈希哈希表） | 连续物理内存块（C 语言层面的连续指针数组） |
| **空间复杂度** | $O(M \cdot N_{max})$ （仅存储实际出现的元素，最大为 $3146$ 个） | $O(L_{max} \cdot P_{max} \cdot \sigma)$ （固定大小，这里是 $11 \times 11 \times 27 = 3267$ 个布尔值） |
| **实际内存占用** | 稍微多一点（每个哈希节点都有指针、哈希值等额外开销） | 极少（只存了数千个 `False` / `True`） |
| **时间复杂度（理论）**| 平均 $O(1)$ 的插入与查询 | 严格的 $O(1)$ 寻址 |
| **时间常数（实际速度）**| **较慢**。每次查询都需要创建临时元组 `(a, b, target_char)`，计算哈希值。 | **极快**。直接通过下标进行偏移量计算，没有任何对象创建和哈希计算的开销。 |
| **代码编写体验** | 极佳。无需进行 `ord(s[i]) - ord('a')` 这样的字符索引转换，可直接存取。 | 需要小心处理边界（防止越界）以及字符到数字的转换。 |

---

### 二、 查找表的设计选择：静态数组 VS 哈希表

在面临“设计一个查找表”的需求时，您可以根据以下三个核心维度来进行选择：

#### 1. 状态空间的大小（最关键的决定因素）
* **当状态空间小且密集时 $\rightarrow$ 选择【静态数组】**
  * **定义**：如果所有维度的最大值相乘，总体积在 $10^7$ 以内（在 Python 中建议 $10^6$ 以内），且大部分位置都可能被填满。
  * **原因**：可以直接开辟空间。
* **当状态空间大且稀疏时 $\rightarrow$ 选择【哈希表】**
  * **定义**：虽然某些维度范围很大（例如位置可能到 $10^9$），但实际出现的不同状态非常少（例如只有 $10^5$ 个状态）。
  * **原因**：如果用数组会发生内存超限（MLE）。哈希表“按需分配”内存，只存储实际存在的数据。

#### 2. 对运行时间（常数）的要求
* **时间限制非常紧 $\rightarrow$ 选择【静态数组】**
  * 数组的 $O(1)$ 是**硬件级**的（直接通过内存地址偏移公式 $Address + i \times size$ 定位）。
  * 在 Python 中，如果循环次数达到 $10^6$ 以上，哈希表（`set` / `dict`）的开销可能会导致超时（TLE），而静态数组通常能卡常通过。
* **时间限制宽裕 $\rightarrow$ 选择【哈希表】**
  * 在时间限制很宽，或者总操作数很小（比如 $< 10^5$ 次）时，哈希表的常数开销可以忽略不计。

#### 3. 编程的便利性与安全性
* **希望快速实现、减少 Bug $\rightarrow$ 选择【哈希表】**
  * 哈希表不需要考虑数组越界（Index Out Of Range）的问题。
  * 哈希表可以直接使用任何可哈希（Hashable）的类型做 Key（如字符、字符串、负数、浮点数），不需要像数组那样做平移或类型转换（比如把字符 `'g'` 映射为数字 `6`）。

---

### 三、 决策金字塔（Rule of Thumb）

当您在做题或写代码时，可以快速按照以下逻辑闭环进行决策：

```text
               [需要设计一个查找表]
                        │
                        ▼
             是否可以简单地估算状态上限？
             (例如：Dim1 * Dim2 * Dim3)
                        │
            ┌───────────┴───────────┐
            ▼ 是                     ▼ 否
     上限是否 <= 10^7?             (直接选择哈希表 set / dict)
            │
      ┌─────┴─────┐
      ▼ 是         ▼ 否 (会 MLE)
 (优先选择静态数组)  (选择哈希表 set / dict)
```

**针对本题的结论**：
因为本题的状态上限仅为 $11 \times 11 \times 26 \approx 3000$，属于典型的**极小且密集**的状态空间。因此，**静态数组（Code 2）是工业和竞赛中更推荐、更安全（绝对不会因为常数大而超时）的写法**。但在时限宽松时，Code 1 展现出的“免字符转换”的简洁性，也同样非常优秀。
