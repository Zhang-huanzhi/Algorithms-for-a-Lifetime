除非穷得没内存了，否则请坚持使用 visited

---

| 维度        | visited 数组                            | 原地修改 (如 grid[i][j] = '#')          |
| --------- | ------------------------------------- | ---------------------------------- |
| **数据完整性** | **保护原始数据**。输入网格保持不变。                  | **破坏原始数据**。无法再次读取初始状态。             |
| **内存消耗**  | 额外消耗 `O(HW)`。对于 `1000×1000` 约占 1-4MB。 | **零额外消耗**。直接利用输入矩阵的存储空间。           |
| **调试易用性** | **高**。打印 visited 能看清搜索轨迹。             | **低**。打印网格时，障碍物和已访问点混在一起。          |
| **功能扩展性** | **强**。数组可以存布尔值，也可以存距离、步数。             | **弱**。通常只能标记“已访问”，难以存复杂信息。         |
| **适用场景**  | **通用**。绝大多数算法竞赛和工程项目。                 | **极致内存限制**。当内存只有 16MB 或 32MB 时使用。  |
| **代码风险**  | **低**。逻辑清晰，不容易出错。                     | **高**。如果后续逻辑还需读取原始网格，会引发不可预知的 Bug。 |
