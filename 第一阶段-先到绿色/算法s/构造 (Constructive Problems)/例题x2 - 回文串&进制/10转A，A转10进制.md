算法里的进制问题，本质上就是不断地**取余（看最后一位）** 和**整除（砍掉最后一位）** 的过程

### 2. 算法题中的两大核心操作（正反向转换）

在算法题中，进制转换无非就是“拆解”和“组装”两个方向：

#### 操作 A：十进制 $\rightarrow$ 任意进制（拆解）
**口诀：“除基取余，逆序排列”**
这正是你代码里写的完美逻辑：
```python
arr = []
while x > 0:
    arr.append(x % A)  # 取余数：得到当前最低位
    x = x // A         # 整除：砍掉最低位，让高位降下来
```
* **注意点**：这样算出来的 `arr`，**第一个元素是原数字的最低位（个位）**。如果是为了输出正确的进制字符串，需要倒过来（`arr[::-1]`）。但如果是判断回文，正反无所谓，因为回文要求两边对称。

#### 操作 B：任意进制 $\rightarrow$ 十进制（组装）
**口诀：“按权累加”**（或者叫“秦九韶算法 / 霍纳法则”）
如果你手里有一个 $A$ 进制的数组 `[6, 3, 6]`（高位在前），怎么转回十进制？
```python
res = 0
for y in arr:
    res = res * A + y  # 每次把之前的积累放大 A 倍，再加上当前位
```
* **Python 偷懒技巧**：如果是字符串形式的进制，Python 提供了内置函数直接转：`int("1010", 2)` 会直接把二进制的 1010 转成十进制的 10。

### 3. 做进制题的 2 个常见“避坑点”

1. **当进制 $A > 10$ 时，千万不要乱拼字符串！**
   * 如果是 16 进制，余数可能是 `10, 11... 15`。如果你把它们转成字符串拼在一起，`10` 会被拆成字符 `'1'` 和 `'0'`，长度和逻辑全乱了。
   * **正解**：像你在这道题里一样，**永远用 `List`（列表）来存余数**。一个列表元素就是一个独立的“位”，不管这个位的值是 8 还是 15，都不会混淆。

2. **零的特殊处理**
   * `while x > 0:` 这个循环结构有一个小盲区：如果输入的数字本身就是 `0`，循环根本不会执行，返回的是空列表 `[]`。
   * **正解**：在做进制转换函数时，最好在开头加一句特判：`if x == 0: return [0]`。（当然本题 $N \ge 1$，所以不加也没事）。

### 1. 进制的本质是什么？
四个字概括：**“逢 X 进 1”**。
* 进制就像是一个“容量有限的盒子”。
* 十进制的盒子容量是 10（装满 0~9 后，必须向高位进 1）。
* $A$ 进制的盒子容量就是 $A$（只能装 0 到 $A-1$ 的数字）。

**权重（权值）：**
无论什么进制，从右往左数，第 $k$ 位（从0开始计数）代表的价值就是 **$A^k$**。
* 十进制的 `352` = $3 \times 10^2 + 5 \times 10^1 + 2 \times 10^0$
* 八进制的 `636` = $6 \times 8^2 + 3 \times 8^1 + 6 \times 8^0$ = 414（十进制）
