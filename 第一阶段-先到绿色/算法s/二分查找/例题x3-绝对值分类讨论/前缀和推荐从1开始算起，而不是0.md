在算法和竞赛中，**强烈推荐使用从 1 开始（1-indexed，即 `pre[0] = 0`，数组长度为 `N + 1`）的前缀和**。

虽然在平时写代码时大家习惯 0 开始的数组，但在处理前缀和时，从 1 开始的设计是业界的“黄金标准”，能帮你避开大量的边界 Bug。

下面为您详细对比这两种写法，以及为什么推荐 1 开始的写法。

---

### 写法一：推荐！从 1 开始的前缀和（长度为 `N + 1`）

这种写法中，`pre[i]` 的物理意义是：**原数组中前 `i` 个元素的和**。

* **初始化**：
  ```python
  pre = [0] * (N + 1)  # pre[0] 默认为 0，代表前 0 个元素的和为 0
  for i in range(N):
      pre[i + 1] = pre[i] + arr[i]
  ```
* **区间求和公式**：
  如果要计算原数组 `arr[L...R]`（包含 $L$ 和 $R$）的和，公式为：
  $$\text{Sum}(L, R) = pre[R + 1] - pre[L]$$

#### 为什么强烈推荐这种写法？
1. **免去边界特判**：
   如果要计算从开头到某个位置的和（即 $L = 0$），公式依然成立：`pre[R + 1] - pre[0]`，因为 `pre[0] = 0`。**不需要写任何 `if L == 0` 的特判代码**。
2. **完美契合计数**：
   如果用二分查找得到了小于 `num` 的元素个数是 `idx`，那么前 `idx` 个元素的和就是 `pre[idx]`，下标完全对应，不需要做 `idx - 1` 这种容易出错的减法。

---

### 写法二：不推荐！从 0 开始的前缀和（长度为 `N`）

这种写法中，`pre[i]` 的物理意义是：**从 `arr[0]` 累加到 `arr[i]` 的和**。

* **初始化**：
  ```python
  pre = [0] * N
  pre[0] = arr[0]
  for i in range(1, N):
      pre[i] = pre[i - 1] + arr[i]
  ```
* **区间求和公式**：
  如果要计算原数组 `arr[L...R]` 的和，公式为：
  * 如果 $L > 0$：`pre[R] - pre[L - 1]`
  * 如果 $L = 0$：`pre[R]`

#### 为什么不推荐？
1. **代码冗余且容易写错**：
   每次求区间和时，你都必须判断 $L$ 是否为 0。如果忘记判断，`pre[L - 1]` 就会变成 `pre[-1]`（在 Python 中指向最后一个元素，在 C++ 中直接越界崩溃），极易写出 Bug。
2. **索引对齐痛苦**：
   当需要求前 0 个元素的和时，没有位置可以安全表达，代码逻辑会变得混乱。

---

### 总结

| 比较维度 | 1 开始的前缀和（`pre` 长度 `N+1`） | 0 开始的前缀和（`pre` 长度 `N`） |
| :--- | :--- | :--- |
| **推荐指数** | **★★★★★（首选）** | ★★☆☆☆（不推荐） |
| **`pre[0]` 的值** | 固定为 `0` | `arr[0]` |
| **求区间 `[L, R]` 和** | `pre[R + 1] - pre[L]`（统一公式） | `pre[R] - pre[L - 1]`（需特判 $L=0$） |
| **边界处理** | **自动优雅处理，无 Bug** | 极易发生 $-1$ 越界 |

以后写前缀和，建议养成**“一律开 `N + 1` 长度，令 `pre[0] = 0`”**的肌肉记忆，这可以帮您在写算法题时节省大量的调试时间。
