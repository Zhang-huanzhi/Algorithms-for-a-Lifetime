`bisect_left` 返回的坐标（索引）是**从 0 开始算起的（0-indexed）**，也就是说它完全符合 Python 列表默认的索引规则。

为了方便理解，我们可以从**“位置”**和**“数量”**两个角度来看待它返回的这个值 `idx`。

---

### 1. 两个极其重要的几何意义

假设我们对一个有序数组 `arr`（长度为 `n`）使用 `idx = bisect_left(arr, num)`：

#### 意义一：作为“索引”（从 0 开始）
`idx` 是 `arr` 中**第一个大于等于 `num` 的元素**的下标。
- 如果所有元素都小于 `num`，则返回 `n`（即数组最后一个元素的下一个位置）。
- 如果所有元素都大于等于 `num`，则返回 `0`。

#### 意义二：作为“元素数量”（核心技巧 🌟）
`idx` 的数值，**正好等于 `arr` 中严格小于 `num` 的元素的总个数**。
- 因为下标是从 0 开始的，下标为 `idx` 的元素前面刚好有 `idx` 个元素（下标分别为 `0, 1, ..., idx - 1`）。

---

### 2. 具体例子直观演示

假设 `arr = [10, 20, 30, 40]`（长度 `n = 4`），对应下标为：
```text
下标 (0-indexed):   0     1     2     3
元素值:           [10,   20,   30,   40]
```

我们来看不同的 `num` 查询结果：

| 查询 `num` | `bisect_left(arr, num)` 返回值 `idx` | 对应下标的元素 `arr[idx]` | 小于 `num` 的元素个数 | 小于 `num` 的元素有哪些 |
| :--- | :--- | :--- | :--- | :--- |
| **5** | **0** | `arr[0] = 10` ($\ge 5$) | **0** 个 | 无 |
| **20** | **1** | `arr[1] = 20` ($\ge 20$) | **1** 个 | `[10]` |
| **25** | **2** | `arr[2] = 30` ($\ge 25$) | **2** 个 | `[10, 20]` |
| **50** | **4** | 越界 (等于 `n`) | **4** 个 | `[10, 20, 30, 40]` |

---

### 3. 为什么它和前缀和 `pre` 配合得天衣无缝？

在我们的代码中，前缀和 `pre[i]` 代表前 `i` 个元素的和（1-indexed 长度统计）。

当 `idx = bisect_left(arr, num)` 时：
1. 小于 `num` 的元素个数正好是 `idx` 个。
2. 这 `idx` 个元素的求和，可以直接通过 `pre[idx]` 在 $O(1)$ 时间内拿到（即 `arr[0] + ... + arr[idx-1]`）。
3. 即使 `idx = 0`（即没有元素小于 `num`），`pre[0]` 也正好等于 `0`，逻辑完全自洽，不需要任何特殊的 `if` 边界判断。
