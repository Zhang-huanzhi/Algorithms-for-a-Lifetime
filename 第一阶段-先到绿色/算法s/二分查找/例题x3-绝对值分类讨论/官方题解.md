这份官方题解的核心思想是通过**排序**、**二分查找**和**前缀和**，将原本需要 $O(N \times M)$ 的双重循环暴力计算，优化到 $O((N + M) \log N)$ 的高效算法。

以下是对题解各个部分的详细拆解和说明：

---

### 1. 核心思路与转化（考察）

首先，求和公式中包含绝对值 $|A_i - B_j|$。由于我们要计算所有 $A_i$ 与 $B_j$ 差的绝对值之和，**整个序列 $A$ 的顺序并不会影响最终的求和结果**。
因此，我们可以先对序列 $A$ 进行**升序（从小到大）排序**，使得：
$$A_1 \le A_2 \le \dots \le A_N$$

对于绝对值 $|x - y|$：
- 当 $x \ge y$ 时，$|x - y| = x - y$
- 当 $x < y$ 时，$|x - y| = y - x$

如果我们固定 $B$ 中的某一个元素 $B_j$（在题解中记为 $y$），我们要计算：
$$\sum_{i=1}^{N} |A_i - y|$$
因为 $A$ 已经是有序的，我们可以把 $A$ 分成两部分来去掉绝对值：
1. **大于等于 $y$ 的部分**：对于这些 $A_i$，贡献为 $(A_i - y)$。
2. **小于 $y$ 的部分**：对于这些 $A_i$，贡献为 $(y - A_i)$。

---

### 2. 如何计算“大于等于 $y$”的部分

假设在已排序的 $A$ 中，**第一个**大于等于 $y$ 的元素的下标为 $i_y$（如果不存在这样的元素，则令 $i_y = N + 1$）。

那么，满足 $A_i \ge y$ 的元素就是 $A_{i_y}, A_{i_y+1}, \dots, A_N$。
这部分元素的个数为：$N - i_y + 1$ 个。

我们可以将这部分的求和公式展开并变形：
$$
\sum_{A_i \ge y} (A_i - y) = \sum_{A_i \ge y} A_i - \sum_{A_i \ge y} y = (A_{i_y} + \dots + A_N) - (N + 1 - i_y) \cdot y
$$

为了快速计算这个式子：
- **确定 $i_y$**：因为 $A$ 是有序的，我们可以使用**二分查找**（例如 C++ 中的 `lower_bound`）在 $O(\log N)$ 的时间内找到 $i_y$。
- **计算区间和 $(A_{i_y} + \dots + A_N)$**：可以通过预计算**前缀和**（或后缀和）在 $O(1)$ 时间内获取。

---

### 3. 如何计算“小于 $y$”的部分

同理，小于 $y$ 的元素就是 $A_1, A_2, \dots, A_{i_y-1}$。
这部分元素的个数为：$i_y - 1$ 个。

将其展开并变形：
$$
\sum_{A_i < y} (y - A_i) = \sum_{A_i < y} y - \sum_{A_i < y} A_i = (i_y - 1) \cdot y - (A_1 + \dots + A_{i_y-1})
$$

同样地：
- $i_y$ 已通过二分查找求得。
- 区间和 $(A_1 + \dots + A_{i_y-1})$ 可以通过**前缀和**在 $O(1)$ 时间内获取。

---

### 4. 整体实现步骤

1. 将序列 $A$ 进行**升序排序**。
2. 预处理 $A$ 的**前缀和**数组 $S$，其中 $S_k = \sum_{i=1}^{k} A_i$（定义 $S_0 = 0$）。
   - 这样，任何前缀和 $A_1 + \dots + A_{k}$ 都可以用 $S_k$ 表示。
   - 任何后缀和 $A_{k} + \dots + A_N$ 都可以用 $S_N - S_{k-1}$ 表示。
3. 初始化答案变量 `ans = 0`。
4. 遍历 $B$ 中的每一个元素 $B_j$（记为 $y$）：
   - 使用二分查找在 $A$ 中找到第一个 $\ge y$ 的位置 $i_y$（注意下标从 1 开始）。
   - 计算大于等于 $y$ 部分的贡献并累加到 `ans`：
     $$\text{Part}_1 = (S_N - S_{i_y-1}) - (N + 1 - i_y) \cdot y$$
   - 计算小于 $y$ 部分的贡献并累加到 `ans`：
     $$\text{Part}_2 = (i_y - 1) \cdot y - S_{i_y-1}$$
5. 最终输出 `ans % 998244353`。

### 5. 复杂度与注意事项

- **时间复杂度**：
  - 排序 $A$ 需要 $O(N \log N)$。
  - 计算前缀和需要 $O(N)$。
  - 对于 $B$ 中的每个元素，进行一次二分查找需要 $O(\log N)$，总共需要 $O(M \log N)$。
  - 总时间复杂度为 $O((N + M) \log N)$，在 $N, M \le 3 \times 10^5$ 的数据范围下可以轻松在 2 秒内通过。

- **取模（Mod）与溢出问题**：
  - 由于 $A_i, B_j$ 的数值较大，中间计算结果会超出 32 位整型的范围，因此在 C++ 中需要使用 `long long`。
  - 进行减法取模时（如 `(a - b) % MOD`），可能会产生负数。在取模时建议使用 `(a - b % MOD + MOD) % MOD` 的写法来保证结果为正数。
