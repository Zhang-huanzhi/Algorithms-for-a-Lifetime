这道题的解决思路，可以看作是一个从**直观理解**到**数学建模**，再到**严谨证明**的完整思维过程。

我们可以将整个解决思路拆解为以下四个步骤：

---

### 第一步：理解核心规则与抽象化

首先，我们仔细分析举办比赛的条件。
题目说：举办一场比赛需要 **1个A、1个C、以及任意1个字符**。

我们可以把这个条件进行数学上的拆解：
* 任何一场合规的比赛，必须包含至少 **1个A**。
* 任何一场合规的比赛，必须包含至少 **1个C**。
* 任何一场合规的比赛，必须包含恰好 **3个字符**。

通过这个抽象，我们发现：字符 `B` 的唯一作用，就是充当那个“任意的第三个字符”。而 `A` 和 `C` 既可以作为“必须的A、C”，在充裕时也可以退化为“任意的第三个字符”。

---

### 第二步：寻找约束边界（寻找必要条件）

设我们最终能举办的比赛数量为 $K$。那么为了达到这个目标，现有的字符必须跨过三道门槛（即三个瓶颈）：

1. **A 的瓶颈：**
   因为每场比赛都必须有至少1个 `A`，所以比赛总数绝对不能超过现有的 `A` 的数量。
   $$K \le n_A$$

2. **C 的瓶颈：**
   同理，每场比赛都必须有至少1个 `C`，所以比赛总数绝对不能超过现有的 `C` 的数量。
   $$K \le n_C$$

3. **总量的瓶颈：**
   因为每场比赛固定消耗3个字符，所以举办 $K$ 场比赛总共需要 $3K$ 个字符。现有字符的总量 $n_A + n_B + n_C$ 必须不小于 $3K$。
   $$3K \le n_A + n_B + n_C \implies K \le \lfloor \frac{n_A + n_B + n_C}{3} \rfloor$$

这三个条件同时成立，构成了 $K$ 的上限。因此，最大的可行值 $K_{max}$ 不可能超过这三者的最小值：
$$K_{max} \le \min\left(n_A, n_C, \lfloor \frac{n_A + n_B + n_C}{3} \rfloor\right)$$

---

### 第三步：证明可行性（验证充分性）

光有上限还不够，我们必须确信：**在这个上限之内的任何一个 $K$，我们都能实际把比赛组装出来。**

我们来尝试构造一下：
1. **搭建骨架：**
   我们拿出 $K$ 个 `A` 和 $K$ 个 `C`，两两配对，组成 $K$ 个形如 `[A, C, _ ]` 的半成品比赛。
   * *可行性：* 因为 $K \le n_A$ 且 $K \le n_C$，我们一定能拿出这么多 `A` 和 `C`。

2. **填充第三个字符：**
   现在我们还需要 $K$ 个任意字符来填满这 $K$ 个比赛。
   我们手头还剩下哪些字符呢？
   * 没用完的 `A`：$n_A - K$ 个
   * 所有的 `B`：$n_B$ 个
   * 没用完的 `C`：$n_C - K$ 个
   
   剩余字符的总数是：
   $$\text{Remaining} = (n_A - K) + n_B + (n_C - K) = n_A + n_B + n_C - 2K$$
   
   根据第三个瓶颈条件，我们知道 $n_A + n_B + n_C \ge 3K$。代入上式：
   $$\text{Remaining} \ge 3K - 2K = K$$
   
   这说明我们手头剩下的任意字符**至少有 $K$ 个**。我们只需任意挑选 $K$ 个塞进那 $K$ 个半成品比赛中，就能完美组装出 $K$ 场合规的比赛。

由此，我们证明了：**最大上限就是可以实际达到的最大比赛数**。

---

### 第四步：高效实现

在明确了数学公式 $K = \min\left(n_A, n_C, \lfloor \frac{n_A + n_B + n_C}{3} \rfloor\right)$ 之后，剩下的就是工程实现：
* **时间复杂度：** 每次查询只需进行几次基本的算术运算，复杂度为 $O(1)$。对于 $T \le 2 \times 10^5$ 的数据，总运行时间在几毫秒到几十毫秒级别，远低于 2 秒的限制。
* **空间复杂度：** 只需存储输入的数值，空间复杂度为 $O(1)$（或 $O(T)$ 用于一次性读取输入）。
* **细节处理：** 在 Python 中，由于 $T$ 较大，使用 `sys.stdin.read().split()` 一次性读取并解析输入，可以有效避免因频繁的 I/O 操作导致的超时。
