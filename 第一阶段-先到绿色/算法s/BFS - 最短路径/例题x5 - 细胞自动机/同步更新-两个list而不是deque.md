在平常的 BFS 模板题中，我们确实最习惯使用 `collections.deque`（双端队列），通过 `popleft()` 和 `append()` 在一个队列里“边进边出”。

而在这道题中，改用 **两个 `list`（`curr_q` 和 `next_q`）进行层级迭代**，主要是基于以下两个关键原因：

---

### 原因一：细胞自动机要求“同步更新”（最核心的逻辑原因）

本题的核心是细胞自动机，其规则要求：**所有格子的状态在每一步结束时，是“同时（同步）”发生变化的。**

#### 如果使用单个 `deque` 边进边出：
单队列的 BFS 是“异步”的。当你从队列里弹出一个刚刚变黑的格子 $A$，去更新它的邻居 $B$ 时，$B$ 可能会立刻满足条件变黑并被塞回队列尾部。
但是，在同一个步骤中，另一个刚变黑的格子 $C$（它也在这一步变黑）可能也和 $B$ 相邻。由于单队列没有明确的“步骤分界线”，$B$ 可能会在这一步中**提前**变黑，从而干扰了对 $B$ 的正确判定（$B$ 本来同时相邻 $A$ 和 $C$，黑邻居数应为 2，不能变黑，但因为异步更新，它可能先看到 $A$ 变黑就误以为自己能变黑了）。

#### 使用两个 `list`（`curr_q` 和 `next_q`）分步：
我们人为地把一轮模拟拆成了**“波及阶段”**和**“蜕变阶段”**：
1. **波及阶段**：只读取 `curr_q`，把所有新黑格对周围白格的贡献（`cnt` 累加）全部算完。在这个阶段，**没有任何一个白格会变黑**。
2. **蜕变阶段**：统计完这一步的所有影响后，我们统一判定哪些白格的 `cnt` 正好是 $1$，将它们变成黑色，并放入 `next_q`。
3. **交替**：`curr_q = next_q`，开启下一步。

这种“双队列分层”的设计，完美保证了**物理时间上的“同时发生”**，避免了同一轮里新变黑的格子互相干扰。

---

### 原因二：Python 的执行效率优化（性能原因）

在 Python 中，`list`（列表）和 `deque`（双端队列）在底层实现上有很大的不同。

- `deque` 的优势在于在头部进行 $O(1)$ 的弹出（`popleft()`）。
- 但在我们的层级 BFS 中，**我们根本不需要逐个从头部弹出元素**。因为我们要处理的是整个层级，直接使用普通的 `for u in curr_q:` 循环遍历列表即可。
- 在 Python（CPython）中，直接用 C 语言底层优化过的 `for ... in list` 循环，其速度要远远快于频繁调用 `deque.popleft()` 的 Python 函数开销。
- 每一轮结束时，直接进行指针交换 `curr_q = next_q`，这是一个 $O(1)$ 的操作，开销极小。

### 总结

- **单队列 `deque`**：适合**无状态相互干扰、只需计算最短路径**的标准 BFS。
- **双列表 `curr_q / next_q`**：适合**有同步更新要求（如本题的细胞自动机）、或者需要严格按“层（Layer/Step）”进行批处理**的场景。在 Python 中，这种写法还能带来更好的常数时间优化。
