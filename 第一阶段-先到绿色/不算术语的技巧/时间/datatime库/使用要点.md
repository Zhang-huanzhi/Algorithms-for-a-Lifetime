1. **字符串进电脑 -> 解析 (strptime)**：“String **Parse** Time”，把看得懂的字符串，解析成电脑能算的 datetime 对象。
    
2. **电脑出结果 -> 格式化 (strftime)**：“String **Format** Time”，把电脑里的时间，格式化成题目要求打印的字符串。

---

当你把两个 datetime 时间点相减时，Python 内部会自动生成一个 timedelta 对象。

拿到 timedelta 后，你最常做的事就是把它**换算成秒或分钟**。

### 第一部分：如何去用？（考场上的“三步流水线”）

在算法题中遇到时间问题，**绝对不要用字符串直接去做数学切片计算**，请严格按照以下“三步流水线”来写代码：

#### 🛠️ 第一步：解包（字符串 -> datetime 对象）

**只要题目给了时间字符串，第一件事就是把它变成电脑认识的时间对象。**

- **工具**：datetime.strptime(text, format)
    
- **目的**：把“死”的字符串变成“活”的对象。
    
- **动作**：
    
    codePython
    
    ```
    s = "2023-05-12 14:30:00"
    dt = datetime.strptime(s, "%Y-%m-%d %H:%M:%S")
    ```
    

#### ⚙️ 第二步：核心计算（使用 timedelta 或比较符）

**在这个阶段，所有的跨月、跨年、闰年问题，Python 底层全自动帮你处理了！**

- **场景 1：算差值（求过去多久）**
    
    codePython
    
    ```
    diff = end_dt - start_dt  # 得到 timedelta 对象
    minutes = diff.total_seconds() // 60
    ```
    
- **场景 2：推算未来/过去时间**
    
    codePython
    
    ```
    future = start_dt + timedelta(days=5, hours=3)
    ```
    
- **场景 3：比较先后顺序 / 区间排序**（日程安排、会议室问题）
    
    codePython
    
    ```
    if dt1 < dt2: # 直接用 < > == 比较先后
        print("dt1 发生得更早")
    ```
    

#### 📦 第三步：打包输出（datetime 对象 -> 字符串）

**算完之后，按照题目要求的奇葩格式输出。**

- **工具**：dt.strftime(format)
    
- **动作**：
    
    codePython
    
    ```
    # 题目要求输出格式为：YYYY/MM/DD
    print(future.strftime("%Y/%m/%d"))
    ```

### 第二部分：有哪些需要注意的？（考场四大致命雷区 🚨）

这是无数人机试爆零踩过的坑，请务必眼熟它们：

#### 💣 雷区 1：大小写字母搞混（最容易引发 Runtime Error）

格式化占位符一旦写错一个字母，程序直接崩溃。记住这个对照表：

- **年**：%Y (大写，四位数 2023) | %y (小写，两位数 23)
    
- **月**：%m (小写，01-12) —— **月份必须是小写 m！**
    
- **日**：%d (小写，01-31)
    
- **时**：%H (大写，24小时制) | %I (大写，12小时制)
    
- **分**：%M (大写，00-59) —— **分钟必须是大写 M！**
    
- **秒**：%S (大写，00-59)
    

> **口诀**：年月日除了**年**是大写 %Y，其他全小写（%m, %d）；时分秒全是**大写**（%H, %M, %S）。

#### 💣 雷区 2：算时间差只用 .seconds（逻辑错误，测试用例过不全）

这在前面强调过，必须再提一次。

- ❌ diff.seconds：如果相差 1 天零 2 小时，它只会返回 2 小时（7200秒），**天数被它私自吃掉了！**
    
- ✅ diff.total_seconds()：它会老老实实把那 1 天也折算成 86400 秒加进去。**永远只用这个！**
    

#### 💣 雷区 3：想当然地加减“月”或“年”

- timedelta(months=1) 会直接报错。
    
- 如果题目真让你“输出下个月的今天”，你需要手动提取 month，并处理 12 月的进位。
    
    codePython
    
    ```
    # 手动处理加一个月的笨办法（但机试安全）
    y, m, d = dt.year, dt.month, dt.day
    m += 1
    if m == 13:
        y += 1
        m = 1
    # 注意：这里可能抛出异常，比如 1月31日加一个月变成 2月31日（不存在），这就需要结合题目条件具体写判断逻辑了。
    ```
    

#### 💣 雷区 4：性能陷阱（TLE 超时风险）

在 Python 中，strptime 的底层解析速度比较慢。

- 如果题目只有几百、几千个时间数据，随便用 strptime。
    
- **【进阶技巧】**：如果题目输入了 
    
    **`105105`**
    
     **级别**的时间字符串，只是让你**排序**或者**比较先后**。**根本不需要转成 datetime！**  
    因为像 "2023-10-25 12:00:00" 这种标准的年-月-日 时:分:秒 格式，**字符串的字典序刚好等于时间的先后顺序！**
    
    codePython
    
    ```
    # 如果数据量极大，且只需比较先后，直接比字符串：
    "2023-10-25" < "2023-10-26"  # True，非常快！
    ```
    

### 💡 总结考场策略

上机的时候，只要读题看到**“时间跨度”、“闰年平年”、“隔了多少天/小时”**，大脑立刻浮现 datetime + timedelta。

如果题目说**“某年某月某日是星期几”**：  
直接用 dt = datetime(year, month, day)，然后 dt.weekday()（0是周一，6是周日），两行代码秒杀全场。
