# 算法竞赛中的高效输出习惯

## 前言

在算法竞赛中，很多新手会遇到这样的困惑：**算法正确、复杂度也对，但就是超时（TLE）**。

问题往往出在一个看似"无害"的坏习惯上：**在循环内频繁使用 `print()` 输出**。

在处理大规模数据（如 N = 2×10⁵）时，这个习惯可能让你的程序慢 10 倍甚至更多。

**优秀选手的共同习惯：先收集所有结果，最后一次性输出。**

---

## 1. 为什么循环内 `print` 会超时？

### 核心原因：I/O 操作极其昂贵

每次 `print` 都涉及：

- **系统调用**：从用户态切换到内核态，请求操作系统输出数据
- **上下文切换**：保存/恢复 CPU 状态、切换内存页表
- **缓冲区刷新**：频繁的小规模写入触发多次刷新

**循环 20 万次 `print` = 和操作系统"打架" 20 万次**

### 形象比喻

- ❌ **循环内 print**：每打包一件快递就跑一趟邮局
- ✅ **正确做法**：把所有快递装上卡车，一次性送到邮局

---

## 2. 三种正确做法

### 做法 A：列表收集 + 解包输出 ⭐推荐

```python
ans = []
for i in range(1, N + 1):
    result = ...  # 计算结果
    ans.append(result)

print(*ans)  # 一次性输出，自动加空格
```

### 做法 B：字符串连接

```python
ans = []
for i in range(1, N + 1):
    ans.append(str(计算结果))

print("\n".join(ans))  # 每行一个
# 或 print(" ".join(ans))  # 一行，空格分隔
```

### 做法 C：极致优化

```python
import sys
write = sys.stdout.write

for i in range(1, N + 1):
    write(f"{计算结果} ")
write("\n")
```

---

## 3. 性能对比（N = 2×10⁵）

|方法|耗时|结果|
|---|---|---|
|循环内 `print`|0.5s ~ 1.5s|⚠️ 可能 TLE|
|`print(*ans)`|0.05s ~ 0.1s|✅ 通过|
|`"\n".join()`|0.03s ~ 0.08s|✅ 更快|
|`sys.stdout.write`|0.02s ~ 0.05s|✅ 极致|

**性能差距可达 10 倍以上！**

---

## 4. 示例对比

### ❌ 错误写法

```python
for i in range(n):
    print(arr[i] * 2)  # 每次循环都输出
```

### ✅ 正确写法

```python
ans = []
for i in range(n):
    ans.append(arr[i] * 2)
print(*ans)  # 一次性输出
```

---

## 总结口诀

> **循环内 print 是大忌，先收集再输出才给力。**  
> **能攒着一起发，就绝不一个一个发。**

### 标准流程

1. 定义容器：`ans = []`
2. 循环收集：`ans.append(result)`
3. 统一输出：`print(*ans)` 或 `print("\n".join(map(str, ans)))`

### 例外情况

只在以下情况才循环内 `print`：

- 交互式题目（Interactive Problem）
- 调试阶段
- 输出次数极少（< 10 次）
