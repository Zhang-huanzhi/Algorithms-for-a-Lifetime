但是同样的逻辑用C就可以。

为什么C++选手不怎么操心 输入输出（I/O）但python选手必须要额外注重？


---

**C++ 是编译型语言**，它的 cin 和 cout（在关闭同步流 ios::sync_with_stdio(0) 后）会被编译器直接优化成几条极其贴近 CPU 寄存器的汇编指令，内存开销极小。

而 **Python 是一门动态解释型语言**，在 Python 中：

- 哪怕是一个简单的整数 1，在底层也是一个庞大的 C 结构体（包含引用计数、类型指针等）。
- 每一个 input() 和 print() 都要经过 Python 虚拟机的层层解释和方法查找。


**结论：**  
Python 跑算法题，最怕的就是**“把耗时的操作放在循环里让 Python 虚拟机去一行行解释”**。  
我们使用 sys.stdin.read().split() 和 '\n'.join(out) 的本质，就是**把几十万次的循环 I/O 动作，打包成一次操作，直接交给底层用 C 语言写好的超级优化的库函数去执行**。

**能批量解决的，绝不逐个处理；能交给底层 C 扩展干的，绝不用 Python 循环干！**
