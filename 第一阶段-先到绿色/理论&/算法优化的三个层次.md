### 1. 改变算法级别（解决 TLE / 超时）
核心是**降低时间复杂度**，用更高级的逻辑代替暴力遍历。

*   **典型例子 1：二分查找**
    *   *常规*：在排好序的数组里找一个数，一个一个挨着找（线性查找），复杂度是 $O(n)$。
    *   *优化*：折半查找（二分），每次排除一半，复杂度直接降到 $O(\log n)$。
*   **典型例子 2：哈希桶（Hash Table）**
    *   *常规*：每次查数据都在列表里循环扫一遍，复杂度 $O(n)$。
    *   *优化*：用哈希桶给数据建立映射，直接精准定位，复杂度降到 $O(1)$。

### 2. 改变数据表示（解决 MLE / 内存超限）
核心是**优化内存布局**，用紧凑的数据结构代替空旷的结构。

*   **典型例子 1：邻接表 替换 邻接矩阵（图论中）**
    *   *常规（邻接矩阵）*：存一个稀疏图用二维数组 `g[V][V]`。如果点数 $V = 10^5$，需要 $10^{10}$ 个位置，直接内存超限（MLE）。
    *   *优化（邻接表）*：只存实际存在的边，空间复杂度降到 $O(V + E)$，挽救了内存。
*   **典型例子 2：稀疏存储（Sparse Storage）**
    *   *常规*：存一个 $10000 \times 10000$ 的大棋盘，用二维数组，哪怕里面只有几颗棋子，也占用了上百兆内存。
    *   *优化*：只用一个三元组列表 `(行, 列, 值)` 存有棋子的位置，没棋子的地方不占内存。

### 3. 减少常数消耗（压榨执行速度）
核心是在**复杂度相同**时，通过更换工具或底层实现，跑得更快。

*   **典型例子 1：用静态数组（Array）替换 字典（Map/Dict）**
    *   *场景*：统计 26 个英文字母出现的次数。
    *   *常规*：用 `map<char, int>`，每次查找都要经历哈希计算、红黑树旋转等，常数开销很大。
    *   *优化*：直接用一个固定大小的静态数组 `int count[26]`，通过 `count[ch - 'a']` 直接定位，常数极小，速度快数倍。
*   **典型例子 2：更换编程语言**
    *   *场景*：同样的算法逻辑。
    *   *常规*：用 Python 或 Java 编写，存在虚拟机、解释器、自动垃圾回收（GC）的常数开销。
    *   *优化*：直接改用 C/C++ 或 Rust 编写，编译成原生机器码运行，消除了这些系统层面的常数损耗。
