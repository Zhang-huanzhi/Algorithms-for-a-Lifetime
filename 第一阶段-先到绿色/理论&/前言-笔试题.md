
不学理论，一味的刷题， 会缺乏抽象能力，不能泛化。 下次遇到了这样的题，还是不会。

这里补下理论知识。

---

AtCoder 很擅长训练“看到题后快速建模并实现”，但它默认你已经掌握很多理论；如果没有系统补课，遇到笔试里的伪代码、正确性证明、复杂度推导，容易发蒙的。

建议把学习拆成两条并行线：

- AtCoder：保持做题，训练题感和实现。重点不是刷数量，而是每题做完要能回答：用了什么算法、为什么能用、复杂度为何是这个。
- 理论课：按专题系统补齐“定义、性质、证明、复杂度、典型模板”。

在算法领域，理论知识主要解决三个问题：
*   **正确性（Correctness）**：为什么这个算法是正确的？（例如：贪心策略的证明、动态规划的状态转移方程为什么没有后效性）。
*   **复杂度（Complexity）**：如何准确评估时间和空间消耗？（不仅是估算，还包括主定理 Master Theorem、摊还分析 Amortized Analysis 等方法）。
*   **设计范式（Design Paradigms）**：分治、减治、变治、动态规划、贪心等思想的本质区别和适用场景。


与AtCoder等算法竞赛偏重于“快速写出AC代码”不同，修士考试是**笔试（手写纸质试卷）**，它更侧重于对**经典算法原理的深度理解、数学证明以及规范的表达**。

| 维度       | AtCoder (ABC/ARC)   | 日本修士考试 (情报理工)        |
| -------- | ------------------- | -------------------- |
| **考试形式** | 线上提交代码，评测机自动测试      | 纸质笔试，人工批改步骤分         |
| **题目来源** | 原创、新颖、脑筋急转弯多        | 经典教材（《算法导论》等）的变形     |
| **代码要求** | 只要AC即可，不在乎变量命名和代码规范 | 注重可读性、伪代码规范、逻辑严密性    |
| **核心考点** | 快速构造解法、代码实现速度       | 算法正确性证明、复杂度推导、数据结构细节 |
